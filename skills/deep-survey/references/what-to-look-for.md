# 各类对象通常要查什么

定题时在选好执行深度后读取。下面是候选角度，按用户问题取舍、合并重复项，再分成独占的证据块；不为覆盖整张清单扩大课题。标「不可省」的基本定义与关键前提要交代。这里只管研究，不规定章节；报告结构由读懂全部材料的主笔决定。

用户只给了对象、没给问题时，用每类末尾的默认问题起草确认单，请他确认。

## AI 工具、模型、开源项目、API、skill、MCP、CLI

读者的典型路径是先弄懂它（定义、接口、实现、效果），再判断要不要接进自己的系统。

| 角度 | 要查什么 | 先去哪 | 常查不到 |
|---|---|---|---|
| 是什么 | 一句话定义、和既有方案差在哪；出品方、发布时间线、开放方式（开源 / 托管 API / 早期访问）；开源项目的 Stars 与增速、最后提交、许可证 | 官网、发布博客、GitHub、作者主页、融资报道 | 真实活跃用户数、调用量 |
| 接口契约（不可省） | 请求由什么组成、各类输入怎么写、返回字段什么意思；官方原样的请求与返回示例；边界：长度、语言、限额、不适用场景；SDK 与接入渠道 | 官方文档与 API 参考、Quick start、SDK 仓库 | 没文档化的边界 |
| 怎么实现 | 官方披露了什么、没披露什么；上游依赖；社区或竞品复刻的做法和达到的水平 | 技术博客、论文、模型卡、创始人访谈、复刻仓库 | 闭源模型的结构与训练数据 |
| 效果与边界 | 官方基准的口径；第三方实测（速度、准确率，谁测的、多少样本、什么条件）；适合与不适合的任务；典型用法与案例（自有信息流里常有）；开发者的正负面评价 | 官方 benchmark 页、第三方评测、HN、Reddit、GitHub issues、自有信源池 | 同条件的独立对照 |
| 格局 | 同类与跟进者的开放方式、价格、成绩；替代技术路线的取舍 | 竞品博客、基准榜单 | — |
| 接入成本 | 价格、免费额度、限额；对照方案的单价；按读者量级算一笔账；条款、数据使用、可用性 | 定价页、terms、privacy、status 页 | 厂商未来定价与存续 |
| 和读者系统的关系 | 读者自己的项目里哪些环节能换、怎么接、怎么验证、什么时候放弃；凭证、依赖、注入风险 | 读者本机代码（协调者列路径）加前几个角度 | — |

接口契约不随用户措辞省略：他问「是什么、有什么用」，接口契约仍是理解这类对象的前提。

默认问题：它是什么、接口怎么用、靠什么实现？效果和边界如何，和同类比怎样？和读者现有系统重叠多少、接入值不值、怎么接？

## 产品：App、SaaS、硬件、消费品

面向多个市场的消费产品，规模、用户、监管按市场分开查。

| 角度 | 要查什么 | 先去哪 | 常查不到 |
|---|---|---|---|
| 是什么 | 定位与形态；解决什么问题、给谁用；和上一代产品的机制差别；留存靠什么；产品截图 | 官网、应用商店页、长篇报道、创始人访谈 | 内部算法 |
| 格局 | 品类规模与增速（多机构口径并列，含最近一期）；各对象用户规模（口径、日期）；功能、融资、团队对比；来源点名的新玩家 | Appfigures、Sensor Tower、a16z 榜单、QuestMobile、融资新闻 | 流量、下载、月活多为第三方估算 |
| 用户 | 画像（含样本量）；动机、使用强度（时长、频次，配参照）、流失原因；用户原话，正负面都要，多平台、近一年 | 调查与学术研究、商店评论、Reddit、小红书、知乎、B 站 | 动机占比多是小样本 |
| 钱 | 各档价格与权益；收入、付费率、每付费用户收入；按读者规模算成本（模型单价、轮数、上下文、缓存）；获客渠道与成本 | 定价页、商店内购列表、财报、模型 API 定价页、出海媒体 | 非上市公司收入、付费率 |
| 主线案例 | 一家主线公司的完整时间线和关键人物原话；两到四个对照案例 | 晚点、The Information、长篇访谈 | 早期内部决策 |
| 风险与门槛 | 监管现状（已生效 / 待生效 / 征求意见）、处罚诉讼下架；上线门槛：备案、审核、商店政策、支付 | 监管原文、律所解读、权威媒体 | 执法尺度 |

默认问题：它现在的增长、商业化和口碑？留存机制是什么、能不能复制？对读者意味着进入、借鉴还是回避？

## 行业、赛道、品类

| 角度 | 要查什么 | 先去哪 | 常查不到 |
|---|---|---|---|
| 是什么 | 行业定义、产业链上中下游、关键术语；演进节点 | 行业图谱文章、长篇报道、维基 | — |
| 格局 | 市场规模与增速（多机构口径并列，说明差异原因）；头部三到五家及份额线索；新进入者与退出者；来源点名但不在对象清单里的玩家 | 艾瑞、QuestMobile、Statista、Gartner 摘要、上市公司财报、融资数据库转述 | 研报全文、精确份额 |
| 用户 | 需求方画像、动机、使用强度、流失原因；需求方原话，多平台 | 调查、学术研究、原帖 | 动机占比 |
| 钱 | 主流收费方式；谁赚谁亏；典型企业的收入、成本、获客成本，写成能复算的账；按读者规模的账 | 财报、招股书、创始人访谈、分析师文章 | 非上市公司盈亏 |
| 主线案例 | 主线企业的时间线与原话；对照案例；和读者处境相近的小团队案例 | 长篇报道、公告、独立开发者自述 | 早期内部决策 |
| 驱动与风险 | 技术、政策、需求三类驱动；监管与风险；新进入者的门槛：资质、备案、审核、渠道 | 政策原文、权威媒体、从业者访谈 | 预测数字只能标预测 |

默认问题：当前格局，头部靠什么？增长、驱动力和最大风险？对读者意味着要不要进、从哪切？

## 公司

工商、司法、税务数据库不在可查范围，写进「还不知道的」，提示用企业信息查询接口。

| 角度 | 要查什么 | 先去哪 | 常查不到 |
|---|---|---|---|
| 是什么 | 成立时间、总部、人数区间、股权与母公司；主营产品与业务线；近一年上新与下线 | 官网、招聘页、发布会、更新日志、企业信息公开页 | 精确人数、股权穿透 |
| 格局 | 主要对手、相对优劣、客户为什么选它 | 对比评测、客户案例、社区 | 真实赢单率 |
| 用户 | 客户类型与代表客户；用户与客户原话 | 客户案例、评论、社区 | 客户名单全量 |
| 钱 | 收入线索、增速、盈亏；融资轮次、金额、投资方 | 财报与招股书（上市公司读原文）、融资新闻 | 非上市公司收入、未公开轮次 |
| 团队与历程 | 时间线、创始人与核心高管背景、关键人员变动、原话 | 长篇报道、访谈、LinkedIn | 内部决策 |
| 风险与舆情 | 负面新闻、公开报道层面的诉讼与处罚、裁员、用户投诉 | 权威媒体、监管公告、社区 | 司法与行政处罚全量 |

默认问题：业务、盈利模式和当前处境？团队与资本背景？对读者意味着合作、入职、投资还是竞争的可行性？

## 其他：技术、政策、人物、事件、资源盘点

没有固定清单。固定一个「是什么」角度，查到能读懂其余角度为止；其余每个用户问题至少一个角度，角度名用问题的关键词。

| 对象 | 常见角度 | 先去哪 |
|---|---|---|
| 技术 | 原理与边界 / 成熟度与采用者 / 替代方案 / 成本与风险 | 论文、官方文档、工程博客、采用者案例 |
| 政策 | 原文要点 / 适用对象与时间 / 执行与案例 / 各方解读分歧 | 政策原文、监管与律所解读、权威媒体 |
| 人物 | 公开履历 / 代表作与观点 / 评价与争议 | 本人原文与访谈、权威报道 |
| 事件 | 时间线 / 各方说法与依据 / 影响 / 后续观察点 | 当事方声明、权威媒体、原始文件 |
| 资源盘点（「做 X 有哪些工具 / 网站 / 项目」） | 做法分几条路 / 每条路的代表工具或项目，固定字段进对比表 / 可参考的案例 / 配套与社区 / 和读者现状怎么衔接 | 官方 showcase、awesome 列表、社区推荐帖、项目仓库 |

这类对象多靠二手解读，各方说法不一致时并列呈现，不取单一立场。

默认问题：它是什么、怎么来的？各方怎么看、分歧在哪？对读者意味着什么？
