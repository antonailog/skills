# deep-survey

把产品、行业、公司、AI 工具或活动研究清楚，写成带来源、能据此做决定的 Markdown 报告。

## 运行方式

- **聚焦调研，默认**：一到两名研究员按互不重复的证据块采集并归纳一次；独立主笔读懂全部材料、决定论点与结构、成稿，一名独立审读员冷读。
- **完整专题**：适合系统解释行业、公司或复杂机制。保留研究员、同一主笔的短备忘与续写、独立审读。

两种深度都保持研究员与主笔独立，理解和写作由同一主笔连续完成。协调者不再重复综合。质量是目标，用量是诊断指标；新增检索要说明它可能补上什么关键缺口。全任务共享预算，按完成消息推进，图表按表达需要选择。

## 采集与评估

- [网页采集](references/fetching.md)：`fetch_page.py` 批量提取 HTML、内嵌 JSON、公开脚本与 GET 数据，保留原文、时间、哈希及明确的缺失状态；支持固定证据回放。
- [报告质量 policy](references/report-quality-policy.md)：八维评分、独立事实核验、严重错误门槛。版本验收使用两名独立盲评，普通报告保留一次冷读；不按篇幅、来源数、图数或 token 给质量分。
- `measure_run.py`：显式指定主/子日志、turn 和时段，按响应去重，区分缓存、非缓存与输出 token，不把累计上下文当成浪费或账单。

## 来源与交付

笔记和对比 CSV 保留 URL。脚本收集来源，交付时统一编号、生成可点击引用，同步 JSON 与 Markdown 来源表，并校验编号是否指向同一页面。报告与来源原件留备份，重复运行不改变已一致的结果。

需要联网检索；Matplotlib 和 Playwright 仅在出图时需要。自有信息流及中文专用接口均可选，相关且可用时才尝试，不在调研中修复基础设施。

完整执行规则见 [SKILL.md](SKILL.md)，设计与验证记录见 [构建记录](../../docs/deep-survey-build/README.md)。抓取实测、固定材料写作回放和完整端到端运行分别记录，不互相代替。
