# deep-survey

带来源的深度调研报告

## 要解决的问题

想摸清一个陌生赛道，通用的 deep research 能搜能写，但开工前不问读者是谁、要做什么决定，写完没人核查，查不到的也不交代。拿同一个赛道课题做过对照：不加载这个 Skill 的子 agent 几分钟就交了报告，结论方向和用 Skill 的一致，可正文没有一个来源编号，几个推算出来的数字以事实的样子进了表格。读者拿到这样的报告，分不清哪句查过、哪句是估的。

## 运行方式

![deep-survey 结构图](../../docs/diagrams/deep-survey.jpg)

协调者留在主会话，只发确认单、做计划、派工和终审，搜索、核查、写作都交给子 agent。用户拍板三处：确认单（一次最多 3 问）、调研计划、报告放在哪。研究笔记没达到每项需求的来源门槛，就派人定向补研，最多三轮；核查时打回过半，也回去补一轮。

## 关键设计

- **读者设定为外行，正文不贴【高 / 中 / 低】标签**：可信度用「官方披露」「第三方估算」「推测」这样的文字交代，对抗、打回、可达性这些核查记录留在笔记里，不挤占阅读路径
- **没有来源编号的数字不进正文，查不到就写「未查到」**：估算一旦写成事实，读者无从发现，会直接误导下游决定
- **写结论的人不审自己的结论**：对抗分析员专找反例，验证者逐条打开原文，既核来源说没说，也核口径撑不撑得住结论；对照实跑里，一条已正式施行的新规被研究员和基线报告都写成了征求意见稿，是对抗分析员查出来的
- **协调者不亲自搜，子 agent 只回数量不回内容**：几百行笔记会填满主会话，协调者在核查前看到结论，会不自觉地采信没核过的数字
- **先查自己长期筛过的信息流，再走中文平台的专用通道，最后才是通用网页搜索**：改版前一份报告的 281 条来源里没有一条来自作者的信息流，只召回两个关键词就拿到 118 条，其中 71 条是长文

## 其他

- 前提：能联网搜索和抓取网页；出图要 matplotlib 和 Playwright；`ZHIHU_ACCESS_SECRET`（知乎）、`INFO2ACTION_REPO`（作者自用的信息流）可选，缺了就退回网页搜索
- 注意：默认走轻量模式；完整模式的 token 约为不用 Skill 的 15—20 倍，结论要给别人看、要据此花钱时再用
- 注意：一次只做一个课题，2—6 个同类对象可以放在一起比；企业工商、司法类信息查不到，会写进「还不知道的」
