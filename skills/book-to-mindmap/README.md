# book-to-mindmap

书和长文转思维导图

## 要解决的问题

把一本书转成思维导图，常见做法是照目录拆、每个节点放一个关键词，看完只记得有哪些话题，记不住结论。这个 Skill 成型前，最早一轮尝试把一本书拆出 352 个叶子节点，格式检查全过，读的时候还是得自己把意思拼起来。之后又被否了两轮：一轮是行内长句把导图撑宽，一轮是枝干仍然停在话题标签。

## 运行方式

![book-to-mindmap 结构图](../../docs/diagrams/book-to-mindmap.jpg)

开工前先定覆盖档：用户没读过原书时默认按精读替代版做，章节里的实质内容都要有位置。骨架要用户确认：只写一级分支和枝干，用户点头后才往下填。查遗漏时每章从原文出 8—12 个问题，交给只看得到导图、看不到原文的子 agent 回答，答不上的回头补。

## 关键设计

- **节点写一句能判真假的判断，不写关键词**：关键词只对边读边画的人自己有用；给别人或三个月后的自己看，「失效模式」这种标签交付不了知识
- **骨架先确认再往下填**：骨架错了，填得越满，错误铺得越开
- **优先用书自带的框架，其次按读者的问题重组**：目录书里已经有了，照抄目录没有增量
- **解释写进 notes，第一段以灰字直接显示在节点里**：节点限 5—18 字，长句会把横向画布撑宽；把解释删掉，读者又得回原文
- **写框架名之前先回原文 grep**：导图是压缩，压缩不该产生原文没有的信息

## 其他

- 前提：Python 3 生成 .xmind，脚本只用标准库；要发飞书时用 lark-cli 发多级列表版
- 注意：整本书逐章做时，一章一张画布，合成一个 .xmind 文件，打开默认只展开到第 2 层
- 注意：XMind 不会重载已经打开的文件，看新版要换个文件名
- 注意：分章派给子 agent 时，它报的长度数字要用 `inline_stats.py` 自己重跑一遍再信
