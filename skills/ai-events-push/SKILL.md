# ai-events-push — 活动推荐的群推送和小红书多图

作者挑活动（或给一段日期），这个 skill 交回能直接发的一套：微信群是 `海报.png` + `文案.md`，小红书是 `出图/` 一组 3:4 图 + `文案.md`（标题候选、正文、标签）。图本身信息完整，文字整段复制就能发，里面每个时间、价格、嘉宾都找得到出处。

## 定位与边界

像一个替作者值班的编辑：他只管挑，你把每场的时间、地点、票价、谁来讲核实清楚，排成一眼看懂的图，再配一段能直接发的文字。读者要的是快速判断「这周去哪场」，所以图本身要信息完整（不靠文字补），写法是平实的活动介绍，不是作者的个人分享。群里的人认识作者、会点链接；小红书的读者是刷到这篇的陌生人，平台判引流，所以小红书图文里不放网址和二维码，标题靠真实看点（首次来华、免费场数、大咖名字）吸引人，不靠营销词。

活动监测项目目录取环境变量 `AI_EVENTS_DIR`，没设就是 `~/claudecode_workspace/工具/活动监测/`，下面的相对路径都从这里算。每次推送一个目录：`宣传/发布/<日期>-微信群/` 或 `宣传/发布/<开始日期>-小红书/`。

## 先分渠道

| 作者说了什么 | 走哪 |
|---|---|
| 群、微信、IM、长图、本周活动推荐 | 微信群：下面第 1–7 步 |

在已经出过的推送目录里只要标题、标签、正文，直接按 `references/小红书.md` 第 4–7 节改 文案.md，不用重跑整套。

## 按需读取

| 文件 | 什么时候读 |
|---|---|
| `references/文案写法.md` | 写 文案.md 和票面介绍之前 |
| `references/新活动上网站.md` | 有活动网站上还没有，或核实时发现网站上的信息错了 |
| `references/小红书.md` | 走小红书渠道时：选场规则、小红书.json 写法、出图、标题、正文、标签、检查 |

## 作者定过的群推送版式（不用再问）

- 叫「本周活动推荐」加日期范围，本周是周一到周日。不说「我收藏的」。
- 不在本周的活动不放，也不做「下期预告」；不加「AIE 周，连着排」这类编者按。
- 按城市分区，北京在前，其余按场数；每场一张网站电脑版同款门票：左边宣传图 16:9，右边日期钟点、名称、地点、主办方、介绍，副券写价格。背景是网站顶栏七彩压淡，右上角场数，底部二维码。这些都在 `assets/poster.html` 和 `scripts/make_poster.py` 里，换版式改模板，不在每次推送里临时改。
- 作者说某个场地、主办方要突出（合作方），地址里那几个字用城市色加粗（`venue_hl`），介绍里点名。

## 流程

### 1. 认出是哪几场

作者给的可能是网站截图（点了星的几场）、活动名、链接、海报图。小红书渠道只给了日期范围的，按 `references/小红书.md` 第 1 节的规则挑，先把范围清单给作者过目。

```bash
S=<本 skill 目录>/scripts
python3 -I $S/fetch_events.py --range <周一> <周日> [--city 北京 上海]   # 列出本周的活动，对着截图认名字
```

对上以后记下 id。截图里看不全的（比如长期活动在页面最下面），问作者是哪一场，别猜。网站上没有的活动（海报图），读 `references/新活动上网站.md`，先整理信息给作者看，作者确认后上网站，这样文字稿里才有详情链接。

### 2. 起草海报数据、拿完整信息

```bash
cd 宣传/发布/<日期>-微信群
python3 -I $S/fetch_events.py --ids <id ...> --out 选中.json --draft 活动.json --week <周一> <周日>
```

`选中.json` 是每场的完整字段（简介、议程、嘉宾、重点、原文链接，「原文」是网站存下的活动原文全文），写介绍用；`活动.json` 是海报数据草稿，日期、钟点、地点、价格、宣传图已经填好，`intro` 空着。网站上没有单独一条的活动（合集里的一场），手动加进 `活动.json`。小红书渠道把 `--draft 活动.json` 换成 `--xhs 小红书.json`，目录换成 `<开始日期>-小红书`。

### 3. 核实

一场一场过：时间、地点、价格、主办方、嘉宾。来源的先后是：活动方海报和报名页 > 网站整理 > 转述（推文、合集文章）。

- 网站上的信息和活动方海报对不上：以海报为准，网站上的错照 `references/新活动上网站.md` 第二节修（先问作者）。
- 先读 `选中.json` 的「原文」：微信文章多半被验证墙挡住，读网站存下的这份。
- 价格、钟点、嘉宾要对报名页或官网：活动行这类页面要跑 JS，web-fetch 只拿到空模板，用 `python3 -I $S/read_page.py _src '名字=网址' ...` 在浏览器里打开再读（网址带 ?、&，整段加引号）。还是没有，票面写「费用未写」「钟点未写」，文字写「以报名页为准」。
- 活动行页面按本机时区显示钟点，本机不在东八区就要换算回北京时间；连续打开会限频，碰到验证码马上告诉作者，别干等。
- 网站上带「你已付款」「已订阅」这类作者个人的话，不写进对外稿。
- 主办方是匿名账号、原文留个人微信、嘉宾是「副业变现」口径的，列出来问作者换不换。
- 每条依据记进 文案.md 的核实记录。

小红书渠道从这里转到 `references/小红书.md` 第 2 节；下面第 4–7 步是群推送。

### 4. 写文字稿和票面介绍

读 `references/文案写法.md`。写完 `文案.md`，把每场压成三行以内的票面介绍填进 `活动.json` 的 `intro`，顺手改 `venue`（区 · 场馆，括号里只放门牌）、`org`、名称的换行。

### 5. 出海报、看海报

```bash
python3 -I $S/make_poster.py 活动.json
```

它会报自检结果：孤字、介绍超三行、价格太长、宣传图没下来、二维码不对。有问题改 `活动.json` 重出，直到「没有问题」。然后打开 `预览-1.png`、`预览-2.png` 亲眼看一遍：宣传图是不是这场的、有没有糊、有没有被裁坏。长竖海报脚本会自动截顶上一块方图；截得不好就自己裁一张放进目录，`cover` 写文件名。

### 6. 核对链接

```bash
python3 -I $S/check_links.py 文案.md
```

详情链接要弹出对应那场；外部链接打不开的，换一个或在核实记录里注明。

### 7. 交稿

给作者的汇报照他习惯的写法：第一行状态卡（已完成｜未完成｜待你决定），再给 `海报.png` 和 `文案.md` 的完整路径，几处按默认处理的事和要他定的事。发法写一句：先发海报（勾「原图」），再复制两条横线之间那段。

作者说已经发了，如果有发布索引 `~/claudecode_workspace/内容/自媒体/发布索引.md`，在「发布记录」最上面加一行：平台写「微信群」，链接写「群消息」，本地稿链到这次的目录。

## 红线

1. **改线上网站（新加活动、修错）先给作者看要改什么，他说可以再发布**；发布前比对本地和服务器，只带这次的改动。网站是公开的，发上去就有人看到。
2. **不替作者发群消息、发笔记、回复任何人**。交稿到文件为止。
3. **时间、价格、嘉宾这些事实不编**。找不到出处的不写，也不换成一个暗含它的模糊说法；读者会照着去报名、买票。
4. **小红书图文里不放网址、二维码和「扫码」「私信」这类引流字眼**。平台判引流会限流，笔记发出去就改不回来。

## 失败怎么办

- 网站数据拉不下来：fetch_events.py 自动退回本地 `页面/app/src/data.json`，提醒作者可能不是最新，必要时先 `zsh 脚本/服务器.sh 拉回`。
- 宣传图下不来：make_poster.py / make_xhs.py 用分类默认图顶上并报出来；能从活动方页面拿到图就换上。小红书渠道的活动行原图下不来就用网站那张，用默认图的场次别当头条。
- 小红书出图超过 18 张、正文加标签超过 1000 字：减场次、合并场次少的日子或换重点版正文，先问作者。
- 截图或字体出问题（中文显示成方块）：海报里中文字体从 jsdelivr 加载，网络不通会退回系统苹方，版式会略有不同，告诉作者。
- 依赖：python3 带 playwright、Pillow、opencv（没有 opencv 就跳过二维码自检，请作者手机扫一下），node（解析网站数据）。
