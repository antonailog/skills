# 小红书多图推送

一段日期里的 AI 活动做成一组 3:4 图（封面 + 每天的活动页）和一篇笔记的标题、正文、标签。读者是刷到这篇的陌生人，不认识作者、不在群里，所以每张图自己要讲得清每场：什么时候、在哪、谁办、多少钱。平台判引流，图上和文字里一个网址、一个二维码、一个「扫码」都不能有。

推送目录：`宣传/发布/<开始日期>-小红书/`。

## 1. 选场

作者给了截图、活动名、海报：就用这几场，跳到第 2 节。只给了日期范围（「近期的活动」「11/11 到 11/17」）：按下面的规则从网站全量里挑，写成 `范围.md` 给作者过目，他点头再往下做。

```bash
python3 -I $S/fetch_events.py --range <起> <止>          # 列出这段日期里的第一层活动
```

- 日期按北京时间，作者人在哪个时区都一样。
- 留下：主题直接是 AI 的活动（技术、产品、开发者、AI 创作、AI 办公实操、具身智能），主办方是认得出来的公司、社区、媒体、协会或高校。
- 不留：投融资路演、招商推介、跨境电商卖货、招生和培训推销（DBA、「搞钱」课）、只挂了 AI 名字的行业会（制药、财税、家政）、信息太少核实不了的、台北和香港的。
- 征集、榜单、线上比赛：排在截止那天，标「线上」。
- 网站上同一场有两条（两个报名页用同一张海报）：留信息全、封面不带二维码的那条，另一条照 `新活动上网站.md` 标重复。
- 可疑的单独列出来让作者定：主办方是平台上的匿名账号（「主办方9873」）、原文留了个人微信、嘉宾介绍是「副业赚钱」「变现教练」。

`范围.md` 分三块：默认入选（按天列表，每行标签、活动、费用、id）、备选（一行一场，写为什么默认不放）、不在范围里但值得提的（下周的大活动、截止日在后面的征集）。场数用脚本数，不要心算。

## 2. 写 小红书.json

```bash
cd 宣传/发布/<开始日期>-小红书
python3 -I $S/fetch_events.py --ids <id ...> --out 选中.json --xhs 小红书.json --week <起> <止>
```

SKILL.md 第 2 步已经跑过这条就不用再跑：草稿已经存在时脚本不覆盖（改过的稿会丢），确实要重起加 `--force`。完全在范围外的场次脚本会报出来、照它自己的日子排，作者点名要放的再挪。

草稿里排在哪天、钟点、地点、价格、宣传图已经填好，`intro` 和 `cover_ids` 空着。逐场核实后改：

| 字段 | 写法 |
|---|---|
| `name` | 用 `\n` 手动断行，按意思断（「PCEA TALK 第 200 期\n走进腾讯 WorkBuddy」）；网站标题里的「【活动报名】」「重磅」这类去掉 |
| `time` | 同一天写「13:30–17:00」；跨天的照实写首日钟点；报名页和海报对不上写「时段以报名页为准」；没写写「钟点未写」 |
| `due` | 红色小标签，只放会影响去不去的：需审核、限 N 人；征集写在 `time`（申报截止） |
| `venue` | 「区 · 场馆」，门牌和楼层只在放得下时写；线上写「线上直播」「线上申报」 |
| `org` | 真正的主办方；平台发布账号和主办不是一家时按海报写 |
| `intro` | 一到两句、三行以内，写这场是什么、看点是什么（谁来讲、几个项目、多大规模），不写报名方式 |
| `price` | 6 个字以内：免费、¥199、¥0–98、押金¥299；没写留空（票面印「费用未写」） |
| `cover_ids` | 封面上叠放 1–5 场，一般放满 5 场：挑最有名的、宣传图好看的、城市错开的 |
| `cover_big` / `cover_blur` / `hero` | 见第 3 节 |

活动行这类页面在本机浏览器里按系统时区显示钟点，本机不在东八区就要换算回北京时间；活动行连续打开会限频，先用 `选中.json` 里网站存下的结构化字段和「原文」核，碰到验证码马上告诉作者，别干等。核实依据逐场记进 文案.md 的核实记录；网站上写错的照 `新活动上网站.md` 第二节修。

## 3. 出图

```bash
python3 -I $S/make_xhs.py 小红书.json 出图
```

版式是作者定的，脚本里已经写死，每期只改数据：

- **封面**：日期范围大字 + 「AI 活动推荐」+ 城市行，下面是 `cover_ids` 那几张票叠放，和活动页的票是同一个组件。
- **每天的活动页**：一天单独占页，顶上一行固定是「11/4 周三 ——— by 阿東」，票从上往下排。6 场拆 3+3，5 → 3+2，4 → 2+2；3 张的页第一张放大成大票，2 张的页两张都是大票。
- **头条**：这页第一张横版宣传图的那场放大放最上面。想指定哪场当头条，在那场写 `"hero": true`；它只在自己落进的那一页生效（先按 JSON 顺序切页，再在 3 张的页里挑头条），想让它进当天第一页，先把它在 JSON 里挪到那天的前三场。2 张、1 张的页每张都是大票，不用挑。没有宣传图的场次（用默认图）不要当头条。
- **只有 1 场的日子**：一张大票放不满一页，下面会空一块。场次实在少，可以和作者商量这天不放，或者换一场。
- **门票**：票根宣传图 16:9，正文写标签、时间、名称、地点、主办方、介绍，副券写价格。图上不重复写页顶已经有的信息（不加周历条、不写「当天 N 场」）。
- **宣传图**：脚本按 id 去活动库找活动行的原图（800 宽，比网站存的 640 清楚），比 `cover` 那张宽就换上，并打印换了几场；也可以在 `cover_big` 里指定一张更大的（拿不到会报）。作者特意挑了 `cover`、不想被换的，那场写 `"cover_big": false`。竖长海报截顶上一块。
- **虚化**：宣传图里印着「扫码报名」「二维码」或网址的，在 `cover_blur` 里写那块的比例坐标（`[[x0, y0, x1, y1]]`，0–1）。坐标相对 `出图/素材/<id>.jpg` 那张（换过原图、裁过的最终用图）：先不写 `cover_blur` 跑一遍，打开那张量好，再写上重跑，脚本把那块高斯模糊掉。

出完先看 `出图/总览.png`，再逐张看大票：宣传图是不是这场的、糊不糊、有没有「扫码」之类的字。自检报的问题（溢出、孤字、截断、二维码、默认图、头条图太小、尺寸、超过 18 张）改 JSON 重出，直到只剩作者知道的那几条（比如确实没有宣传图）。

## 4. 标题

给 5–8 个候选，每个 20 字以内，前 10 个字里有读者会搜的词（AI 活动、北京、上海）或最大的看点。

吸引人靠这期真有的东西：

- 大活动、大名字：「AIE首次来华！这周33场AI活动排好了」「这周有丘成桐和斯坦福院长的AI分享」
- 实打实的数：「这周33场AI活动，18场免费」
- 城市和人群：「北京AI人这周别宅家，15场活动」「上海AI人这周去哪？12场排好了」
- 活动类型：「黑客松、Codex课、具身沙龙这周都有」
- 朴素报题：「这周的AI线下活动，按天排好了」

不用营销腔：不写震惊、必看、不看后悔、全网第一、史上最、建议收藏、码住、干货满满、家人们、宝子们。名字和数字要对得上：「能听」「能见到」只在确实能报名参加时写，优先校友、要审核的写「有……的分享」。

## 5. 正文

小红书正文不显示 Markdown：不写加粗、`#` 小标题和列表符号，靠空行分段；不放 emoji。正文加标签不超过 1000 字。开头一句先报数，数字从 `check_xhs_text.py` 打印的统计里抄。两种写法，作者挑：

**清单版**：开头一句报数，然后按天一行一场「城市｜名称｜价格」。33 场大约 950 字，标签只剩 50 字左右的空间。

```
11/4–11/10 的 AI 活动按天排好了，共 33 场：北京 15、上海 12、深圳 2、杭州 1，线上 3。票上写了时间、地点、主办方和费用，搜活动名能找到报名页。

11/4 周三
上海｜GTC 全球流量大会｜普通票免费
北京｜企业本体落地闭门研讨会｜免费
```

**重点版**：完整清单交给图，正文挑 6–8 场值得专门空出时间的，每场两行（「日期 城市｜名称」+ 一句看点和价格），同类的几场并成一段（具身智能 3 场、Codex 2 场、截止的征集），最后一句告诉读者怎么找报名页、问一句去哪场。

```
11/4–11/10 的 AI 活动整理好了，一共 33 场，18 场可以免费去：北京 15、上海 12、深圳 2、杭州 1，线上 3，周末两天有 10 场。每场的时间、地点、主办方、费用都在图里，按天排好了，下面挑几场值得专门空出时间的

11/5–6 上海｜AI Engineer Shanghai 2026
AI Engineer 大会首次来华，51 场演讲与圆桌，Manus、Harvey 内部实践首次公开，¥1999

具身智能有 3 场，都免费：11/4 上海 iTalk 聊 VLA 落地，11/5 上海机器之心 Data In Motion 聊具身数据，11/6 北京具身智能产业论坛

搜活动名就能找到报名页。这周你打算去哪场？
```

看点只写票面和核实记录里有出处的事实。不写「报名链接在评论区」「私信我要」这类引导。

## 6. 标签

6–8 个，三层各挑：

- 大词：#人工智能 #AI活动
- 城市和场景：#北京活动 #上海活动 #北京AI活动 #上海AI活动 #周末去哪儿 #AI线下活动
- 主题：这期确实有的类型（#具身智能 #黑客松 #Codex #AIEngineer）

每个标签在正文里都要有对应的内容（写了 #周末去哪儿，正文就要提周末那几场）；同一层只留最具体的那个。各话题的浏览量查不到（要登录或付费工具），告诉作者：发笔记加话题时，候选列表里会显示浏览量，同类里挑大的换。标签发的时候一次定好，发出去再改容易被限流。

## 7. 检查和交稿

```bash
python3 -I $S/check_xhs_text.py 文案.md 小红书.json
```

它查每套标题的字数、正文加标签的字数、网址和引流 / 限流词，并核对正文里「共 N 场」「北京 N」「N 场免费」「周末 N 场」和数据对不对。都过了再交稿。

`文案.md` 的结构：最上面一句发法（图按 01 → NN 的顺序一次传完，再贴标题、正文、标签），两条 `---` 之间是可以直接复制的一套，另一种正文写法放在下面一节（`## ` 开头），最后是 `## 核实记录`。检查脚本认这几个标记：`**标题…**` 下面是 `1. ` 这样编号的标题候选，`**正文**` 和 `**标签**` 各占一行，标签写在 `**标签**` 下面那一段；另一种写法那节可以只有 `**正文**` 和 `**标签**`。

交稿汇报照群推送第 7 步的写法。作者发出去以后，在发布索引最上面加一行，链接原样存（带 `xsec_token`），平台写「小红书」。
