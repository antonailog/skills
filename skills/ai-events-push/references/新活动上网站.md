# 新活动上网站、修网站上的错

作者给的活动网站上还没有（通常是别人发来的一张海报），或者核实时发现网站上某场的信息错了，读这份。两件事都是改线上网站，**先把要改的内容给作者看，作者说可以再发布**。

下面的路径都相对活动监测项目目录（`AI_EVENTS_DIR`，没设就是 `~/claudecode_workspace/工具/活动监测/`）。

## 加一场新活动

1. **整理海报上的信息**。长海报切成几段放大看清小字；人名、公司名里拿不准的字再放大确认（11-02「苋在科技」差点认成「觅」）。报名二维码用 opencv 解：裁出二维码那块、放大两倍再解，裁得太紧解不出来。
2. **给作者看弹窗打算放什么**。逐项列：标题、分类、一句简介、时间、地址（括号外是主行，括号里是小字）、主办方和各单位、费用、重点关注（两三条）、宣传图、议程、嘉宾、报名链接、活动原文。海报上没写的（费用、结束时间、谁讲哪场）照实写没写，不替它补。11-02 那场的讨论稿在 `设计/讨论/2026-11-02-新活动-聚上地-弹窗方案.md`，可以照着列。
3. **作者确认后写精编记录**：在 `样稿/活动-2026-10-26.json` 末尾加一条，格式照文件里已有的条目。几个本项目自己加的字段：
   - `封面`：整张海报放进 `数据/covers/`，写文件名；长海报再给 `封面小图`（截标题那一块，16:9 左右），日历卡片和门票用它，弹窗用整张。
   - `原文文字`：把海报上的字整理成 Markdown（小标题、列表、**加粗**标签，冒号放在 `**` 外面），弹窗按 Markdown 显示。
   - `地图搜索`：地址主行是场地名、地图上搜不到时（「直觉创造」），写楼名给地图链接用。
   - `报名`：二维码解出来的链接。
   - id 用 `<拼音简写>-<城市缩写>-<月日>`，比如 `jushangdi-bj-1104`。
4. **本机构建看一眼**：`python3 -I 脚本/发布页面.py --build --dry-run`，在 `页面/app/dist-site` 起一个本地服务（先用 `lsof -nP -iTCP:<端口> -sTCP:LISTEN` 确认端口没人占，8765 常被别的服务占着），打开 `?e=<id>` 截图给作者。
5. **发布前比对**：只带这次的改动上去。
   ```bash
   RS=(rsync -rlptzn -c -i --exclude __pycache__ --exclude .DS_Store -e "ssh -o BatchMode=yes -o ConnectTimeout=15")
   H=$(grep -m1 '^HOST=' 脚本/服务器.sh | cut -d= -f2):$(grep -m1 '^R=' 脚本/服务器.sh | cut -d= -f2)
   for p in 脚本/ 样稿/ 活动库/内容/; do "${RS[@]}" --delete "$p" "$H/$p" | grep -v '^\.'; done
   ```
   列出来的应该只有你改的文件；多出别的，先问作者是不是别的会话在改。
6. **发布**：`zsh 脚本/服务器.sh 发布`（服务器上重建再发，五到十几分钟）。完了打开 `https://antonailog.com/more/ai-events/?e=<id>` 核对弹窗，控制台没有报错才算完。

## 修网站上某场的错

比如活动方海报写 14:00–17:00，网站写 09:00–18:00：以活动方海报为准。

- 自动整理的内容在 `活动库/内容-自动/<id>.json`，每天会被重写，不要改它。复制一份到 `活动库/内容/<id>.json`（人工的优先），改对字段，在「说明」里写一句为什么改、依据是什么。
- 改之前先 `zsh 脚本/服务器.sh 拉回`，拿到服务器上最新的自动内容再复制。
- 发布前比对、发布、核对，同上面第 5、6 步。
