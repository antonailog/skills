# html-deck — HTML 演示稿

交付一个项目文件夹：一份能放映、能在页面上改的 HTML 讲稿，到定稿时再出离线包和网站版。

## 定位与边界

像一个懂设计、也懂演讲的制作搭档：把「这一页观众该先看到什么」讲透。每页一个观点，结构先于样式；拿不准的地方摆出来给用户挑，他拍板，你落地。

用户要的是一份能上台、讲得清楚的稿子，不是一套好看的模板。所以先定讲什么（场合、时长、听众、每页一句观点），风格从 4 套里挑；要拍板的事做成讨论页让他点选；改稿靠他在页面上直接改和批注，不靠来回对话描述「第几页左边那个」。

一次只做一份稿。要 .pptx / Keynote 文件交给 pptx；单页图解、流程图交给 archify；把讲稿改成公众号文章交给 human-article；海报交给 image-prompt；部署到某个具体网站交给用户自己的发布流程（这里只出静态目录）。

## 按需读取

| 文件 | 什么时候读 |
|---|---|
| `references/components.md` | 第 2 步排大纲、第 4 步写稿之前 |
| `references/themes.md` | 第 3 步挑风格、用户要微调颜色字体时 |
| `references/revise.md` | 第 5 步每轮改稿之前 |
| `references/deliver.md` | 第 6 步交付之前；用户要外发或公开时 |
| `references/presenting.md` | 用户问按键、翻页笔、演讲者视图、动效时；现场演讲的稿交付时 |

脚本都在 `scripts/`，下文 `SKILL_DIR` 指本文件所在目录。脚本用 Python 3 标准库；检查、风格渲染要 Playwright，讨论页压缩图片用 Pillow（没有也能跑）。

## 意图分流

| 意图 | 信号 | 从哪步开始 |
|---|---|---|
| 新稿，信息齐 | 有主题，且有场合或时长，且有材料或大纲 | 第 1 步只补缺的，接着第 2 步 |
| 新稿，只有主题 | 「做个关于 X 的分享」 | 第 1 步：问开工的几件事，给一版大纲骨架 |
| 在别的事里提到要上台 | 「下周要汇报这个」 | 一句话问要不要做成演示稿，不自动开工 |
| 改已有的稿 | 给了项目目录，说「批注完了」「改第 5 页」「换风格」 | 第 5 步（换风格走第 3 步） |
| 交付 | 「打包」「拷到别的电脑」「发到网上」 | 第 6 步 |

## 1 开工

问清这几件，缺什么问什么，一轮最多问 3 件，其余用默认并写明：
- 场合和听众：谁来听、他们懂多少、听完要他们做什么
- 时长：决定页数（大约每页 1—2 分钟）
- 现场条件：用谁的电脑、有没有网、有没有翻页笔、投影比例、要不要双屏看备注
- 材料：大纲、文档、数据、截图、录屏在哪
- 公开范围：以后会不会外发或公开；真名、公司、项目代号哪些不能出现（交付时要放进扫描词）

## 2 大纲

读材料，排页：每页一行，写观点句、用什么组件、要不要分步。组件和写法见 `references/components.md`。

- 标题写观点不写分区名；一页一个观点
- 分步只标在「先讲 A 再揭晓 B」这种页上
- 数字、引用、出处来自用户材料，或打开核对过的来源；材料撑不起时长时，列出缺口问用户，不编内容
- 先不砍内容，时长超了最后一起删

大纲给用户确认。页多、要他挑的地方多时，用讨论页（第 5 步的 discussion.py）。

## 3 风格

按场合推荐 1—2 套，再用大纲里的封面加 2—3 页有代表性的内容渲染 4 套给他挑（第一次建项目时先用推荐的那套建，见第 4 步）：

```bash
python3 $SKILL_DIR/scripts/render_styles.py <项目>/讲稿 --pages 1,3,6 --recommend keynote
```

生成 `改稿/风格/风格讨论.html`，用浏览器打开给用户。他选定后改 index.html 里那一行风格 link。

## 4 初稿

```bash
python3 $SKILL_DIR/scripts/scaffold.py <项目目录> --title "标题" --theme swiss --author "署名" --event "场合"
```

建出 `讲稿/index.html`（内容）、`讲稿/deck/`（引擎和 4 套风格，每份稿各拷一份，以后升级引擎不改坏旧稿；要升级用 `--engine-only`）、`讲稿/嵌入/`、`改稿/`、`交付/`。

按大纲写 `<div id="stage">` 和 `</div><!-- /stage -->` 之间的内容，每页一个 `<section class="slide">`，每页写备注。这两个标记不要删：编辑模式和交付脚本靠它们定位内容。写完跑检查，有问题修到过：

```bash
python3 $SKILL_DIR/scripts/check.py <项目>/讲稿 --shots <项目>/改稿/截图
```

再看几页截图（用 Read 看图），确认版面像样，然后告诉用户怎么打开、怎么开编辑模式。

## 5 改稿

按 `references/revise.md`：开编辑模式（`scripts/serve.py`）让用户在页面上改和批注；读 `改稿/批注.json`，意思明确的直接改，要拍板的（设计、改写、删减、看不懂的、和之前定过的冲突）做成讨论页：

```bash
python3 $SKILL_DIR/scripts/discussion.py <spec.json> -o <项目>/改稿/讨论-<日期>-<事>.html
```

排版问题给真实渲染的几种排法，不给线框图。每条批注改完标 status 和 reply。用户在页面上直接改过的内容原样保留：改文件只做局部替换，不凭记忆整页重写。

## 6 交付

按 `references/deliver.md`：

```bash
python3 $SKILL_DIR/scripts/check.py <项目>/讲稿
python3 $SKILL_DIR/scripts/package.py <项目>/讲稿 --words 真名,公司名        # 离线包
python3 $SKILL_DIR/scripts/website.py <项目>/讲稿 --replace 真名=网名 --desc "摘要"   # 网站版（要公开时）
```

两个脚本都会对要装进去的全部文件跑隐私扫描，发现就停。扫描看不到图片里的内容：列出的截图你用 Read 看一遍，再请用户过目。现场演讲的稿，交付时附上按键和演讲者视图的用法（`references/presenting.md`）。

## 每轮回复用户

- 做了什么（一两句）、怎么打开看（文件路径或编辑模式地址）
- 要他定的事：讨论页链接，加一句每件事的推荐
- 检查结果：检查和扫描是否通过；没跑的说没跑

## 红线

1. **要拍板的事不替用户定**。设计、改写、删减、风格都给讨论页让他选；他的原话和已定的事不悄悄改。替他定下的东西上了台、发出去就收不回来
2. **用户在页面上改过的内容不被覆盖**。改 index.html 前备份到 `改稿/备份/`，只做局部替换；编辑服务开着时改完让他刷新
3. **外发和公开前扫解压后的全部文件**。页面上看不到不等于文件里没有：嵌入页、数据、备注都会被带出去。扫描发现的逐条处理，不直接 `--force`；网站版不放备注和只在现场用的嵌入
4. **不编数据和引用**。数字、原话、出处来自用户材料或打开核对过的来源；拿不准的标出来问

## 出问题时

| 情况 | 怎么办 |
|---|---|
| 没装 Playwright | 检查只查文件；风格渲染改为把 themes.md 的说明和 `assets/components.html` 给用户看；明说这次没做自动检查 |
| 编辑服务端口被占 | 脚本自动换端口，告诉用户新地址 |
| 字体下载失败（没网、被墙） | 脚本落到系统字体并提示；联网后重打。设了代理的走 `HTTPS_PROXY` |
| 检查报溢出 | 缩短文字、拆页，不靠缩小字号硬塞 |
| 讲稿里找不到 stage 标记 | 补上 `<div id="stage">` 和 `</div><!-- /stage -->` 再开编辑模式 |
| 在线页没有备用截图 | 截一张放 `嵌入/截图/`，在 `.box` 里加 `<img class="shot">` |
