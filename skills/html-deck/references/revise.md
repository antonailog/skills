# 改稿循环

用户在页面上直接改、留批注；你读批注，明确的直接改，要拍板的做成讨论页；改完逐条标状态。一轮一轮走到定稿。

## 开编辑模式

```bash
python3 <SKILL_DIR>/scripts/serve.py <项目>/讲稿        # 打印 http://127.0.0.1:<端口>/，端口被占会自动换
```

告诉用户：打开地址，按 E 进编辑模式。能做的：点选元素、双击改字、Delete 删除、⌘Z 撤销、`[` `]` 调字号、面板上改粗细颜色、按住拖动挪位置（吸附 8px，Option 自由拖）、选中元素或整页写批注（可粘贴截图）、N 打开备注直接改。改动自动保存回 index.html；批注存 `改稿/批注.json`。服务要一直开着，改完让用户告诉你。

## 读批注

`改稿/批注.json` 是一个列表，每条：

| 字段 | 意思 |
|---|---|
| `page` | 第几页（全局批注为 null） |
| `scope` | 元素 / 本页 / 全局 |
| `target.path`、`target.text` | 批注的是哪个元素和它的文字。path 写成 `页序号:子元素序号链`，都从 0 数：`2:1.0` 是第 3 页的第 2 个子元素里的第 1 个。以 text 为准，path 只在页面结构没变时准 |
| `text`、`images` | 批注原文、截图（`改稿/图/…`，用 Read 看图） |
| `status`、`reply` | 你来填：`已改` / `有疑问`，和一句怎么改的 |

先读全部批注和截图，再看 index.html 里用户在编辑模式里直接改过的地方（和上一版对比），这些改动原样保留。

## 分两类

- **意思明确的直接改**：换字、删一块、调顺序、照用户给的样子改。改完在 reply 写一句改了什么
- **要拍板的做讨论页**：设计和排版（怎么排、用什么图）、改写（要替用户写新句子）、删减、看不懂批注指什么、和之前定过的事冲突。status 标「有疑问」，reply 写「见讨论页第 N 题」

排版问题给真实渲染，不给线框图：把整个 `讲稿/` 文件夹复制几份（放 `改稿/` 下，连 deck/ 和嵌入文件一起，单拷 index.html 打不开），各改一种排法，截图放进讨论页。截图可以用 `python3 <SKILL_DIR>/scripts/check.py <目录> --shots <输出目录>`。

## 讨论页

```bash
python3 <SKILL_DIR>/scripts/discussion.py <spec.json> -o <项目>/改稿/讨论-<日期>-<事>.html
```

spec 写法见 discussion.py 开头。规矩：
- 标题写「要你定的 N 件事」；lead 说清这一轮已经直接改了什么
- 每题带上用户批注原文（context）、你的推荐（rec）和理由；选项并排
- 要用户改的文字放 `fill`，他可以直接在页面上改
- 用户点「复制我的决定」贴回来后，照着改，并把讨论页里没选的方案扔掉

开工时问信息也守同一条：一轮最多问 3 件，其余用默认并写明。

## 改文件时保护用户的手改

- 编辑服务开着时，用户可能正在页面上改。改 index.html 前先备份（`改稿/备份/`），改完告诉用户刷新页面；他那边没刷新就保存会被版本检查拦下，不会互相覆盖
- 只做局部替换（按原文片段精确替换），不凭记忆整页重写
- 改完跑 `scripts/check.py`，再截改过的几页自己看一遍

## 收尾一轮

- `批注.json` 每条都有 status 和 reply
- 回复用户：直接改了哪些（一两句）、讨论页链接、要他定的几件事
