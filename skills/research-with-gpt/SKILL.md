# research-with-gpt — Deep Research 的出题人和收卷人

出题时，交一组能直接复制进 ChatGPT Deep Research 的 prompt；报告回来后，交每份的摘要和一份对照。调研本身由用户在 ChatGPT 里跑：这个 skill 不联网查资料，也不派 Codex 去查，这是用户 2026-11-09 定的。

## 定位

像一个懂行的研究助理：先帮用户把真正想搞懂的问题问清楚，再拆成几份互不重叠的研究任务书；报告回来后，先讲清每份说了什么、彼此哪里一致、哪里矛盾，再等他定怎么用。

Deep Research 跑一次要几十分钟，次数有限，方向错了整轮白跑。所以出题前那一两轮对话最值钱，不要默认用户已经把问题想清楚。prompt 宁可多拆几条，也要每条问题具体、互不重叠。

## 文件夹

一个主题一个文件夹：工作区 `知识/调研/<主题>-<YYYY-MM-DD>/`，主题用中文短名。

```
0-说明.md          真问题、方向表、下一步
1-prompt.md        全部 prompt，和消息里给的一致
2-报告原件/        用户把下载的 md / docx / pdf 拖进来，不用改名
3-报告转写/        docx、pdf 转出的文字
4-摘要与对照.md
```

后续产出（方法论、导图等）接着用 5-、6- 编号。

报告常常隔几天才回来，下个会话只读 `0-说明.md` 就要能接上，所以它固定这样写：

```markdown
# <主题>

真问题：<钢人轮后和用户确认过的一句话>
用途：<用户拿结果去做什么>

| # | 方向 | 报告文件 |
|---|---|---|
| ① | <方向名> | <2-报告原件/文件名，没回就空着> |

下一步：<一句话>
```

## 进来先分流

| 信号 | 走哪段 |
|---|---|
| 新主题，`知识/调研/` 下没有对应文件夹 | 出题 |
| 用户说报告回来了，或 `2-报告原件/` 里有表中没登记的文件 | 收卷 |
| 「再补两条」「③ 重出」 | 在原文件夹里追加或替换，编号接着排，`0-说明.md` 和 `1-prompt.md` 一起改 |

说报告回来了，却不知道是哪个主题时，列出 `知识/调研/` 下方向表里还有空行的文件夹，问是哪一个。

## 出题

### 1. 先查背景

先查再问，问题才问得准。读这几处：

- 记忆（MEMORY.md 里和主题相关的条目）：用户是谁、在做什么、踩过什么坑、有哪些写法偏好
- `知识/调研/`、`知识/学习/`、`知识/设计/` 等目录里和主题相关的已有调研：记下哪些已经调研过，写进每条 prompt 的「不用重复」
- 主题落在某个项目上的，读那个项目的 project.md

### 2. 双向钢人

用户的原话（2026-11-08 定的口令，照做、不改写）：

> 先别急着回答，也别默认我已经把问题想清楚。
> 请先对这个问题做一次详细思考的“双向钢人论证”：
> 1.用最完整、最有力的方式，重述我真正想解决的问题。
> 2.使用钢人论证法分别给出支持我当前想法、以及反对它的最强论证。
> 3.找出双方真正的分歧，以及最可能改变结论的关键变量。
> 4.只问我一个最关键的问题。
> 等我回答后，再给出明确判断、理由和下一步行动。

这一轮只交这四步，第 4 步只问一个问题，不附结论，也不附默认方案，然后停下来等回答。「不回就按默认开工」在这里不适用。用户回答后，如果最能改变方向的变量还没定，再来一轮，同样只问一个问题；真问题清楚了就往下走，不为凑轮数多问。

常见的关键变量：要学到什么程度（能判断、能动手、能教人）；结果拿去做什么（做决定、建 skill、写文章、落到某个项目）；已经知道和已经否掉的东西；地域和时间范围。

### 3. 拆方向

拆成 5–8 条，每条是一个能单独回答的问题域，彼此不重叠。

- 先覆盖用户点名的方向，再补他没想到、但真问题需要的。补的那几条要在方向表里写明为什么加
- 一条里塞了两个问题域的拆开；两条问的是同一件事的合并
- 理念类（是什么、为什么）、方法类（怎么做）、资产和工具类（用什么）、案例类（别人怎么做成的），通常各成一条
- 每条的「这次不用讲」要指向另外几条，这样几份报告不会互相重复

### 4. 写 prompt

写之前先读 `references/范例-AI设计协作.md`，学它的格式和颗粒度，不照搬内容。

每条六段，顺序固定：

1. **【背景】** 每条都完整带上同一段，因为每条都在一个单独的 ChatGPT 对话里跑，看不到另外几条。要写：现在的年月；用户是谁；他现在的做法；反复遇到的问题（报告能不能对症，看的就是这一段）；已经调研过、不用再罗列的；钢人轮问出来的用途。只写用户愿意给 ChatGPT 看的内容。
2. **【这次调研】** 一句话题目。
3. **请回答**：3–7 个编号问题，每个都具体到能判断报告答没答上。给线索名单时写明「需核实现状，不限于这些」，因为你记得的工具名和版本可能已经过时。
4. **这次不用讲**：指向另外几个方向，以及已经调研过的内容。
5. **【交付结构】** 用 → 串起章节顺序，最后一节是来源列表。如果是学东西的主题，加一节「拿用户自己的场景从头示范一遍」。
6. **【写法要求】** 照抄下面这段。主题需要时可以加一句，比如「例子尽量考虑中文页面」：

```text
【写法要求】
- 用中文写，术语第一次出现时附英文原词。读者是第一次系统学这个主题的人：先给结论和全景，再一层层展开。每条原则配一个具体例子。
- 每个事实都附来源链接和发布日期，优先用近一年的材料。变化快的领域，用到旧材料时注明可能过时。
- 来源是什么性质（官方文档、有过程的实测、个人观点），在正文里用一句话说明。不要用【高/中/低】这类标签打分。
- 不要营销话术和空泛的“最佳实践”。每条建议都说清：解决什么问题、怎么做、什么时候不适用。找不到证据就直说。
- 背景都写在上面了，不用先问我澄清问题，直接开始。
```

最后一句要留着：Deep Research 开跑前常会先反问一轮，这句话能省掉用户一次来回。

### 5. 交付

建好文件夹，写好 `0-说明.md`、`1-prompt.md`，再建一个空的 `2-报告原件/`。消息按这个顺序：

```
写给：ChatGPT Deep Research，每条单独开一个对话发。

<一行判断：真问题是什么>

<方向表：编号 | 方向 | 为什么单列>

只想先发几条的话：先发 ①②⑦，<一句理由>。
下载报告时优先选 Markdown（Word 和 PDF 转成文字会丢掉来源链接），放进 <文件夹绝对路径>/2-报告原件/，放好后说一声。

### ① <方向名>
（代码块：完整 prompt）
……
```

方向表和 prompt 放在同一条消息里给。用户说「③ 换成 X」，就只重写那一条，两个文件跟着改。

## 收卷

### 1. 登记

把 `2-报告原件/` 里的每份报告对上方向表的编号。看标题和正文判断，不靠文件名。对不上任何一条的单独列出来，问用户归哪条。只回来一部分时，先做回来的那几份，没回的在表里留空。

### 2. 转成文字

md 直接读。docx 和 pdf 转成文字放进 `3-报告转写/`，文件名用 `<编号>-<方向>.txt`：

```bash
textutil -convert txt "<原件.docx>" -output "3-报告转写/<编号>-<方向>.txt"
pdftotext -layout "<原件.pdf>" "3-报告转写/<编号>-<方向>.txt"
```

转出来是空的或乱码（多半是扫描版 PDF），告诉用户是哪一份，请他重新下载 Markdown 或 Word 版。

### 3. 摘要与对照

写 `4-摘要与对照.md`：

```markdown
## ① <方向>（<原件文件名>）
核心结论：三句以内
最有用的：3–5 条，每条一句，附报告里的来源链接

（每份一节）

## 对照
### 共识
### 矛盾
（谁说了什么，各自的依据）
### 只有一份提到的
```

只写报告里写了的内容。你自己的判断单独标成「我的看法」，用户要分得清哪些是报告说的、哪些是 AI 加的。

### 4. 问下一步

回复里写几行结论：最重要的三条共识、最值得注意的一个矛盾。附上文件链接，然后问用户下一步做哪个。可以说你推荐哪个，但在他回答之前不要动手：

1. 合成一份方法论，写成 `5-方法论.md`：先给结论，再逐条展开，接着讲流程，然后拿用户的项目从头示范一遍，最后附检查清单
2. 转成导图：交给 book-to-mindmap
3. 发到飞书：用 lark-cli，格式规则见全局 CLAUDE.md
4. 做成 skill：交给 skill-build
5. 补一轮 deep research：回到出题，编号接着排

最后更新 `0-说明.md` 的方向表和下一步。

## 红线

1. 摘要和对照里不编造报告没写的内容，也不编造来源链接。用户会拿它们做判断，编出来的东西看上去和真的一样。
2. 不删除、不改动 `2-报告原件/` 里的文件。那是用户下载的原件，可能没有第二份。
3. prompt 的背景里不写账号、密钥，不写未公开的他人信息。prompt 会被发到外部服务。
