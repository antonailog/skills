# 范例：AI 设计协作（2026-11-09）

这是用户第一次走这个流程时用的 7 条 prompt，用户认可了这套格式。学它的格式、颗粒度和拆法，不要照搬内容。

当时还没有钢人轮，背景里少了一句「用途」，现在写的时候要补上。

目录：
1. 主题和拆法
2. 共用的【背景】
3. 共用的【写法要求】
4. 七条 prompt 各自的部分

实际交付时，每条 prompt 都完整写成【背景】→ 各自的部分 →【写法要求】，放进一个单独的代码块。这里为了不重复，共用的两段只放一次。

## 1. 主题和拆法

用户原话：想系统学习「怎么做好 AI 设计」，比如和 agent 协作创建页面时，怎么一起做出高质量、最好还能令人惊艳的页面。点名的方向有：设计理念、方法论、好的 skill、好的工具，以及「其他你认为有价值的方向」。

| # | 方向 | 为什么单列 |
|---|---|---|
| ① | 设计理念：好页面从哪来、AI 为什么做得平庸、怎么把品味讲给 AI | 用户点名；直接对着「千篇一律」这个痛点 |
| ② | 协作方法论：完整工作流 | 用户点名 |
| ③ | skill 和规则：现成可装的 | 用户点名 |
| ④ | 工具：按工作流环节梳理 | 用户点名 |
| ⑤ | 质量闭环：让 agent 看见、评审、验证 | 补的：没有验证，前面几条都落不了地 |
| ⑥ | 惊艳手法：动效、排版、3D、叙事 | 补的：用户想要「惊艳」，理念类那条讲不到实现 |
| ⑦ | 案例拆解：高手的真实过程 | 补的：方法论容易空，要有过程可查的真例子 |

建议先发 ①②⑦，因为这三条直接对着「千篇一律」。工作区里已经有「UI 组件库生态」和「Web 字体与排版」两份调研，所以每条都注明这两块不用再罗列。

## 2. 共用的【背景】

```text
【背景】
现在是 2026 年 11 月。我是独立开发者，不是科班设计师。我平时让 coding agent（Claude Code、Codex）直接写前端代码做页面，包括个人网站、工具界面、活动页、宣传长图。页面以中文内容为主，技术栈是 React + Tailwind + shadcn/ui。
我现在的做法：先定页面结构再动手；先出首屏截图，确认后再做全页；配色用现成主题，不让 AI 自己调；组件优先用现成库；在真实 design token 的骨架上定布局；项目里用 DESIGN.md 记设计规范。
反复遇到的问题：页面能用，但千篇一律，被评价“没有设计性”；AI 自己调的配色多轮被否；用 AI 生图定下的视觉气质，落到代码里对不上；给了参考网站，产出没对齐，整版返工；页面上解释性的小字越加越多。
UI 组件库和动效组件生态、Web 字体与排版，我已经调研过，这两块不用再列。
```

注意这几处：当前年月；「我现在的做法」和「反复遇到的问题」都写的是具体事，不是形容词；已经调研过的内容明说不用再列。

## 3. 共用的【写法要求】

```text
【写法要求】
- 用中文写，术语第一次出现时附英文原词。读者是第一次系统学这个主题的人：先给结论和全景，再一层层展开。每条原则配一个具体例子（网站、代码片段或 prompt 原文）。例子尽量考虑中文页面的情况。
- 每个事实都附来源链接和发布日期，优先用 2025 年下半年以来的材料。工具和模型变得快，用到旧材料时注明可能过时。
- 来源是什么性质（官方文档、有过程的实测、个人观点），在正文里用一句话说明。不要用【高/中/低】这类标签打分。
- 不要营销话术和空泛的“最佳实践”。每条建议都说清：解决什么问题、怎么做、什么时候不适用。找不到证据就直说。
- 背景都写在上面了，不用先问我澄清问题，直接开始。
```

## 4. 七条各自的部分

### ① 设计理念

```text
【这次调研】好页面从哪来：设计理念、AI 做出来平庸的原因、怎么把品味讲给 AI

请回答：
1. 哪些网页设计原则经得住时间（层级、排版、网格、留白、对比、一致性、内容优先等）？按对页面质量的影响排序，每条配一个 2025–2026 年优秀网站的例子。
2. AI 生成的页面为什么普遍平庸、彼此雷同（常被叫作 "AI slop" 或“AI 味”）？列出典型特征，例如紫蓝渐变、Inter 字体、居中大标题加三栏卡片、emoji 当图标、到处是圆角和阴影。分析成因，比如训练数据分布、模型默认值、指令太泛、没有参照。再整理 Anthropic、Vercel 和设计师社区对这个问题的分析和对策。
3. 品味（taste）能不能拆成可以传达的东西？设计师、design engineer、art director 怎么描述和传递品味？moodboard、参考网站、风格关键词、反例清单各起什么作用，各有什么局限？
4. 给 AI 描述设计意图时，哪些设计词汇最能改变产出？按类别整理：风格流派（如 Swiss style、editorial、brutalism、bento）、版式、字体、色彩、质感、动效。每个词写清：它是什么意思，说它和不说它 AI 的产出有什么区别，再给一个代表网站。只收说了真能改变产出的词。
5. 设计理论和实践里怎么解释“令人眼前一亮”？可以从这几方面讲：新颖和熟悉之间的平衡（如 MAYA 原则）、记忆点、叙事、细节打磨。什么情况下追求惊艳反而伤害页面？

这次不用讲：具体工具对比、skill 推荐、协作流程的步骤（另有调研）。

【交付结构】
一页结论 → 设计原则 → AI 做得平庸的特征和成因 → 品味怎么传达 → 设计词汇表（表格）→ 惊艳与克制 → 给我的 10 条可以直接照做的建议 → 来源列表
```

### ② 协作方法论

```text
【这次调研】和 coding agent 协作做一个页面：完整流程和方法论

请回答：
1. 设计师、design engineer，以及做 AI 设计产品的团队（如 Vercel v0、Anthropic、Figma、Linear、Lovable 的成员）公开分享过“用 AI 做页面”的真实流程，这些流程具体是什么样？按阶段整理：需求和 brief → 找参考 → 定方向 → 结构和线框 → 视觉定稿 → 实现 → 细节打磨 → 验收。
2. 每个阶段人做什么，AI 做什么？人的判断放在哪几个节点最划算？哪些阶段应该让 AI 一次出多个方案并排比较，哪些阶段应该只改一处？
3. 设计 brief 怎么写给 agent？哪些信息必须给（受众、目的、真实内容、气质、参照、约束、反例）？哪些信息给了反而会限制产出？找 2–3 份公开的高质量 brief 或 prompt 原文，分析它们为什么有效。
4. 从设计到代码有几条路线，请对比：先在 Figma 或画布上出稿，再让 agent 实现；直接让 agent 在代码里设计（design in code）；先用 AI 生图定气质，再转成代码；先用 v0 这类工具生成，再迁移进项目。每条路线适合什么情况，常见的失败是什么，从业者的结论是什么？
5. 设计规范怎么变成 agent 能遵守的上下文？包括 DESIGN.md、design token 文件、组件清单、AGENTS.md / CLAUDE.md 里的设计规则；W3C Design Tokens 规范现在进展到哪；有没有公开的好范例。
6. 迭代时怎么给反馈最有效？截图标注、指到具体元素、给数值还是给感受、一轮给几条、什么时候该推倒重来。
7. 参考网站怎么用，才能让产出真的对齐？要从参考里拆出哪些维度（版式、比例、字号阶梯、间距、配色、动效节奏）？怎么防止 agent 只学到表面？

这次不用讲：逐个对比工具、推荐 skill（另有调研）。

【交付结构】
一张流程总图（Mermaid）→ 分阶段详解（每个阶段写目标、人做什么、AI 做什么、产物、常见坑）→ brief 模板和示例 → 反馈写法模板 → 参考网站拆解清单 → 完整示范：用这套流程做一个“个人项目展示页”，从 brief 到验收，每一步都写出给 agent 的实际指令 → 来源列表
```

### ③ skill 和规则

```text
【这次调研】能提升 AI 前端设计质量的 skill、规则和系统提示词

请回答：
1. 盘点公开可用、专门用来提升 AI 前端设计质量的东西：Agent Skills（SKILL.md 格式，Claude Code 和 Codex 都能用）、Cursor rules、AGENTS.md 片段、MCP server 自带的指令等。线索如下，请核实现状，也不要只看这些：Anthropic 官方的 frontend-design skill、impeccable、ui-ux-pro-max、Vercel Web Interface Guidelines 及配套的 agent skills，以及 awesome-claude-skills、awesome-cursorrules 这类合集里和设计相关的条目。
2. 每一项都写清：作者、地址、最近更新时间、使用量（star 等）、核心机制（审美原则、反模式清单、检查命令、设计词汇、流程编排，属于哪一种）、适用于哪些 agent、怎么安装、已知局限。
3. 有没有对比实测或用户反馈？装和不装，产出差多少？哪类写法真正改变了结果：反例清单（如“禁止紫色渐变”）、正面描述审美、强制先出多个方案、附带检查命令？找不到实测就直说。
4. AI 页面生成产品（v0、Lovable、Bolt 等）公开或泄露出来的系统提示词里，关于设计质量写了什么？它们有哪些共同点？
5. 根据以上内容总结：一个好的前端设计 skill 应该包含哪些部分？哪些写法有效，哪些无效（例如堆形容词、规则清单写得超长）？

这次不用讲：通用的 prompt 工程技巧、和前端设计无关的 skill。

【交付结构】
总览表（每一项 × 上面列的各个维度）→ 最值得装的 5 个，逐个说明理由和用法 → 系统提示词里设计规则的共同点（附原文摘录）→ 好 skill 的结构建议，加一个示范骨架 → 来源列表
```

### ④ 工具

```text
【这次调研】AI 设计和页面生成工具全景（2026 年）

请回答：
1. 按工作流环节整理工具。下面的名单只是线索，请核实现状，并补上近 12 个月出现的新工具：
   a. 找灵感和参考：Mobbin、Refero、Godly、Awwwards、Savee、Cosmos 等
   b. 用 AI 生成界面：v0、Lovable、Bolt、Figma Make、Google Stitch、Claude Artifacts、Magic Patterns、UX Pilot、MagicPath 等
   c. 把设计画布和 agent 打通：Figma MCP、Pencil、Paper、Onlook、Subframe、Builder.io 等
   d. 让 agent 看到页面：Playwright MCP、Chrome DevTools MCP、视觉回归工具等
   e. 视觉素材：配色、图标、插画，以及 AI 生成的图片和视频怎么用在网页里
2. 每个工具都写清：定位；我已经在用 Claude Code / Codex 写 React 代码，它怎么接进来（MCP、导出代码、CLI）；价格；公开的产出质量评价和代表作品；局限。
3. 对已经在用 coding agent 写代码的人来说，哪些工具能带来最多新东西？哪些和 agent 已有的能力重叠，可以不用？
4. 从业者反复推荐的工具组合有哪些？

这次不用讲：组件库和字体（已调研过）、纯设计师用的 Figma 插件细节、原生 App 的设计工具。

【交付结构】
环节 × 工具总表（每条信息注明查证日期）→ 每个环节推荐 1–2 个，并说明理由 → 2–3 套组合（极简、均衡、追求惊艳）→ 被高估或不推荐的工具，以及原因 → 来源列表
```

### ⑤ 质量闭环

```text
【这次调研】让 agent 看到、评审、验证自己做的页面：质量闭环和评测

请回答：
1. 视觉反馈闭环：agent 写完页面后自己截图检查、对照参考图迭代，有哪些做法（截图工具、多种屏幕尺寸、暗色模式、改前改后对比）？公开实践的效果怎么样？多模态模型看截图的能力到哪为止，对齐、间距、字重、颜色细微差别这类细节能不能看出来？
2. 设计评审清单：整理成熟、能直接操作的 UI 评审标准（如 Nielsen 可用性启发式、Refactoring UI、Vercel Web Interface Guidelines、WCAG 对比度和可访问性要求、排版检查项），合成一份分层清单：必须过的项、体现品质的项、体现惊艳的项。
3. 哪些设计问题可以用代码稳定地检查出来（对比度、design token 以外的颜色和间距值、字号阶梯、文字溢出、布局偏移、性能）？有哪些现成工具？
4. 用 LLM 或多模态模型做设计评审：有哪些相关研究和工具？线索如下，请核实：UICrit、Design2Code、WebGen-Bench、WebDev Arena、Design Arena。这种评审靠不靠得住？和人类设计师的判断一致程度如何？评审 prompt 怎么写，能减少偏差？
5. 各个模型做页面设计的表现：根据公开排行榜和实测，2026 年哪些模型更强？差别体现在哪？注明数据日期。

这次不用讲：功能测试、后端测试。

【交付结构】
闭环流程图 → 分层评审清单（能直接复制给 agent 用）→ 自动化检查工具表 → 用模型做设计评审的研究结论，加能直接用的评审 prompt 示例 → 模型对比（带日期）→ 来源列表
```

### ⑥ 惊艳手法

```text
【这次调研】让页面令人眼前一亮的手法，以及怎么让 AI 稳定做出来

请回答：
1. 2025–2026 年获奖或在设计社区广泛传播的网站（Awwwards 每日最佳和年度最佳、FWA、CSS Design Awards、Godly 精选等），惊艳感主要来自哪些手法？请归类：排版（超大字、可变字体、杂志式排版）、版式（不对称、打破网格）、动效（滚动叙事、页面转场、微交互、弹簧物理）、3D 和 WebGL / 着色器、生成式视觉、光标交互、声音、内容叙事等。每类给 2–3 个网站，说明用了什么手法。如果有中文网站的好例子，也请收进来。
2. 每类手法用什么技术实现，门槛多高（GSAP / ScrollTrigger、Motion、Lenis、Three.js / React Three Fiber、着色器、View Transitions API、CSS 滚动驱动动画等）？哪些 AI coding agent 写得稳？哪些经常写坏，坏在哪？
3. 克制：这些手法在性能、可访问性（prefers-reduced-motion）、移动端上分别有什么代价？顶尖设计师怎么把一个页面的记忆点控制在一两个？工具页、文档、作品集、活动页各适合做到多惊艳？
4. 动效设计原则：时长、缓动曲线、编排，以及动效要表达什么意思。参考 Emil Kowalski、Rauno Freiberg 等 design engineer 的公开文章，以及 Material、Apple 的动效规范，整理成能直接写进给 agent 的指令里的规则。
5. 有没有人公开分享过用 AI agent 做出获奖级或广泛传播的网站的完整过程？他们怎么分工？

这次不用讲：组件库罗列（已调研过）。

【交付结构】
手法总表（手法 × 网站例子 × 实现技术 × AI 实现时的常见问题 × 代价）→ 动效规则清单 → 不同类型页面该做到多惊艳的建议 → 让 AI 实现这些手法的 prompt 示例 → 案例 → 来源列表
```

### ⑦ 案例拆解

```text
【这次调研】高手用 AI 做出高质量页面的真实案例拆解

请回答：
1. 找 8–12 个公开、过程能查到的案例：设计师、design engineer 或独立开发者用 AI（Claude Code、Cursor、Codex、v0、Lovable 等）做出公认高质量的网页或产品界面，并且公开了过程（博客、推文串、视频、直播、GitHub 仓库，或 Figma Config、Vercel Ship 等会议演讲）。优先选有改前改后对比、有 prompt 原文或对话记录的。
2. 每个案例拆解这几点：做的是什么；用了哪些工具；人负责什么，AI 负责什么；关键 prompt 或指令原文；迭代了几轮；卡在哪，怎么解决的；成品的公开评价。
3. 放在一起看：这些案例有什么共同做法？和普通人用 AI 做出平庸页面相比，差别出在流程的哪几个节点？
4. 反面案例：公开复盘失败、吐槽 AI 设计翻车的例子，失败原因是什么？

【交付结构】
案例总表 → 逐个拆解 → 共同做法（按工作流节点归纳）→ 反面教训 → 值得借鉴的 prompt 和做法摘录（附原文链接）→ 来源列表
```
