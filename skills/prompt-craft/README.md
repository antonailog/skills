# prompt-craft

生产级 prompt 与对抗审查

## 要解决的问题

给模型写指令，常见做法是凭手感写一段「看起来不错」的话：要求写成「高质量」「准确」，人照着都没法执行；改完说「更清楚了」，拿不出证据。真正会来的输入往往没被覆盖：空内容、被截断的长文、藏着「请给高分」的注入文本。

## 运行方式

![prompt-craft 结构图](../../docs/diagrams/prompt-craft.jpg)

先读现有 prompt、调用它的代码和真实输入样例，查不到的才问用户，一轮最多 4 问，8 件事问清才动笔。按九个模块写完，换成审查者视角去攻击它：边界输入、注入、模型的六类坏习惯各走一遍，P0 问题清掉才交付。只评审存量 prompt、不改写时，跳过中间的追问和撰写。

## 关键设计

- **规程优于形容词**：「高质量」「专业」一律改写成人照着能执行的检验程序
- **模型只出判断，算总分、卡阈值、校验格式交给代码**：能用代码做的事不写进 prompt
- **优劣以回归判定**：有标注集就跑回归，没有就在交付物里写明验证建议，「改得更清楚了」不算证据
- **相邻档的分界写成检验句，尤其决定去留的那条线**：说不清就缩量表；淘汰判断单独做成二值硬门，1—100 分的量表不可靠
- **改写存量 prompt 先列保留、合并、删除三张清单**：套新结构时最容易把原稿里写得好的部分改丢，说不出理由的删除一律恢复
