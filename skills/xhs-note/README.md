# xhs-note

写小红书笔记，含封面

## 要解决的问题

让 AI 写小红书笔记，写出来的常常是推广文案的腔调，「彻底改变」「吊打」随手就来。读者是同行，看得出吹牛，稿子要像一个做工具的人在交换经验。笔记还分体裁，工具分享帖和感悟帖的节奏几乎相反，拿错了节奏，写几版都用不上。编进去的经历和数字一旦发出去，就收不回来。

## 运行方式

![xhs-note 结构图](../../docs/diagrams/xhs-note.jpg)

开工先分体裁，看不出是工具帖还是感悟帖就问用户。起草时先读同体裁的范文、再用声纹文件对一遍声音，规则清单留到写完才跑：四层终审里第一层事实审计不过，后面三层不用跑。封面和标签都先问要不要；发布后对比用户手改过的稿子，能在旧笔记里验证的规律才回写声纹文件，库里没有的场景就把成稿收进范文。

## 关键设计

一篇小红书笔记要同时做到：读起来像用户本人在跟同行交换经验，写进去的经历和数字都真实。xhs-note 把材料分成三类分开存放：范文给手感，声纹文件对声音，终审门挑错；封面另有一份先定方向再生图的说明。

- **范文优先，规则只做终审**：范文以完整的已发布笔记存放，附体裁、标题、配图和发布链接，比如工具帖的 `2026-08-01-forge-bugfix.md`；`references/redlines.md` 开头写明成稿后才跑。`references/voice.md` 和范文冲突时，以范文为准。
- **先分体裁，两种节奏各读各的范文**：工具分享帖短段落、编号清单为主体、收尾求互动；感悟帖一条感悟一整段，没有清单，结尾只写来源一行。`references/voice.md` 的硬手迹里，只对工具帖成立的几条都标了出来。
- **只写用户真经历过的事**：终审第一层是事实审计：逐句列出素材之外的场景、对话、数字、时间，换成素材里的细节、标占位，或改成诚实的模糊说法（`references/redlines.md`）。想引用播客、文章里别人的案例和数字，先问用户。
- **红线管能不能发，声纹管像不像**：`SKILL.md` 的红线只有三条：只写真实经历、效果用平实的词、不用平台限流词，都是发出去就收不回来的。零 emoji、句号规则这类风格约定放在 `references/voice.md`。
- **声纹只收验证过的手迹**：`references/voice.md` 的硬手迹用范文里的原句举例；只在一篇范文里见过的写法放进「还在观察」一节，不拿来判合格。回写声纹时先做减法。

```text
xhs-note/
├── SKILL.md                                 分体裁、起草、终审、封面、标签、归档
├── references/
│   ├── voice.md                             声纹：人称、硬手迹、标题、不会说的话
│   ├── redlines.md                          终审门：四层检查加回滚检查
│   ├── cover-image.md                       封面：出方向、写生图指令、调 Codex
│   └── examples/                            范文：用户已发布的笔记
│       ├── 2026-08-01-forge-bugfix.md       工具帖范文：短版
│       ├── 2026-08-02-forge-fupan.md        工具帖范文：配图多的长版
│       └── 2026-08-03-podcast-chenmian.md   感悟帖范文：听播客的感悟
└── examples/
    └── sunzi-mindmap-note/                  例子：让 AI 把《孙子兵法》读成导图
```

## 其他

- 前提：封面交给本机 Codex CLI 内置的生图，单张十分钟上下，放后台跑
- 注意：范文和声纹（`voice.md`）取自用户自己的笔记，换人用要换成自己的范文，缺范文这套方法就失效
- 注意：`references/cover-image.md` 里调 Codex 的命令写死了代理端口和 Codex 二进制的查找方式，换机器先改这两处
- 注意：已有流量的笔记改标签容易被限流，标签在发布时一次定好
