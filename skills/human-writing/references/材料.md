# 材料

第二步找材料时读前三节，第四步问作者时读最后一节。这一步只收集事实，不定主线，也不排轻重。

## 带着问题找

- **按 `材料笔记.md` 开头的问题去找材料。** 读者读这篇文章会问什么，就去找能回答这些问题的材料。不用通读整个项目目录，一份文档读到答案就往下走，长文件先搜关键词，再读前后几行。

## 去哪里找

- **先读项目自己的文件。** 从 `project.md`、`README.md` 这类总说明读起，再看文档和页面，读到能说清读者用起来是什么样为止。同一件事前后改过的，以最新的为准。
- **打开网站看它今天真实的样子。** 记下一两个今天能看到的例子和日期。遇到前端渲染、直接抓取看不到的页面，用 Playwright 在后台开无头浏览器看，不碰作者的屏幕。
- **写别人做的东西、新闻和活动，先找一手材料。** 官方原文、正式公告、论文、代码仓库、当事人完整的访谈，都以这些为准；媒体报道和别人的解读只用来补背景、对照着核对。不同来源互相冲突时，不挑最合适的那条写死，把两种说法和各自的出处都记下来。
- **现成的截图和录屏都要打开看。** 截图直接打开看，录屏先抽几帧拼成一张图看，`ffmpeg -i 视频 -vf "fps=6/时长,scale=640:-2,tile=3x2" -frames:v 1 抽帧.jpg`。看三件事，画面里有没有没公开过的邮箱、手机号、私信和真人照片，是不是和现在对不上的旧版本，要演示的效果录到没有。

## `材料笔记.md` 记什么

- **开头三五行写读者会问的几个问题。** 这几行在第一步写好。
- **接着用十行左右记三样东西。** 一是「不能写的」，记清在哪里、具体是什么；二是拿不准的事，记下前后矛盾的说法和查不到的事实；三是要问作者的事，把资料撑不起来的地方写成他一两句话就能答上的问题，比如「你自己现在每天早上还看订单吗，一般几点看？」。
- **最后记下用到的几个关键文件和网址。** 写的时候要补细节、改稿时要核对事实，都回这些原文去看。读到的事实留在你的上下文里，不抄进笔记。

## 问作者（第四步）

- **整个流程只在这里停下来等他，要问的事一次问完。** SKILL.md 第四步那几样缺什么就问什么，加上 `材料笔记.md` 里要问他的事，最后问一句有没有一定要放的、一定不写的。问的时候先不交稿，别先交一篇空稿再等他往里补，他想加的东西才有地方放。每一篇都重新问。
- **问他做过的、看到的和他的判断。** 他为什么做这件东西、自己平时怎么用、现在怎么看，项目文档里很少有，只有他知道。
- **材料撑不起篇幅，也告诉他。** 说清缺的是哪一段，请他补一两句；他补不上，文章就写短。
- **查不清、又不影响文章重心的小事，自己定。** 比如一个每天在变的数字用哪天的，按材料里最稳妥的说法写，交稿时告诉他。

问的时候像这样发给他，每一问一两句话就能答上：

```
写之前想问你几件事，一两句就够，口语和错别字都没关系：

1. 你和这件事实际发生过什么？……（带一两个材料里的具体例子）
2. 哪个瞬间、数字或者一句话最让你在意？
3. 你现在最想说的判断是什么？
4. ……（材料里查不到、只有你知道的事）
5. 这篇我打算让读者读完知道……，你觉得对吗？
6. 有没有一定要放的、一定不写的？
```
