# 图：什么时候画、参考什么、怎么出、怎么验

## 什么时候画

判断标准只有一条：读者要对这段信息做什么。要比较、看形状、看结构、顺着路径走，图比文字快；要跟着推理走，文字比图准。

| 内容里的关系 | 文字表达的困难 | 图型 | 图上必须看得见 |
|---|---|---|---|
| 数量、趋势、占比 | 一串数字看不出形状 | 条形比大小、折线看趋势、组成图看占比 | 单位、时点、分母、来源 |
| 原因、条件、影响 | 多因一果、链条、反馈用句子要绕 | 因果链、分支判断、闭环 | 中间机制、方向、条件、不确定性 |
| 先后、循环、分支 | 步骤多了读者记不住在第几步 | 流程图、泳道图 | 输入、动作、判断条件、结果、失败出口 |
| 层级、组成、职责 | 谁属于谁靠缩进说不清 | 层级图、分层图 | 归属；不用上下级伪装因果 |
| 多方观点、多个方案 | 各说各的看不出差在哪 | 对照、取舍矩阵 | 主张、前提、证据、代价；不评胜负 |
| 多项约束共同作用 | 条件散在几段里 | 条件汇合图 | 每项限制、同一适用地区与对象 |
| 经历、认识变化 | 事件和认识交织 | 时间线 | 事件与认识分开，转折原因 |
| 整期结构（骨架图） | 需要一眼看到全貌 | 层级图、框架图 | 节点是正文单元标题原句 |
| 整期实质内容（总结图） | 要一张图带走全期 | 按章分模块的信息图 | 每章的判断、关键数字、关系、边界 |

有上表里的关系就画；拿不准时画，事后补图比删图难。只有定义和单句结论的内容不画。发布方已给的图不重画，只补图注。同一关系对应几种图型时，看「必须看得见」那列哪种放得下。

图文分工：图承担关系和形状，文字保留数字、条件、归属，让内容可搜索、可引用。文字独立成立，用户删掉图不丢机制，但不逐句复述图里已画出的关系。表格和图是两种视觉：离散值的多维比较用表格，看形状和趋势用图；三组以内的数字写进句子。

粒度：一个单元最多一张主图；跨单元的关系进骨架图或总结图；关键内容不放图。

总结图的画法（用户认可的「编辑式信息图」风格）：顶部标题加一句主张，下面一条章节路线条；每章一个编号模块，模块标题是判断句，模块内用大数字卡放关键数值（数字 30 到 36 号、说明 18 号）、用对照卡放分歧、用小流程放链条，边界用灰字小注；深色卡放结论、浅色卡放依据、强调色只给一两处差异；末尾一行行动清单。宽 1600，高随内容，通常 3,000 到 4,500。图上每个数字和判断先在正文里有，再上图。

## 参考什么画

| 图的哪一部分 | 从哪里来 | 为什么 |
|---|---|---|
| 内容：判断、机制、数字、条件 | 已写好的正文单元，不从转写另起炉灶 | 图和文字出自同一份理解才不打架；画完反查图中数字、归属、条件与正文一致 |
| 原始数据 | 原始资料附件里的原数值和口径 | 图上数字能回到材料；不同口径先解释差异再决定能否画在一张图里 |
| 发布方原图 | 原样嵌入或忠实重绘 | 它是证据；重绘只为可编辑或并进骨架，不改关系和数值 |
| 图型 | 上面的关系表 | 先定关系再选图型，避免先想好要画什么再凑内容 |
| 骨架图节点 | 正文单元标题原句 | 与正文逐句对账 |
| 样式 | 下面的视觉参数 | 全篇的图是一套 |

每张图一句图注说明看什么。没有精确数据的关系用带标签的示意形状，不造比例、曲线和坐标。箭头要能读成「需要、下一步、影响、取决于」之一，读不出关系的箭头删掉。只有同属一个对象、地区和时期的限制才汇合，不同城市的举例分开列。

## 输入里的图

| 类型 | 例子 | 处理 |
|---|---|---|
| 证据图 | 嘉宾供图的数据图、截图 | 原样嵌在它支撑的判断旁，加图注；不重绘 |
| 结构图 | 发布方画的框架、流程 | 要改、要标注、要并进骨架时重绘成可编辑图；否则原样留 |
| 装饰图 | 封面、公告、表情 | 不进正文，留在播客信息的 Shownotes 里 |

保留的图过一遍文字提取，图里的数字和术语才能被搜到、被引用。保存图片 URL 与本地文件映射，核对不是封面误配或相邻文章的图。图片获取失败就报告是哪张，不画一张猜测图冒充。

## 怎么出：一份 SVG 真源，载体决定渲染

图的类型不决定工具。数据图、因果图、流程图、骨架图都先写成 SVG 真源，再按载体渲染：飞书转原生画板节点，文字、形状、连线可编辑；Markdown 直接内嵌 SVG，预览不渲染时另出 PNG。内容改动只改真源。数据图由脚本从数据生成 SVG，画板里只调样式，改数据回脚本重出。生图模型不画任何带数字或带知识结构的图。

### 出图规范与渲染库

所有图按下面四步出。约束来自维护者的《出图规范》，执行要用到的部分都已写在本文件和 `_shared/figkit/README.md` 里：

1. **写图稿**：从正文单元抽，填 task、type、title、items（文本、数字、单位、口径）、relations、notes、source（字段见 `_shared/figkit/README.md`）；图上每个数字先在正文里有。图稿放工作区 `figs/图稿-<名>.json`。
2. **选主题**：默认 Editorial Forest；用户点名 beautiful-feishu-whiteboard 里的主题时换（已录入 grove、avocado-press、long-table、monochrome，色值原样取自该仓库 templates/<slug>/design.md）。主题只定画布、四种面（base／strong／accent／plain）和跟随面的文字色；每个模块最多一张 strong、一张 accent，其余 base。用户说配色不好看又没给参照时，不自造新方案：把同一张图稿用全部已录入主题各渲染一张并排给他挑；他给了参照图或仓库，就把参照原样录入成新主题再渲染。
3. **渲染并校验**：`scripts/make_figure.sh 图稿.json 输出.svg [主题]`。它调 `../_shared/figkit/figkit.py` 出 SVG，再跑 `check_figure.py --wb`：最小字号 16、卡内行长 30 字、只用主题颜色、strong／accent 用量、文字超出所在形状、数字被拆到两行、画板转换的文字溢出。不过不进下一步。已有模板：信息图（总结图）、层级图（骨架图，一章超过 3 个单元自动分行）、条件汇合、流程图（`branch_link: false` 时分支行变成不连线的「对照」行，适合「现状流程 vs 我们的做法」）、组成条、柱状图。
4. **转画板并看**：按下面「转飞书画板」写入，导出云端预览逐区看；箭头用 `marker-end` 原生连接器，不手画箭头。

下面的视觉参数与 figkit 模板一致。

### 视觉参数

画布宽固定 1600，飞书按正文宽度整体缩放，画布字号不等于阅读字号。

| 项 | 取值 |
|---|---|
| 画布 | 宽 1600；高由内容定，内容底加 60；宽高比 1:1 到 3:2 是紧凑度自查指标 |
| 页边距 | 四边 60 |
| 字号 | 板标题 30 粗；副标题与底注 18 灰；模块标题 24 粗；模块判断句 20 粗；正文 20；要点与注释 18 |
| 行高 | 模块标题 34；正文 32；要点 28 |
| 卡片 | 圆角 12、描边 1.5；高度贴合内容：22 加各行行高之和加 22，上下内边距相等；左右内边距 24 |
| 间距 | 相邻卡片水平 40、垂直 48；分区之间 56 到 64 |
| 密度 | 内容占画布 75% 以上；一行中文不超过 30 字；放不下时删次要句或改横排，不缩字号、不拉高画布 |
| 连线 | 正交折线，描边 2.5；箭头用 `line`／`polyline` 加 `marker-end`，画板转原生连接器（实测）；标签 18 灰 |
| 技术 | 字体 Noto Sans SC；文字只用 `<text>`；不用 filter、pattern、clipPath、mask、gradient、polygon；`<defs>` 里只放箭头 marker |

留白指模块之间有一道缝，不是把画布撑大让内容稀疏地漂着。配色由主题定（见上）：base 面做默认卡，strong 面只给结论卡、路线当前项、流程末步，accent 面只给分歧或唯一最该记的数字；每模块各最多一张。数据系列按主题 data 顺序取，最多四个。

### SVG 文本预折行

画板会按文本框宽度重排文字，所以 SVG 里每行文字自己预先折好，一行一个 `<text>`。折行按词不按字：数字、百分比、英文串是一个整体（「2,000」「76.69%」不能拆成两行），标点不落行首。实测用按字折行时，三处数字被拆成「2,00／0」「76.6／9%」，本地渲染看不出，云端预览才暴露。折行宽度按「中文 1.0、其他 0.6」乘字号估算后再留 30 到 40 的余量。

### 转飞书画板

先读当前 `lark-cli skills read lark-whiteboard` 及其引用，用当前支持的转换和写入接口，不凭猜测构造，也不把一张大图片放到画板上宣称可编辑。写入的实测硬约束：

- 幂等 token 每次唯一（固定值会被当重复请求静默吞掉，返回 ok 但内容不变）。
- z_index 显式按节点顺序给，背景为 0，否则背景会压在文字上整板空白。
- 文本框按飞书字宽放宽：宽度取「中文 1.0、其他 0.65」乘字号乘 1.08 再加 10；放宽后居中文字中心减半个增量、右对齐减整个增量，否则看起来没居中。右对齐文本离容器边缘留 100 以上。
- 写完等十几秒再导出核验；页面显示异常先硬刷新，以服务端导出为准，不据页面缓存改图。
- 文档创建时用 `<whiteboard type="svg" path="@文件.svg">` 可一次建板，之后仍按下面的流程用 openapi 转换加放宽重写一遍；`@文件` 和 `--source @文件`、`--output` 都只收相对当前目录的路径，绝对路径静默失败。
- raw 写入可能是追加，先核对语义；重制走「回读旧板和用户手改 → 合并到真源 → 新空板一次幂等写入 → 回读、预览、实机验证 → 替换旧块」。

### 文字溢出

SVG 正常但飞书越框，常见原因是目标字体字重宽度不同，原生文本框额外折行而背景固定高度。处理顺序：用目标字号字重测文字宽，先定语义换行再定容器；给文本框留可校准余量；容器随行数增长、相邻模块让位；修一处后看所有同类框和相邻节点；把修复同步回真源或几何补丁，重新生成不复发。

## 四层验收

| 层 | 证明什么 | 不能替代什么 |
|---|---|---|
| 本地 SVG/PNG 与测量 | 内容、容器布局、本地字形 | 飞书字体与换行 |
| 原生回读 | 节点内容、几何、样式、连接完整 | 字形没有越界 |
| 飞书服务端预览 | 转换结果大致布局 | 高倍率下所有细节 |
| 真实浏览器 | 读者看到的、可编辑、重开正常 | 来源真实性与用户喜好 |

浏览器先整体看结构，再按可阅读比例逐区检查全部文字，重点看窄框、长句、数字单位、末行和页底；选一个文本节点进入编辑再退出重开；操作后回读确认没有误拖。无法实机检查就记为未验证，保留已完成的本地产物与原生回读。
