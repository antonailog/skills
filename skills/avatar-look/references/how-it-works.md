# 原理、调参与走过的弯路

用户问「怎么做的」、要调手感、或者想换实现方式时读这份。

## 一句话

不是真 3D：AI 生成一段头绕一圈的视频，MediaPipe 量出每一帧头朝哪，网页把鼠标方向换算成视频里的帧，用 seeked 串联一帧帧跳过去。

## 链路与关键词

| 环节 | 做什么 | 关键词 |
|---|---|---|
| 生图 | 照片 / 想法 → 3D 卡通半身像 | 图生图、3D 卡通渲染 |
| 生视频 | 首尾帧都用这张图，头绕一圈 | 图生视频（I2V）、首尾帧、固定机位 |
| 裁切编码 | 按全片人脸中位数裁方块，压成每帧都是关键帧的 H.264 | ffmpeg、all-intra、GOP=1（`-g 1`）、faststart |
| 量朝向 | 鼻尖相对脸部轮廓中心的偏移 ≈ 头朝哪 | MediaPipe Face Mesh、head pose 近似 |
| 剔眨眼 | 眼睑开合度比前后 6 帧中位数低 15% 以上，且短促（≤ 5 帧）、头没明显朝下 | EAR（eye aspect ratio） |
| 时间轴 | 转幅到位后的帧按顺序排开，方向角平滑后强制单调；转超过一圈时裁成正好一圈，接缝挑首尾画面最像的裁法；首尾没闭合（缺几帧的角度）时用双向光流补帧，补的帧接在视频末尾 | atan2、单调化、分段线性插值、环形（wrap-around） |
| 跟随 | 鼠标相对头像中心的角度 → 时间轴目标位置，播放头按最短路径追 | 指数平滑（时间常数）、限速、requestAnimationFrame |
| 出画面 | 每走到新的一帧就设 `currentTime`；没跳完时只记最新目标，等 `seeked` 再跳 | HTMLMediaElement、seeked 串联 |

全关键帧的原因：普通视频隔几十帧才有一个完整帧，跳到中间某帧要从上一个关键帧解码过来，所以慢；每帧都是关键帧后跳哪都只解一帧，体积大一点（480px、5 秒约 900KB）。

## 先分清是哪种卡

用户说「卡」「不顺」「效果差」时，先让他三选一，再动手：

| 用户看到的 | 多半是 | 先查什么 |
|---|---|---|
| 画面一下一下跳，像翻幻灯片 | 相邻两次画面跨了很多帧 | `verify.py` 的 `frame_step_median / max`（应为 1–3）；选帧是不是沿时间轴连续走 |
| 转到某个方向时头突然多扫一段再弹回来 | 视频多转了一段没裁，同一方向在时间轴上出现两次 | `report.json` 的 `trimmed` 是否为空、`gap_deg` 是否为负；`verify.py` 的 `slow_step_max`（应 ≤ 3） |
| 鼠标停了头才慢慢转过去 | 追随太沉 | `TAU_MS`、`MAX_SPEED`（见下表） |
| 快速转头时发虚、有重影或停住不动 | 跳转跟不上 | 视频是不是全关键帧（`-g 1`）；跳转有没有用 seeked 串联；`seeks_per_sec` 是否 ≥ 20 |

10-16 第一版被说「卡顿」时没先问是哪种，按猜测改了一轮；体感反馈只给形容词是反复出现的问题，问清维度比多试一版便宜。

## 手感参数（`avatar-look.js` 开头）

| 参数 | 默认 | 用户说… | 怎么调 |
|---|---|---|---|
| `TAU_MS` | 90 | 太飘、太慢、跟不上 | 调小（60–70） |
| | | 太生硬、一下就甩过去 | 调大（120–150） |
| `MAX_SPEED` | 170 | 甩鼠标时转得太猛 | 调小（110–130） |
| `IDLE_MS` | 1500 | 鼠标一离开就回正脸太快 / 太慢 | 按秒数改 |
| `STILL_MS` | 5000 | 鼠标停着不动时回正脸太快 / 太慢；不想要这个行为 | 按秒数改；0 = 停着也一直看鼠标（10-21 用户要的：停 5 秒回正，像转回来看访客） |
| `WAKE_PX` | 10 | 回正后手一碰鼠标就转走 / 挪了半天才跟过去 | 调大 / 调小 |
| `FACE_FADE_MS` | 260 | 正脸和视频切换有闪 | 调大 |

另有两个写死的：鼠标离头像中心不到头像宽度 30% 时保持上一次方向（方向不稳）；首尾之间视频没拍到的那段，处理脚本超过两帧角度就用光流补帧（`report.json` 的 `seam_fill`，10-21 起），没补的小缺口过中点直接切首尾帧。

## 走过的弯路（别再走）

| 做法 | 结果 |
|---|---|
| Three.js / 图片转 3D 模型 | 长相、质感都掉；眼睛画在贴图上，转不了眼珠 |
| 只做左右转头的视频 | 头像换位置后鼠标会在上方、下方，必须上下左右都有 |
| LivePortrait 生成眼神网格图 | 用户要的是头、颈、眼一起动，不是只动眼珠 |
| 按「姿态最接近」直接挑帧 | 挑中的帧在时间上不相邻，转起来一顿一顿 |
| 帧图 + 相邻帧混合 | 理论更平滑，并排对比时用户觉得不如视频，推测是快速转头时混合帧有重影 |
| 分段生成关键帧再拼 | 用户嫌麻烦；一张图 + 一段视频够用 |
| 眨眼只看眼皮开合 | 10-20 发现：低头往下看时眼皮连续几帧下垂，被当成眨眼剔掉，正下方画面没了、绕圈跳 5 帧，用户的感受是「转到下方不往下看」。现在只剔短促且头没朝下的 |
| 视频多转的部分直接留着 | 10-20 发现：多转 76° 时，鼠标越过起点头会先抢跑到前面再切回来，慢转一次跳 5—8 帧；快速画圈测不出来。处理脚本已自动裁成一圈，验收加了慢转一圈 |

## 已知限制

- 转动幅度只跟方向走，不随鼠标远近变化（视频里只有一圈固定幅度）
- 只在 Chrome 实测过；Safari 没测，交付时要说
- 视频模型偶尔眨眼、硬物变形，脚本只能剔眨眼帧，变形要重新生成
