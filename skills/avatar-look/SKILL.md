# avatar-look — 会看向鼠标的 3D 头像

交付一个组件目录：头绕一圈的视频素材、正脸图、朝向数据、组件脚本、演示页，外加三行接入代码。放在页面哪里、显示多大，头都会转向鼠标所在的方向。

## 定位与边界

像一个做过这件事、踩过坑的动效工程师朋友：把「哪一步要你动手、动手时怎么填、生成完怎么挑」讲透，其余的机械活全包，最后交一个三行就能接入的组件。

用户要的是「页面上一个顺滑地看向鼠标的头像」，真 3D 不是目标。所以一切围绕「一段头绕一圈的视频 + 连续时间轴 + seek」组织。下面这些都是实测过、用户否掉的路线，除非用户主动问，不再提出：Three.js 或图片转 3D 模型（长相走样、眼珠转不了）、帧图混合（快速转头有重影）、按姿态直接挑帧（一顿一顿）、眼神网格图（只动眼珠）、分段生成关键帧（太麻烦）。

「360°」指看向屏幕平面上任意方向，头、颈、眼一起动；不是头转一整圈看到后脑勺，也不是只有眼珠动。

一次只做一个形象。边界之外的交出去：只要静态头像图，直接用 codex image_gen 出；视频剪辑压缩，直接用 ffmpeg；通用鼠标动效、滚动序列帧动画，交给 impeccable；页面整体设计，交给 forge-design。

## 从哪一步进入

先看用户手上有什么，从对应的步骤开始，前面的跳过：

| 手上有 | 从 |
|---|---|
| 照片或文字想法 | 第 1 步 |
| 现成的 3D 头像图（正脸、纯色背景） | 第 2 步 |
| 现成的绕圈视频 | 第 3 步 |
| 已有组件，嫌卡、飘、慢 | 先请用户三选一说清是哪种：画面一跳一跳 / 跟手慢 / 快速转头发虚。「卡」至少有这三种，修法完全不同，猜错就要多返工一轮。再按 how-it-works.md 的「先分清是哪种卡」对症改 |

只说「想要会看鼠标的头像」、什么都没给：用一段话讲清 5 步，以及哪两步要他自己动手，然后问他给照片还是给想法。在聊页面首屏、问头像能不能动：先一句话说能做成看向鼠标的 3D 头像，再问要不要做。

再问一件事：**产出目录放哪**。用户指定位置；没指定就问，不要自己挑一个放进别人正在改的页面目录。

## 依赖

ffmpeg、uv（脚本用 uv 起 Python 3.12 临时环境装 mediapipe）、playwright + 本机 Chrome（验收用）。开工前 `which ffmpeg uv` 看一眼。mediapipe 下载失败多半是网络问题，按本机代理设置重试；两次不通就停下，把报错告诉用户，不要改用户的环境配置。

## 第 1 步 出 3D 头像图

读 `references/prompts.md` 第 1 节。照片给了就用照片版提示词，否则用想法版。

默认 agent 用 codex image_gen 出图（Claude Code 里按全局 CLAUDE.md 的生图规则调 codex；宿主是 Codex 就直接用 image_gen）。出完把图给用户看，对照挑选标准确认：正脸、居中、身体正对、纯色背景、头顶留白、特征和照片一致。

codex 失败两次，或用户不满意、想自己出：按人工环节的骨架给他提示词和指引（见「输出」），等他发回图片路径。

## 第 2 步 用户生成视频

这一步只能用户去即梦操作。读 `references/prompts.md` 第 2 节，按人工环节骨架给出：即梦首尾帧设置、主版提示词、两个备选、挑选标准、做完回什么。提示词里的配饰按形象改（没帽子眼镜就换掉或删掉那半句），其余不动——每一句都对应一个踩过的坑，表格在同一节。

## 第 3 步 处理视频

```bash
uv run --no-project --python 3.12 --with "mediapipe==0.10.14" --with "opencv-python<4.11" --with "numpy<2" \
    python <本 skill 目录>/scripts/process_video.py <视频> --out <产出目录>
```

它自动按人脸裁方形，输出 `avatar.mp4`（全关键帧）、`poster.webp`、`poses.js`、`check.png`、`report.json`，并自检。视频转了不止一圈时会自动裁成正好一圈（报告里的 `trimmed`）：不裁的话同一方向在时间轴上出现两次，转到接缝头会抢跑一段再切回来。`smoothness` 是沿一圈相邻帧的画面差，中位数为 1，接缝和最大值在 2 左右正常；某处远超 2.5 会列进 problems：

- 退出码 0：打开 `check.png`（九宫格，8 个方向 + 正脸）自己先看方向对不对，再给用户看
- 退出码 2：视频不合格（没转满一圈、识别率低、幅度太小）。把原因翻译成挑选标准里的哪一条没过，带上备选提示词，回第 2 步
- 裁切不理想（帽子被切、人偏）：用 `--crop W:H:X:Y` 手动指定重跑

打印出来的眨眼帧号对照视频确认一下：剔掉的帧不进时间轴，真眨眼剔掉没影响；剔的若是往下看的帧（眼皮下垂），正下方的画面就没了，绕圈还会跳，`smoothness.jumps` 会报出来。

## 第 4 步 产出组件

把 `assets/avatar-look.js` 和 `assets/demo.html` 复制进产出目录。组件以 skill 的 assets 为真源，不要在产出目录里改出分叉版本；要改行为就改 assets 再重新复制。

用户点名了页面才接入，接入三行：

```html
<div class="avatar" data-avatar-look><img src="<产出目录>/poster.webp" alt=""></div>
<script src="<产出目录>/poses.js"></script>
<script src="<产出目录>/avatar-look.js"></script>
```

- 容器要有宽高、`overflow: hidden`；圆形、边框写在容器上。组件在里面叠一层静音视频，`<img>` 是正脸占位
- 容器是 JS 渲染出来的：渲染完调 `AvatarLook.scan()`
- 页面原来的头像图换成 `AvatarLook.poster`，组件没加载时可以退回原图
- 路径按页面相对产出目录的位置写

## 第 5 步 验收

```bash
python3 <本 skill 目录>/scripts/verify.py <产出目录>/demo.html
```

它开 Chrome 测 8 个方向是否在 ±45° 内、快速画圈时每秒跳转次数、慢转一圈时头有没有一路跟住鼠标（`slow_track_err_max` 偏差、`slow_reverse` 倒退、`slow_step_max` 单步帧数）、控制台报错。接入了页面的话，再对那个页面截一张图看头像框里的样子。

自动测试只证明能用，顺不顺要人手感判断；Safari 没测就说没测。

## 输出

**人工环节**（第 1 步用户自己出图、第 2 步生视频），每次按这个顺序：

```
1. 去哪做、怎么设置（工具、模式、时长、比例）
2. 提示词（代码块，可直接复制；生视频给主版 + 两个备选）
3. 挑选标准（逐条可判断）
4. 做完回我什么（文件路径）
```

**最终交付**：

```
1. 一句现状：做好了，接到了哪里
2. 三行接入代码
3. 验收数据：报错数、每秒跳转次数、8 个方向是否正确；明说「这是自动测试，手感请你亲手试」，没测的浏览器说没测
4. 产出目录、演示页、check.png 的链接
```

命中才出：脚本自检不过 → 重新生成视频的建议（说清哪条标准没过 + 换哪个备选提示词）；用户嫌卡、飘、慢 → 改了哪个参数、改成多少。

## 红线

1. **生视频这一步不替用户生成，也不假装生成过**。没有视频文件就停在第 2 步等他。编出来的进度会让他以为素材已经有了。
2. **只接入用户点名的页面**。别的会话可能正在改别的页面，改了会冲掉对方的工作。
3. **只处理用户本人或已获授权的形象照片**。生成他人的形象并放上网页，收不回来。

## 失败处理

| 情况 | 怎么办 |
|---|---|
| codex 出图失败两次 | 给提示词让用户自己出 |
| 识别不到人脸（非人类形象） | 告诉用户形象需要有能识别的脸；换更拟人的设计重出第 1 步 |
| 自检退出码 2 | 回第 2 步，说明哪条不合格，换备选提示词 |
| 验收方向错 | 先看 `check.png` 哪格不对；多半是视频某个方向没转到，重生成视频比调参有效 |
| 本机没有 Chrome | 用 Playwright 自带的 Chromium，说明它不支持 H.264，结果不可信 |
