# study-guide — 把没读过的材料写成一篇能学的指南

交付一篇学习指南：主题文件夹里的 `guide.md` 加图片和来源表，构建成符合博客规范的知识页（正文 820、在页面正中），本地可看，用户说「发布」后上线。

## 定位与边界

像一个先把材料全读完、再动笔写综述的同行——材料、用户的原始需求和调研方向只划定范围，叙事主线由你重新梳理：冗余的合并，冲突的回到原始来源裁决，分散的融合到该在的位置，证据不够的自己检索补齐；文中提到的例子、作品、网站、视频，都收齐实物让读者看得到。语气是专业综述，像原始报告那样陈述、有依据。

用户还没读过材料，他要的不是几份材料的缩写拼在一起，而是一条能跟着走、能学会的主线。主要读者是用户自己（先学，可以直接发博客）；要改成公众号这类正式文章时他会另改，交给 human-article。

边界之外的交出去：还没有材料、要先出调研题目，交给 research-with-gpt；要 AI 自己调研、出一份帮他做决定的报告，交给 deep-survey；已经掌握的知识总结成飞书文档，走飞书知识总结的流程；单期播客的复习笔记交给 podcast-summary；书或长文转导图交给 book-to-mindmap；博客首页、文章页本身的改版直接改博客项目。

## 按需读取

| 文件 | 什么时候读 |
|---|---|
| `references/writing.md` | 第 2 步定主线、第 4 步写全文前：写作规范（好的样子和自查），不是格式要求 |
| `references/outline-example.md` | 第 2 步写提纲前，看提纲通常有哪几块 |
| `references/components.md` | 第 2 步想展示方式、第 5 步配图排版时；guide.md 的全部写法在这里 |
| `references/infographic.md` | 第 5 步要画高保真信息图时 |
| `references/publish.md` | 第 6 步构建自检、第 7 步发布、第 8 步维护时 |

脚本在 `scripts/`（下文用 `<skill>` 指本 skill 目录），页面模板在 `assets/guide-app/`。

## 意图分流

| 信号 | 走哪条线 |
|---|---|
| 给了材料（或材料所在文件夹），要整理成文章 / 指南 / 知识页 / 发博客 | 全流程，从第 1 步做 |
| 已有学习指南 + 新材料（「补进去」「更新一下」） | 维护，按 publish.md「维护」 |
| 有材料但只说「帮我看懂」「理一下」，没说要文章 | 做完第 1–2 步的提纲，给一页结论和主线，问要不要做成完整指南 |
| 明说「保留原文」「原文全文」 | 原文模式：writing.md 末节 |
| 在做别的（读报告、research-with-gpt 收卷）时说「太长了」「看不过来」 | 一句话问要不要做成学习指南，不自动开工 |

## 主题文件夹

沿用 research-with-gpt 的结构；不是从它来的，就在工作区的 `知识/调研/<主题>-<YYYY-MM-DD>/` 下新建，材料放进 `2-报告原件/`（视频、网页、PDF 也放这里）。

```
<主题文件夹>/
├── 0-说明.md          材料表、版本记录、线上地址、下一步
├── 2-报告原件/        原始材料，只读
├── 3-报告转写/        inventory.py 转出的文字
├── 原图/              信息图的 PNG 原图（不发布；页面用的是 img/ 里转好的 JPG）
└── <N>-学习指南/      本 skill 的产出，N 从 5 起取空着的编号（0–4 是 research-with-gpt 用的，3 留给报告转写）；已经有学习指南目录就沿用，不改名
    ├── 提纲.md         读者任务、叙事主线、目录、论点池的去向、要补的证据、外部对象、展示设想（第 2 步）
    ├── 核对.md         核到原文的、AI 补的、没找到出处的（给用户和维护看，不上页面）
    ├── guide.md        正文真源
    ├── sources.json    来源表；sites.json（网站、作品、产品）、videos.json 可选
    ├── links/          找回链接的过程文件
    ├── img/            信息图、截图（这里的东西会被发布）
    ├── 自检截图/        page_check 的截图（不放 img/，否则会被带上线）
    ├── app/            页面模板副本
    ├── site/           构建产出（发布用）
    └── index.html      单文件版（本机双击看）
```

## 流程

八步，中间停两次等用户：第 2 步之后、第 6 步之后。

### 1 收料

```bash
python3 -I <skill>/scripts/inventory.py <主题文件夹>
```

扫整个主题文件夹（不只原件目录——材料常被放在根目录，漏收过 4 份），转成文字，打印材料表：每份的类型、字数、链接数、内部引用标记数。转不出来的、视频没字幕的，列给用户，请他换格式或给转写稿。材料表写进 `0-说明.md`。

### 2 定主线 → 第一次停

先读 `0-说明.md` 的真问题和用途、`1-prompt.md` 的背景段（有的话）：用户为什么学、学完拿去做什么、以前踩过什么坑，读者任务从这里来。再把每份材料**读完**（不是扫标题）。

然后先拆、再建（writing.md「主线」一节）：把材料拆成论点池，合并冗余、裁决冲突、融合分散；再从读者任务出发，自己搭一条叙事主线，报告的章节顺序不当骨架。读的时候顺手记下两样东西：证据薄、需要自己检索的地方；文中会提到的外部对象（案例、产品、网站、作品、视频、论文）和读者需要看到它们什么。裁决冲突时，裁决所依赖的那几条这一步就回原网页核实：主线常常跟着裁决走，依据到第 3 步才被推翻，提纲就得重来。

写进 `提纲.md`（outline-example.md 是一份格式示范，块可以增减）。其中最要紧的是用一段话讲清这篇怎么推进：写不出来，多半还在按材料的顺序走。

再挑最能暴露问题的一部分写成样章，用真组件渲染（构建方法见 publish.md），截图。样章里出现的外部对象照第 3 步的做法先收好实物，用户看到的才是读者会看到的样子；其余的核对和收图留到第 3 步。把读者任务、叙事主线、目录、论点池里合并和裁决的要点、外部对象和展示设想，连同样章截图发给用户，**停下等他回**。这一步最值钱：方向错了，后面全文、配图、核对都要返工。

### 3 补证据、收实物

第 2 步核过的裁决依据、样章收过的外部对象不用重做，这一步补齐其余的。

- 材料带内部引用标记、链接丢了（inventory 的「引用标记」> 0）：`extract_cites.py` 备料 → 派子 agent 按材料分批找原链接，写 `links/<材料名>.json`（字段见 merge_sources.py 开头）→ `merge_sources.py` 并进 `sources.json`。网页搜索有额度，一个子 agent 别派太多条，用光了就分批续。
- 正文要用的关键论断（数字、日期、产品功能、原话）对着原网页核一遍。
- 提纲里记下的证据薄的地方，自己联网检索补齐；查到的来源手写进 `sources.json`，同样核一遍。
- 外部对象：登记进 `sites.json`、`videos.json`，跑 `collect_refs.py` 收截图、封面、能嵌的视频；字体、作品这类登记样张页、展示页；首屏是加载动画、要看的部分在下方时，用 `shot` 调（components.md「截图画廊」）。截到的逐张看一眼，和正文说的不是一个东西的删掉重找。关键数据（年份、成绩、价格）要有出处。
- 跑 `fetch_icons.py` 下载来源网站的图标（引用浮窗和来源列表用）；没拿到的页面上显示通用图标，不用补。
- 跑 `check_links.py` 逐个打开正文用到的链接，「确定坏了」的换掉，「需要人工确认」的自己开一次。换链接时，同一份来源只是换了地址：材料引用（`材料名-n`）改 `links/<材料名>.json` 再跑 `merge_sources.py`（直接改 sources.json 会在下次合并时被覆盖），手写的来源直接改 sources.json；换成另一份来源：sources.json 加一个新 id，guide.md 里的 `[[旧 id]]` 改成它。核对结果、没找回的、打不开的写进 `核对.md`，不上页面。

### 4 写全文

按确认过的提纲铺开 guide.md，照 writing.md 的规范写：专业综述的语气，取舍看会不会改变读者的做法，论断和依据写在一起，AI 自己的判断放「我的看法」，页面上不放给核对者看的说明。写的过程中发现主线要调整，就调，在提纲里记一笔。

### 5 配图排版

按展示设想落组件，写法照 components.md。怎么展示，看那一处要读者做什么：比较、感受样子、看动态、照着做，各有合适的组件；抽象原则的对错差别可以画信息图（infographic.md，先出两张样张给用户看风格）。写完整篇再从读者的角度过一遍：读到某个例子、某个产品时能不能一点就看到；哪里要来回对照、一段话讲不清，就补一张图或表，图表里的事实逐条对原文。

### 6 构建自检 → 第二次停

按 publish.md 构建、跑 `page_check.py`（截图放 `自检截图/`），四个宽度全过；自己看截图（字号层级、空框、挤成一字一行的列）。把本地预览地址和截图发给用户，**停下等他看**。他提修改就改完再自检；他说「发布」才进第 7 步。

### 7 发布

按 publish.md：读本机发布配置，只传这一篇的目录，传前传后都和线上比对，上线后在线上地址再跑一次 `page_check.py`，`0-说明.md` 记一笔。没有发布配置就停在本地预览，告诉用户。

### 8 维护

新材料进来、要改版式时按 publish.md「维护」：登记材料 → 并进论点池（合并、裁决、融合）→ 看主线要不要调、哪些部分要改 → 改 → 构建自检 → 用户说「发布」再发 → 记版本。

## 输出

文章的目录由这次的叙事主线决定，没有固定骨架。多数学习指南里有用的组成部分（开头的全局概览和骨架图、前置知识、示范、检查清单、还不确定的、来源列表）见 writing.md「常见的组成部分」，要不要、放哪里看内容。

**交给用户的消息**：第一次停时是提纲要点 + 样章截图；第二次停时是本地预览地址 + 截图 + 一行自检结果；发布后是线上地址。

## 红线

1. **可核对的事实没出处不写**：数字、日期、价格、产品功能、谁说了什么，查不到出处就不进正文；图表里的事实逐条对原文。用户还没读过材料，判断不了真假，编出来的数字他会当真去用。
2. **原始材料只读**：不删、不改 `2-报告原件/`，那可能是唯一一份。
3. **私人信息不上页面**：商业打算、合作者、真人照片、账号不进正文和示范。页面会公开发布。
4. **用户说「发布」之前不上线**，上线只传这一篇的目录。发出去的东西收不回来，整站发布还会把别的会话没上线的改动带出去。

## 出问题时

| 情况 | 怎么办 |
|---|---|
| 材料转不出文字（扫描版 PDF、乱码） | 列出来请用户换格式；不凭文件名猜内容 |
| 视频、播客没有字幕或转写 | 请用户给；不凭标题写 |
| 某部分证据不够 | 自己联网检索补齐；查不到可靠来源的说法不写成定论，放进「还不确定的」或删掉 |
| 网页搜索额度用光 | 分批续；找不到的不写进正文，记进核对.md |
| 生图两次不对 | 不放这张图，文字写完整 |
| 截图截到拦截页、登录墙 | collect_refs.py 会改用页面封面图；都拿不到就只放链接；不伪装浏览器绕过 |
| 构建报错 | 按报出的行号改 guide.md；不改模板去迁就写错的语法 |
| 没有本机发布配置 | 停在本地预览，告诉用户本地版在哪 |
