# study-guide — 把没读过的材料写成一篇能学的指南

这个 skill 帮读者快速了解一个陌生的领域。读者手上有一堆材料，自己还没读过：几份调研报告、几篇论文、几段视频。这个 skill 先把材料全部读完，再重新组织成一篇学习指南：一条能跟着走的主线，配上图表、例子的实物和可以点开核对的来源，最后构建成一个知识页。

## 写给谁、要达成什么

读者是不了解这个领域的人，领域里的行话他不一定懂。读完这篇指南，他应该能说清这个领域的全貌、主线和主要争论，并且知道接下来该深入学哪一块。

主题涉及方法、读者很可能要动手时（比如「怎么做好 X」「X 该怎么选」），指南还要给出方法论：做法和它的依据、拿一个常见场景从头走一遍的示范、判断一个方案对不对的标准。拿不准要不要写方法论，就在第一次停下时问用户。

你的身份是一个先把材料全部读完、再动笔写综述的专家。材料、调研的原始问题和调研方向，划定的是这篇要覆盖的范围；叙事主线由你重新梳理：冗余的合并，冲突的回到原始来源裁决，分散的收拢到该在的位置，证据不够的自己检索补齐。文中提到的例子、作品、网站、视频，都收齐实物，让读者一点就能看到。写得通俗易懂、不缺专业性，陈述有依据。

这些相邻的事交给别的 skill：还没有材料、要先出调研题目，用 research-with-gpt；要 AI 自己调研、出一份帮人做决定的报告，用 deep-survey；单期播客的复习笔记，用 podcast-summary；书或长文转导图，用 book-to-mindmap；改写成公众号文章，用 human-article。

## 流程概览

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 收料 | 把材料都转成能读的文字，列出材料表 | 材料表 |
| 2 定主线 | 读完材料，拆成论点池，重新搭叙事主线，写一章样章 | 提纲、样章截图 → **第一次停** |
| 3 补证据、收实物 | 找回引用链接，核对关键论断，补薄弱的证据，收齐例子的实物 | sources.json、实物素材、核对.md |
| 4 写全文 | 按提纲写完整篇 | guide.md |
| 5 配图排版 | 每一处按读者要做的事选组件，补图表 | 带组件的 guide.md、图片 |
| 6 构建自检 | 构建页面，四个宽度自检 | 本地预览 → **第二次停** |
| 7 发布 | 用户说「发布」后上线 | 线上地址 |
| 8 维护 | 新材料进来时增量更新 | 新版本 |

两次停下都要等用户回复：第 2 步方向错了，后面全要返工；第 6 步是用户第一次看到完整页面。

## 进来先分流

| 信号 | 走哪条线 |
|---|---|
| 给了材料（或材料所在文件夹），要整理成文章 / 指南 / 知识页 | 全流程，从第 1 步做 |
| 已有学习指南 + 新材料（「补进去」「更新一下」） | 第 8 步维护 |
| 有材料但只说「帮我看懂」「理一下」，没说要文章 | 做完第 1–2 步，给一页结论和主线，问要不要做成完整指南 |
| 明说「保留原文」「原文全文」 | 原文模式：writing.md 末节 |
| 在做别的（读报告、research-with-gpt 收卷）时说「太长了」「看不过来」 | 一句话问要不要做成学习指南，不自动开工 |

## 流程

### 1 收料

这一步要把材料变成能读的文字，并弄清手上一共有什么。

```bash
python3 -I <skill>/scripts/inventory.py <主题文件夹>
```

`<skill>` 指本 skill 的目录。脚本会扫整个主题文件夹（材料常常没放进原件目录，直接放在根目录），把每份转成文字，打印材料表：类型、字数、链接数、内部引用标记数。转不出来的、视频没字幕的，列给用户，请他换格式或给转写稿。材料表写进 `0-说明.md`。

### 2 定主线 → 第一次停

这一步决定整篇怎么讲。读完所有材料，把它们拆开重组，搭出一条让读者能顺着走下来的主线，再写一章样章让用户确认方向。

1. **定范围**：有 `0-说明.md` 和 `1-prompt.md` 的，读调研的原始问题、目标和诉求，确定这篇要回答什么、要不要写方法论。
2. **读完材料**：每份都从头读到尾，不只看标题。
3. **拆成论点池，再搭主线**：做法见 `references/writing.md`「主线」一节。报告的章节顺序不当骨架。
4. **边读边记**：证据薄、要自己检索的地方；文中会提到的外部对象（案例、产品、网站、作品、视频、论文），以及读者需要看到它们的哪一面。
5. **先核裁决依据**：裁决冲突所依赖的那几条，这一步就回原网页核实。主线常常跟着裁决走，依据到第 3 步才被推翻，提纲就得重来。
6. **写 `提纲.md`**，通常有这几块，按主题增减：
   - 读者任务：读完能说清什么；写方法论时，还要写读完能做成什么
   - 叙事主线：一段话讲清从哪里出发、经过哪几个关键判断、落到哪里。写不出来，多半还在按材料的顺序走
   - 目录：章节标题用名词短语
   - 论点池的去向：每条进了哪一部分、被合并、被裁决，或者为什么不收
   - 要补的证据、外部对象（在文中做什么、要收什么、怎么展示）、展示设想
7. **写样章**：挑最能暴露问题的一部分写出来，用真组件渲染（构建方法见 `references/publish.md`），截图。样章里出现的外部对象先按第 3 步的做法收好实物，用户看到的就是读者会看到的样子。

把读者任务、叙事主线、目录、合并和裁决的要点、外部对象和展示设想，连同样章截图发给用户，**停下等他回复**。要不要写方法论还没定的，在这里一起问。

### 3 补证据、收实物

这一步让正文里的每个事实都能点开核对，让每个例子读者都能看到。第 2 步已经核过的裁决依据、样章里收过的外部对象不用重做。

要做的有五件：找回丢失的引用链接；把正文要用的关键论断（数字、日期、产品功能、原话）对着原网页核一遍；对提纲里记下的薄弱处联网检索补齐；收齐外部对象的截图、封面和视频；检查正文用到的每个链接能不能打开。具体的脚本和顺序见 `references/evidence.md`。核对结果、没找回的、打不开的都写进 `核对.md`，不上页面。

### 4 写全文

这一步按确认过的提纲把 guide.md 写完整。照 `references/writing.md` 的规范写：通俗易懂、不缺专业性，把压缩的写开；取舍看会不会改变读者的理解或做法；论断和依据写在一起；你自己的判断放进「我的看法」；页面上不放给核对者看的说明。写的过程中发现主线要调整，就调，并在提纲里记一笔。

### 5 配图排版

这一步让读者在需要看的地方看得到、在需要对照的地方对照得清。按展示设想落组件，写法见 `references/components.md`。怎么展示，看那一处要读者做什么：比较、感受样子、看动态、照着做，各有合适的组件；抽象原则的对错差别可以画信息图（`references/infographic.md`，先出两张样张给用户看风格）。

写完整篇，再从读者的角度过一遍：读到某个例子、某个产品时，能不能一点就看到；哪里要来回对照、一段话讲不清，就补一张图或表。图表里的事实逐条对原文。

### 6 构建自检 → 第二次停

这一步确认页面在各种宽度下都能正常读。按 `references/publish.md` 构建，跑 `page_check.py`，截图放进 `自检截图/`，四个宽度都要通过。再自己看截图：字号层级、有没有空框、有没有挤成一字一行的列。

把本地预览地址和截图发给用户，**停下等他看**。他提修改，就改完再自检；他说「发布」才进第 7 步。

### 7 发布

这一步把这一篇放上线，不影响站上别的页面。按 `references/publish.md`：读本机发布配置，只传这一篇的目录，传之前、传之后都和线上比对，上线后在线上地址再跑一次 `page_check.py`，在 `0-说明.md` 里记一笔。没有发布配置，就停在本地预览，告诉用户。

### 8 维护

这一步把新材料并进已有的指南，而不是另起一篇。按 `references/publish.md`「维护」：登记材料 → 并进论点池（合并、裁决、融合）→ 看主线要不要调、哪些部分要改 → 改 → 构建自检 → 用户说「发布」再发 → 记版本。

## 主题文件夹

从 research-with-gpt 来的，沿用它的文件夹；不是的，在工作区的 `知识/调研/<主题>-<YYYY-MM-DD>/` 下新建，材料放进 `2-报告原件/`（视频、网页、PDF 也放这里）。学习指南目录用下一个空着的编号（5 起）；已经有学习指南目录的，沿用，不改名。

```
<主题文件夹>/
├── 0-说明.md          材料表、版本记录、线上地址、下一步
├── 2-报告原件/        原始材料，只读
├── 3-报告转写/        inventory.py 转出的文字
├── 原图/              信息图的 PNG 原图（不发布；页面用的是 img/ 里转好的 JPG）
└── <N>-学习指南/
    ├── 提纲.md         第 2 步的提纲
    ├── 核对.md         核到原文的、补充检索的、没找到出处的（不上页面）
    ├── guide.md        正文真源
    ├── sources.json    来源表；sites.json（网站、作品、产品）、videos.json 可选
    ├── links/          找回链接的过程文件
    ├── img/            信息图、截图（会被发布）
    ├── 自检截图/        page_check 的截图（放 img/ 会被带上线）
    ├── app/            页面模板副本
    ├── site/           构建产出（发布用）
    └── index.html      单文件版（本机双击看）
```

## 交给用户的消息

第一次停：提纲要点 + 样章截图（+ 要不要写方法论，没定的话）。第二次停：本地预览地址 + 截图 + 一行自检结果。发布后：线上地址。

## 红线

1. **可核对的事实没出处不写**：数字、日期、价格、产品功能、谁说了什么，查不到出处就不进正文；图表里的事实逐条对原文。读者还没读过材料，判断不了真假，编出来的数字他会当真去用。
2. **原始材料只读**：不删、不改 `2-报告原件/`，那可能是唯一一份。
3. **未公开的信息不上页面**：私人打算、他人的未公开信息、真人照片、账号不进正文和示范。页面会公开发布。
4. **用户说「发布」之前不上线**，上线只传这一篇的目录。发出去的东西收不回来，整站发布还会把别的会话没上线的改动带出去。

## 出问题时

| 情况 | 怎么办 |
|---|---|
| 材料转不出文字（扫描版 PDF、乱码） | 列出来请用户换格式；不凭文件名猜内容 |
| 视频、播客没有字幕或转写 | 请用户给；不凭标题写 |
| 某部分证据不够 | 自己联网检索补齐；查不到可靠来源的说法不写成定论，放进「还不确定的」或删掉 |
| 网页搜索额度用光 | 分批续；找不到的不写进正文，记进核对.md |
| 生图两次不对 | 不放这张图，文字写完整 |
| 截图截到拦截页、登录墙 | collect_refs.py 会改用页面封面图；都拿不到就只放链接；不伪装浏览器绕过 |
| 构建报错 | 按报出的行号改 guide.md；不改模板去迁就写错的语法 |
| 没有本机发布配置 | 停在本地预览，告诉用户本地版在哪 |
