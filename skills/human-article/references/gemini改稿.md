# Gemini 改稿 prompt

第八步用。`scripts/gemini_revise.py` 读下面代码块里的字当 prompt，把文章接在最后一行后面；作者要在 Gemini 网页里用，就整段复制，再把文章贴在后面。改 prompt 只改代码块里的字，第一行到「下面是需要进行活人感改造的文章：」之间的都会发给 Gemini。

```
下面是我写的一篇文章，需要你改稿保证文章的主线通畅、有活人感，改稿具体要求是：

1. 主线清晰、段落通顺。你应根据文章自行思考写作目的，通过目的思考写作的主线，全文应按照叙事主线推进，一句一段为主，能拆开的就拆开，每段接住上一段，和主线接不上的段落，可以挪动、合并或者删掉。原文拿一件事从头讲到尾的，顺着这件事往下改，不拆成一块一块的功能介绍。
2. 给读者讲清楚事，也让读者看到我这个人。讲功能和知识的段落直接讲事，不硬加“我”和“你”。讲我经历的事时，我做了什么、看到了什么、当时怎么想、哪一下愣住了、我怎么判断，原文写了的都留着，不要删成只剩结果。“你”用在带读者看、给读者打比方、跟读者搭一句话，或者告诉读者能怎么做的地方，比如“你看这张图右上角”“你可以把它想成……”。硬配上去的“我”和“你”删掉；“我”是做事的人时留着，不写成没有主语的句子。说自己做的东西时口气谦逊亲和，像跟朋友聊天。
3. 说人话。先说谁做了什么，用说出口的完整说法；读者不认识的名字，第一次出现时用半句话说清，skill、prompt、Agent 这类 AI 领域的通用名词直接用，不解释。口气跟着原文走，原文轻松就轻松，原文正经就正经。
4. 用词需要是白话。不要为了古朴将双音节词压缩为单音节的字，文章不追求单位字数的信息密度，追求表达自然、文字亲近。量词后面的东西、动词后面的对象都说出来，比如“排了四节”写成“排了四节课”，“九点前要交”写成“九点前要交作业”。
5. 不加原文里没有的事实、数字、人名、程度说法和别人的反应；我做过什么、用它做成了什么，都以原文为准。
6. 标题、开头的「大家好，我是阿東。」、文末的固定结尾、单独一行的图（[图N]、[视频N]、[公众号二维码] 或图片链接）和加粗原样保留；挪段落时，图跟着它讲的那件事走。

改完先给全文。全文后面单独一行写「===改动说明===」，再用几行说改了哪几处、删了什么。
```
