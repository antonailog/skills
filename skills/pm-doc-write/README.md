# pm-doc-write

按本人写法写周报、OKR、项目总结

## 要解决的问题

工作文档的读者是老板和协作方，要在 30 秒内扫到结论和下一步。没有约束时，起草出来的文档容易过程先行、把多对象的信息写成长段落、数字不带对比基线，语气是名词化的汇报腔，读着不像用户本人的手笔。

## 运行方式

![pm-doc-write 结构图](../../docs/diagrams/pm-doc-write.jpg)

认准场景后，先读通用约束和对应的场景模板，再起草本地 Markdown，逐条过终审清单；读着不像本人手笔，就回范文库重读模板指定的段落重写。发布是可选的最后一步：说清发到哪、用户确认后，才用 lark-cli 新建文档或块级追加。用户说要收录一篇文档时另走收录流程，新写法合进模板，逐条确认后才生效。

## 关键设计

一篇工作文档要同时做到两件事：读者 30 秒内扫到结论和下一步，读起来像用户本人的手笔。pm-doc-write 把写法分成两层：所有文档共用的通用约束，加上每个场景一份的模板；模板连着用户本地的范文库，收录新范文时把写法差异合进模板。

- **通用约束打底，场景模板叠在上面**：`references/通用约束.md` 管所有文档共用的结构、数字和语气，末尾附终审清单；每个场景再配一份模板，比如 `references/模板_周报.md` 锁定单周的章节顺序和每个子模块的写法。两层冲突时以通用约束为准，没有模板的场景按就近模板写。
- **结论先行，多对象信息进表格**：每节的结论、统计、目标放在文档头、汇总表和标题里，过程和原始数据沉到附录或外链。凡是多个对象乘多个属性的信息，比如指标、todo、对比、排期，一律进表，段落只写单线叙述（`references/通用约束.md`）。
- **数字带对比基线，事实只用用户给的**：数字写成 3%→7% 这样的变化，目标未定用 →xx 留白占位。数据、链接、责任人只来自用户的素材，缺的地方在文中标出、留给用户补上，`SKILL.md` 把这条列为红线。
- **语气贴近用户的简报体写法**：用名词短语加冒号加数据的压缩句式，责任人挂在标题或条目尾部；强调靠标题、分级列表和冒号加子项，正文不加角括号、方头括号、长破折号。教学类长文用完整句讲因果，写法在 `references/模板_项目总结.md`。
- **每条约束写明原因，模板从范文里长出来**：通用约束来自用户认可范文的跨篇分析，每条附上原因，模板没覆盖的情况按原因推断。收录新范文时全文快照原样存档，模板末尾的范文一节写明原文链接、本地快照和读哪一段，规则在 `SKILL.md` 的收录子流程里。

```text
pm-doc-write/
├── SKILL.md                   场景对照表、起草流程、收录子流程
├── references/                通用约束必读，模板按场景读一份
│   ├── 通用约束.md            所有文档共用的写法和终审清单
│   ├── 模板_周报.md           周报：多模块进展和 Todo 闭环
│   ├── 模板_周报todo.md       多个例会的汇报材料按期汇总
│   ├── 模板_OKR.md            定位和季度目标
│   ├── 模板_项目总结.md       项目复盘和方法论沉淀
│   ├── 模板_指标需求.md       指标查询手册和提需论证
│   ├── 模板_评测结论.md       评测文档的口径和统计结论
│   ├── 模板_策略迭代说明.md   策略改动在回归集上的效果说明
│   ├── 模板_LR.md             策略、模型改动的上线评审
│   └── 模板_调研报告.md       调研和证据类分析
└── examples/
    └── pomodoro-summary/      例子：把番茄钟网页的开发记录写成项目总结
```

## 其他

- 前提：发布和收录需要 lark-cli
- 注意：范文库是使用者本地的资产，不随仓库发布；换人用要先收录自己的范文，成稿才像自己
- 注意：飞书上维护中的文档只新建或追加，从不覆写，覆掉的内容找不回来
