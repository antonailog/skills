# 《html-deck Skill 设计文档》

> 阶段：S2 设计 · 状态：已确认（2026-11-23）
> 读者：用户确认边界和流程；以后改这个 skill 的人看为什么这样定
> 档位：完整档（公开仓库、有脚本、要跨会话保持同一套做法）

## 0. Skill 化决策（S0 结论）

做 HTML 演示稿会反复用（演讲、课程、汇报、产品演示），里面有大量每次都一样的活（缩放翻页引擎、编辑服务、离线打包、网站版生成、检查），还要跨会话保持同一套做法（先讨论再动手、分步只在需要的页、公开前扫源文件）。仓库里没有能扩展的：pptx 出的是 PowerPoint 文件，archify 做单页图解，knowledge-canvas 做知识画布，forge-design-lab 定网站设计参数，都不管「一份能上台的稿子」。

满足：☑ 会重复使用 ☑ 容易被路由错（和 pptx、archify 抢） ☑ 有脚本能省重复劳动 ☑ 需要跨会话统一

## 1. 收料结论（S1）

### 1.1 需求与场景

- **使用者与处境**：要做演讲、讲课、汇报或产品演示的人，有主题和一些材料，想要一份能直接上台放、还能自己在页面上改的演示稿。
- **现在怎么解决、哪一步最烦**：PPT 里排版费时间，改一个字要来回对话；嵌网页、视频、断网、换电脑都容易出事；公开发布时容易把私人内容带出去。
- **理想产出**：一个文件夹，双击就能放；能在页面上改字、批注；能打成离线包拷到别人电脑；能生成一版发到网上。
- **什么算做对了**：上台能放完（翻页笔、断网、换电脑都不出事）；每页观众一眼知道这页讲什么；用户拍板的地方没被替他决定；公开版里没有私人内容。

### 1.2 已有决策与约束

| 类别 | 内容 | 可否推翻 |
|---|---|---|
| 形态 | 纯 HTML + CSS + JS，不用框架、不用构建；16:9 舞台按窗口缩放 | 不可 |
| 风格 | 固定 4 个：瑞士网格、编辑书卷、暗场发布会、新野兽派；每次从中挑，功能完全一样只换外观 | 不可 |
| 功能 | 见 `01-需求与决定.md`：已有功能全部带上，新增 13 项 | 不可 |
| 公开 | 放 antonailog/skills 公开仓库；skill 里的例子用大众题目，不用用户自己的讲稿 | 不可 |
| 上下游 | 上游：用户的大纲或材料（md、文档、表格、录屏）。下游：现场放映、离线包、静态网站版。部署到哪个网站不归本 skill | 可讨论 |
| 安全 | 外发和公开前扫解压后的全部文件；公开版不放备注和真名 | 不可 |

参考对象及不借鉴什么：

| 参考 | 借鉴什么 | 明确不借鉴什么 |
|---|---|---|
| 作者 2026-11 那场分享的讲稿 | 整套引擎、编辑模式、交付脚本、改稿循环 | 讲稿内容、只适合那一场的版式（时间线、流水线这类定制图） |
| reveal.js | 演讲者视图、总览、翻页笔按键的通行做法 | 不引它本身（太重、要配置）；不做嵌套竖向页 |
| Anthropic pptx skill | 「先出大纲再排版」的顺序 | 不出 .pptx，不做母版占位符那套 |
| forge-design-lab | 用真实内容渲染多版再挑 | 不做 token 工作台，风格是固定的 4 套 |

### 1.3 基建盘点

不调外部接口，全部是本地脚本和浏览器：

| 工具 | 什么时候用 | 必用/看情况 | 失败时 |
|---|---|---|---|
| Python 3 标准库 | 编辑服务、打包、网站版、扫描 | 必用 | 没有 Python 就只给静态稿，不开编辑模式 |
| Playwright | 风格渲染、自动检查（溢出、断网）、截图兜底 | 看情况 | 没装就跳过检查并明说「这次没做自动检查」 |
| Google Fonts css2 接口（`text=` 参数） | 打包时按用到的字下载字体子集，缓存在 `~/.cache/html-deck/fonts/` | 看情况 | 没网就回落系统字体并提示；设了代理走 `HTTPS_PROXY` |

## 2. 设计

### 2.1 要解决的问题

把「我要讲一个东西」变成一份能直接上台放、能在页面上改、能拷到别的电脑、能发到网上的 HTML 演示稿，并陪用户多轮改到定稿。

### 2.2 定位与边界

**定位**：HTML 演示稿。像一个懂设计、也懂演讲的制作搭档——把「这一页观众该先看到什么」讲透：每页一个观点，结构先于样式；拿不准的地方摆出来给你挑，你拍板，我落地。

**核心立场**：用户要的是一份能上台、讲得清楚的稿子，不是一套好看的模板。所以先定讲什么（场合、时长、听众、每页一句观点），风格从 4 套里挑，所有要拍板的事做成讨论页让他选；改稿靠他在页面上直接改和批注，不靠来回对话描述位置。

**范围**：一份演示稿从开工、大纲、风格、初稿、改稿到交付（现场版、离线包、网站版）。一次只处理一份稿。

**不处理**：

| 不处理什么 | 交给谁 |
|---|---|
| 要 .pptx / Keynote 文件 | pptx skill |
| 单页图解、流程图、架构图、一页说明 | archify |
| 知识画布、可缩放的知识地图 | knowledge-canvas |
| 网站页面、产品界面的设计 | forge-design、forge-design-lab |
| 把讲稿改写成文章、逐字稿发公众号 | human-article |
| 海报、小红书多图、活动推送图 | image-prompt、xhs-note、ai-events-push |
| 把材料整理成长篇学习指南 | study-guide |
| 部署到某个具体网站（服务器、CDN） | 用户自己的发布流程；本 skill 只出静态目录 |

**很像但不该触发的 query**（门禁第 1 条）：

1. 「把这份周报转成 pptx，明早发给老板」→ pptx
2. 「画一张我们推荐系统的架构图，做成一页能分享的」→ archify
3. 「帮我把上周分享的讲稿改成一篇公众号文章」→ human-article
4. 「做一张下周沙龙的活动海报」→ image-prompt
5. 「帮我重新设计一下博客首页」→ forge-design

### 2.3 触发与意图路由

**触发层素材**

- 应触发：「做个演示稿 / 讲稿 / 幻灯片 / slides / 分享用的 html」「下周要讲 X，帮我准备」「给新人上一堂课，要能投屏」「季度汇报做成网页版」「产品演示要放录屏和 demo」「这份讲稿我批注完了」「讲稿打个包拷走」「换个风格再出一版」；哪怕用户只说「要上台讲」「要做个分享」，没说 HTML，也触发
- near-miss：上面 5 条
- 抢活的隔壁：pptx（用户说「PPT」时要分辨：要文件还是要能放的稿子——没点名文件格式就归本 skill，点名 .pptx 归 pptx）、archify（单页说明）、Artifact 的 Slides 类型（用户明确要 claude.ai 上的页面时归它）

**路由层**

| 意图强度 | 判断信号 | 应答 |
|---|---|---|
| 强 | 有主题，且有场合或时长，且有材料或大纲 | 走全流程，第 1 步只补缺的 |
| 弱 | 只有主题（「做个关于 X 的分享」） | 问开工的 5 件事，给一版大纲骨架 |
| 潜在 | 在别的任务里提到要上台、要汇报 | 一句话问要不要做成演示稿 |
| 改稿 | 给了已有稿的目录，说「批注完了」「改第 5 页」「换风格」 | 直接进改稿循环（第 5 步） |
| 交付 | 「打包」「拷到别的电脑」「发到网上」 | 直接进交付（第 6 步） |

### 2.4 输出框架

**固定骨架**：每份稿都是同一个项目结构，任何场景不变。

```
<项目>/
├── 讲稿/index.html          内容：每页一个 <section>，只写内容和组件，不写样式
├── 讲稿/deck/               引擎：deck.js、deck.css、风格 themes/<风格>.css（开工时从 skill 拷一份；字体打包时才下载子集）
├── 讲稿/嵌入/                截图、视频、嵌入页
├── 改稿/批注.json            编辑模式写的批注
├── 改稿/讨论-<日期>-<事>.html  每轮要拍板的事
└── 交付/                    离线包 zip、网站版目录
```

每页的骨架：标题（一句观点）+ 一个主组件 + 页脚（来源、页码）+ 备注（只在现场版）。

**必出模块**

| 模块 | 入选条件 | 内部结构 | 对应考点 |
|---|---|---|---|
| 开工确认 | 每份新稿 | 场合、时长、听众、现场条件（谁的电脑、有没有网、翻页笔、投影比例），缺的才问 | K1 缺信息时问了，且不超过 3 问一轮 |
| 大纲 | 每份新稿 | 每页一行：观点句、用什么组件、要不要分步 | K2 每页一个观点；K3 分步只标在需要渐进讲的页 |
| 风格选择 | 每份新稿、换风格时 | 用大纲前几页真实内容渲染候选风格，讨论页点选 | K4 渲染的是真实内容不是占位符 |
| 初稿 | 每份新稿 | 按大纲写 index.html，跑检查 | K5 检查通过：无溢出、文件都在、断网能放 |
| 改稿循环 | 用户批注后 | 明确的直接改；要拍板的出讨论页；改完逐条标状态 | K6 用户手改的内容没被覆盖；K7 要拍板的没替他定 |
| 交付 | 用户要打包或公开时 | 检查 → 隐私扫描 → 离线包 → 网站版 | K8 扫描在打包前跑，命中就停 |

模块 6 个。触发式模块：

| 模块 | 触发条件 | 取舍 |
|---|---|---|
| 演讲准备 | 场合是现场演讲 | 提醒备注、翻页笔、演讲者视图的用法 |
| 网站版 | 用户要发到网上 | 删备注、换署名、私人嵌入换截图；部署交给用户 |

### 2.5 执行流程

| 步 | 做什么 | 用到 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|---|---|
| 1 开工 | 补齐场合、时长、听众、现场条件、材料 | — | 用户的话和材料 | 开工确认（几行） | 只有主题时一轮问 3 件，其余用默认并写明 |
| 2 大纲 | 读材料，排页，每页一句观点、选组件、标分步 | references/components.md | 材料 | 大纲（文字或讨论页） | 材料不够撑时长：列出缺口问用户，不编内容 |
| 3 风格 | 用前 3—4 页真实内容渲染候选风格 | scripts/render_styles.py | 大纲、风格清单 | 风格讨论页 | 没装 Playwright：给风格说明和样张截图让用户挑 |
| 4 初稿 | 建项目、拷引擎和风格、写内容、跑检查 | scripts/scaffold.py、scripts/check.py | 大纲、风格 | 能放的稿子 | 检查不过就修到过；字体没下好就先用系统字体并提示 |
| 5 改稿 | 开编辑模式；读批注；改；出讨论页；标状态 | scripts/serve.py、assets/discussion.html | 批注.json | 新一版稿子、讨论页 | 端口被占就换端口；用户在页面上改过的文件只做局部替换，不整页覆盖 |
| 6 交付 | 检查、扫描、打离线包、生成网站版 | scripts/check.py、privacy_scan.py、package.py、website.py | 定稿 | zip、网站版目录 | 扫描命中：停下列给用户，不出包 |

### 2.6 辅助资源

| 资源 | 类型 | 为什么需要 |
|---|---|---|
| deck.js / deck.css | assets/engine/ | 舞台缩放、翻页、分步、页签、嵌入、断网兜底、备注、全屏、打印、翻页笔、演讲者视图、总览、动效、图表、二维码；每份稿都一样 |
| editor.js | assets/engine/ | 编辑模式前端（只在编辑服务打开时注入） |
| 4 套风格 | assets/engine/themes/ | swiss.css、editorial.css、keynote.css、brutal.css；只定变量和组件外观 |
| 讨论页模板 | assets/discussion.html | 每轮拍板都用同一套：顶上列要定几件事和推荐、选项并排、点选加备注、复制后显示「已复制」 |
| 组件样张 | assets/components.html | 所有组件在一页里，写稿时照着用；也用来验收 4 套风格 |
| scaffold.py | scripts/ | 建项目目录、拷引擎和风格（字体在打包时才下载） |
| serve.py | scripts/ | 编辑模式服务：注入 editor.js、只写回舞台段、版本检查、备份、批注和截图 |

| render_styles.py | scripts/ | 拿大纲前几页渲染候选风格截图 |
| privacy_scan.py | scripts/ | 扫要装进去的全部文件：本机路径、用户名、邮箱、手机号、密钥样式、IP、用户指定的词 |
| package.py | scripts/ | 按引用收文件、字体抽子集、打离线 zip、写「怎么播放」 |
| website.py | scripts/ | 网站版：删备注、换署名、标了「仅现场」的嵌入换截图 |
| components.md | references/ | 组件清单、什么时候用、什么时候分步 |
| themes.md | references/ | 4 套风格的样子、适合场景、变量表 |
| revise.md | references/ | 改稿循环：读批注、讨论页规范、手改保护 |
| deliver.md | references/ | 交付检查清单、离线包、网站版、隐私扫描、换电脑注意事项 |
| presenting.md | references/ | 翻页笔按键、演讲者视图、总览、动效规则 |

### 2.7 输入输出定义

**预期输入**：主题和场合；可能带材料目录、表格、录屏、已有的旧稿。

**query 样本**（门禁第 5 条）：

1. 「下周三组里技术分享，45 分钟，讲我们从 0 到 1 搭 RAG 评测的经验，材料在 docs/rag-eval/ 下面，帮我做个 html 的演示稿，要能在会议室电脑上直接放」
2. 「给新人上一堂 Git 入门课，大概 90 分钟分三节，想要安静一点的风格，代码要在投影上看得清」
3. 「季度汇报，给老板看，数据在 q3.csv，十页以内，要有图表，别花里胡哨」
4. 「下周产品发布要演示新插件，有两段录屏和一个网页 demo，现场用翻页笔，场地网不一定好」
5. 「讲稿我批注完了，你看下 改稿/批注.json 改一下，第 7 页那个图我想换个画法你先给我几种」
6. 「讲稿定了，打个包我要拷到活动方电脑上，再出一版能发到我博客的」
7. 「上次那份分享换成暗色的再出一版，内容不变」

**预期输出**：一个项目文件夹（结构见 2.4），每轮回复用户：做了什么、要他定什么（讨论页链接）、怎么打开看。

### 2.8 上下文分层规划

| 层 | 放什么 | 预估体量 |
|---|---|---|
| description | 做什么、哪些说法要触发（含没说 HTML 的）、不处理 pptx 和单页图解 | ~350 字 |
| SKILL.md 正文 | 定位和立场、路由表、6 步流程（每步一段）、讨论规矩、红线、项目结构 | < 250 行 |
