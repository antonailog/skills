# 信源获取：36 氪与同类中文科技商业媒体

> 日期：2026-10-11 · 用途：自动化调研 skill 的信源接入依据。
> 预算：搜索、抓取、实测合计 25 次，已用完。本机出口走 Clash 代理 `http://127.0.0.1:7897`，实测时没有记录出口 IP。
> 标注约定：**【实测】**表示本次亲手跑过，结果原样记录在第 3 节；**【源码】**表示读过 RSSHub 的 GitHub 源码；**【搜索】**表示只看到搜索结果，没有打开核对；**【未测】**表示本次没有验证。

## 1. 一句话结论

36 氪桌面域名（`36kr.com`、`www.36kr.com`，含官方 RSS `/feed`）前面有一道火山引擎的 JS 挑战。curl 和 WebFetch 第一次请求就会被拦，无头 Chromium 2.8 秒内能自动过。移动端文章页 `m.36kr.com/p/<id>` 不经过这道挑战，用 curl 就能拿到服务端渲染的全文和结构化 JSON。所以零成本可自动化的组合是：**用公众号订阅或 `site:36kr.com` 搜索拿到文章 ID → 用 `m.36kr.com/p/<id>` 取全文**；官方 RSS 用无头浏览器读作为补充；公开实例 rsshub.app 在本机不可用（Cloudflare 403）。

**火山引擎拦截的触发条件（本次观测）**：桌面域名下的任何路径（文章页、`/feed`），只要请求不执行 JS、也没带有效的 `_waftokenid` cookie，**第一次请求就会被拦**，和请求频率无关。挑战页 HTTP 状态码是 200（不是 403），content-type 是 `text/html`，大小约 25 KB。所以程序不能只看状态码，要检查返回体里有没有「安全检测」。按频率触发的阈值本次没有测出。
