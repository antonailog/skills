# 信源获取：知乎

> 日期：2026-10-11 · 用途：给自动化调研 skill 定「知乎」这一信源的取数路径。
> 环境：Claude Code（WebSearch / WebFetch / curl / Python / playwright 无头 Chromium），代理 `http://127.0.0.1:7897`；直连出口经 ipinfo 测得为 CN。
> 预算：搜索 + 抓取 + 实测共 25 次，已全部用完（另有 2 次 ipinfo 出口检测的辅助请求）。凡未核实的内容都在第 5 节「存疑 / 待查」列出。

## 一句话结论

2026-10-11 实测，未登录时直接抓知乎专栏和问答页，curl、WebFetch、无头 Chromium 全部返回 403；rsshub.app 公共实例被 Cloudflare 拦截，搜狗知乎搜索跳到反爬页。不登录还能用的只有两条：海外搜索引擎（只拿到标题和 URL）和第三方 RSSHub 实例（只拿到热榜问题）。首选路径是知乎官方 2026 年 5 月开放的「知乎数据开放平台」（REST / MCP）：用知乎账号注册就能拿 Access Secret，2026-10-11 官网首页写的是「注册免费获取 5000 次/天调用」。它的限制是搜索接口只返回摘要和赞同数，每次最多 10 条，不能翻页。要读全文，仍需要用户自己的登录态。

## 3. 高质量内容的识别

### 3.1 可以机读的信号

以下字段来自官方知乎搜索 API，或来自 RSSHub 的输出：

| 信号 | 来源字段 | 怎么用 |
|---|---|---|
| 赞同数 | `VoteUpCount`（可以直接在请求里用 `SortBy=VoteUpCount:desc:(N,)` 做服务端过滤） | 先设一个下限，比如 ≥100；冷门话题适当放宽 |
| 评论数 / 精选评论 | `CommentCount`、`CommentInfoList` | 评论区常有反驳和补充事实，可以拿来做交叉核验 |
| 作者认证 | `AuthorBadge`、`AuthorBadgeText`（认证文案） | 判断是否为从业者或机构：认证里写了公司或职位的，优先采信 |
| 权威等级 | `AuthorityLevel`（官方字段，取值含义没有公开说明）；平台自称内容有 L1–L5 分级并经过人工审核 | 作为排序参考，不能单独当作结论依据 |
| 时效 | `EditTime`（当前对应发布时间）、RSS 的 `pubDate` | AI 产品类问题优先看近 12 个月的内容 |
| 内容类型 | `ContentType`（Article / Answer 等）；URL 形态：`/org/` 是机构号，`/people/` 是个人，`zhuanlan.zhihu.com/p/` 是专栏 | 专栏文章往往是体系化长文，回答往往是一手经验 |

以下信号属于平台常识，本次没有逐一核实：优秀答主、新知答主等身份标识；盐选内容是付费的，非会员只能看到部分；回答长度；「编辑于」时间。

### 3.2 在「AI 产品 / 科技行业调研」场景下价值较高的类型

下面是判断，不是实测结论。

1. **从业者在「如何评价 X」类问题下的回答**：常有一手使用体验或内部视角。拿到后用认证文案核对作者身份。
2. **技术负责人的长文专栏**：讲机制和原理，比媒体稿深。
3. **创业者或产品人的复盘**：讲做产品的取舍。
4. **AI 媒体机构号**：时效强，适合补事件线；但很多是公众号稿的转载，不能当一手信源。
5. **「值得关注的 AI 博主」类问题**：可以当作者种子池，先发现作者，再按作者去搜。

## 4. 推荐方案

### 首选：官方开放平台，零成本、可自动化、低风险

1. 用户手动做一次：在 [developer.zhihu.com](https://developer.zhihu.com/) 用知乎账号注册，在个人中心生成 Access Secret。然后二选一：
   - 执行 `claude mcp add --transport http --scope user --header "Authorization: Bearer <secret>" zhihu https://developer.zhihu.com/api/mcp/v1`；
   - 或者把 secret 写进环境变量，由 skill 直接用 curl 调 REST。
2. skill 的取数流程：
   - 对每个子问题调 `zhihu_search`，带上 `SortBy=VoteUpCount:desc:(N,)`。拿回 10 条摘要，连同赞同数、认证、权威等级和时间。
   - 需要更多结果时改写 query 多查几次，因为接口不能翻页。
   - 需要追热点时补调 `hot_list`。
   - 报告里引用时保留作者名和 `Url`；官网写有「引用数据时展示具体作者信息」。
3. 成本：每日免费额度内为 0。每次调用前用「额度查询 API」或个人中心核对余量，超额后会自动从余额扣费。

### 备选 1：没有 key 时的降级路径，零登录

- **发现**：用 WebSearch 加 `allowed_domains: ["zhihu.com","zhuanlan.zhihu.com"]`（T13 ✔），或用 Bing `site:`（T1，命中率低，结果需要过滤）。只能拿到标题和 URL。
- **热点**：第三方 RSSHub 实例 `/zhihu/hot`（T12 ✔）。只到问题层，没有回答；实例随时可能失效。
- 正文拿不到。报告里要标明「知乎来源只有标题，未读正文」，不能把标题当结论。

### 备选 2：要读全文，必须有登录态，只用于少量关键文章

- 用用户**已登录**的真实浏览器，例如 Claude in Chrome，或者 OpenCLI 的「use your logged-in browser」，逐篇打开。每次几篇，低频、人工可见，不批量。
- 不建议在无头 playwright 里塞导出的 cookie 批量跑：本次未实测，账号风险落在用户身上。

### 不建议

- 逆向 x-zse-96 签名去调内部接口：签名随版本变；meurz 项目已归档；zhihu-oauth 有被 DMCA 的先例。
- rsshub.app 公共实例（Cloudflare 拦截）。
- 搜狗知乎搜索（进反爬页）。
- 无 cookie 的直接抓取（T4、T5、T8、T10、T11 全部 403）。

### 只能由用户手动做的事

1. 注册开放平台、生成和保管 Access Secret，并决定是否充值以应对超额。
2. 需要全文时，在自己的浏览器里登录知乎并授权 agent 使用。如果非要用 cookie，由用户导出并自担账号风险。
3. 如果要自建 RSSHub 并启用需要 cookie 的知乎路由，由用户提供 `ZHIHU_COOKIES`。

## 5. 存疑 / 待查

- **免费额度口径**：早期报道写 1000 次（「每天」和「每月」说法不一）；2026-10-11 官网首页写 5000 次/天；计费文档说明是限时优惠。注册后以个人中心为准，并留意每个额度组单独的上限。
- **问题回答 API** 的返回字段没有读到，它能否给出回答全文待核实。如果能，备选 2 的大部分场景都可以改由官方接口完成。
- 官方 API 的 QPS 上限文档里没写，只有错误码 30001。
- RSSHub 各个知乎路由是否需要 `ZHIHU_COOKIES` 没有核实（docs 返回 404，预算已用完）。可以直接看源码 https://github.com/DIYgod/RSSHub/tree/master/lib/routes/zhihu 。
- rsshub.rssforever.com 是否配置了 cookie、能稳定多久，未知。只测了 1 次。
- 带登录态的 playwright 或 Chrome 方案没有实测，能否通过 40362 风控未知。
- 附录 B 的开源工具都没有实测，星数和推送时间不代表现在还能用。
- 搜狗的反爬是请求特征触发还是统一拦截，单次测试分辨不了。
- Bing `site:` 只命中 2/10，可能与 `setlang=zh-CN` 或地区有关，没有对照测试。

## 附录 A　官方渠道详情：知乎数据开放平台（2026-10-11 读取）

- **开放时间**：据 [威易网 2026-05-19 报道](https://www.weste.net/2026/05-19/zhihu-API-MCP-Skill.html)和搜索摘要，平台在 2026 年 5 月开放，提供 REST API、MCP、Skill 三种接入方式。知乎专栏上也有一篇[《[笔记] 知乎API和MCP正式开放!》](https://zhuanlan.zhihu.com/p/2033565515994678331)，因 403 没能读到。
- **免费额度**：2026-10-11 官网首页写「注册免费获取 5000 次/天调用」。[计费文档](https://developer.zhihu.com/docs?key=billing_price)说明：
  - 部分服务共用同一个额度组，同一知乎账号下的多个 Access Secret 共用额度；
  - 鉴权失败、参数错误、被限流的请求不计费；
  - 每日额度是限时优惠，后续可能调整。
  - 早期报道写的是 1000 次，且「每天」还是「每月」各处说法不一致。以个人中心「用量统计」为准。
- **鉴权**：请求头 `Authorization: Bearer <access_secret>`，同时必须带 `X-Request-Timestamp`（秒级 Unix 时间戳）。Access Secret 在个人中心生成（[文档](https://developer.zhihu.com/docs?key=authorization)）。
- **端点清单**（来自文档中心目录）：
  - 搜索类：知乎搜索、全网搜索、直答
  - 热榜
  - 问题发现：问题推荐、问题回答
  - 创作能力：我的创作全文、我的创作评论、账号创作数据、单篇创作数据
  - 知识库：列表、内容列表、文件上传、检索
  - 小工具：PDF 解析、PPT 生成
  - 知乎用户数据（OAuth）：用户的内容、用户的关注、用户的收藏、收藏夹列表、收藏夹内容
  - 另有 Zhihu CLI、知乎 MCP、额度查询 API
- **知乎搜索 API**（[文档](https://developer.zhihu.com/docs?key=zhihu_search)）：`GET https://developer.zhihu.com/api/v1/content/zhihu_search`
  - 参数：`Query`（必填）；`Count` 默认 10，最大 10；`SortBy` 可选 `CommentCount` / `VoteUpCount` / `EditTime`，支持区间过滤，例如 `VoteUpCount:desc:(100,)` 表示只要赞同数不少于 100 的结果。
  - 返回：`HasMore` **固定为 false**，即每个 query 最多 10 条；`ContentText` 是**内容摘要**；`Url` 带 `utm_medium=openapi_platform` 溯源参数。还返回 `VoteUpCount`、`CommentCount`、`AuthorName`、`AuthorBadgeText`、`AuthorityLevel`（权威等级）、`EditTime`、`CommentInfoList`（精选评论）和 `RankingScore`。
- **热榜 API**（[文档](https://developer.zhihu.com/docs?key=hot_list)）：`GET …/api/v1/content/hot_list`，`Limit` 最大 30。返回 Title、Url、ThumbnailUrl、Summary，只包含问题和文章两类。
- **MCP**（[文档](https://developer.zhihu.com/docs?key=unified_mcp)）：服务地址 `https://developer.zhihu.com/api/mcp/v1`。Claude Code 的接入命令：`claude mcp add --transport http --scope user --header "Authorization: Bearer <access_secret>" zhihu https://developer.zhihu.com/api/mcp/v1`。文档列出的能力是：搜索知乎和全网、看热榜、知乎直答。
- 「问题回答 API」的返回字段，以及它能否给出回答全文，**本次没有读到**。
