# 信源获取：即刻（okjike.com / 即刻 App）

调研日期：2026-10-11　｜　调研环境：Claude Code（WebSearch / WebFetch / curl / Python / 无头 Chromium），出口代理 `http://127.0.0.1:7897`
本次预算：搜索 + 抓取 + 实测共 22 次（上限 25）。WebSearch 5 次、WebFetch 1 次、命令行网络调用 16 次。

## 一句话结论

不登录就能稳定拿到即刻内容的是 `m.okjike.com` 分享页（圈子、用户、单帖三种页面）。页面是 Next.js 服务端渲染，`<script id="__NEXT_DATA__">` 里带完整 JSON：点赞、评论、转发、分享数、精选标记、作者认证、粉丝数，单帖页还带 5 条评论。缺点是每页只有 10 条、不能翻页，即刻站内也搜不了。所以首选做法是三步：固定圈子和用户名单，每天 curl 分享页解析 JSON；用 WebSearch `site:m.okjike.com 关键词` 找内容；再回抓单帖详情。翻页、站内搜索、完整评论只能走登录态 API，这一步要用户自己用即刻 App 扫码拿 token。

### T10 开源 SDK 文档：能否匿名访问（结论：都需要登录）
- jike-sdk README 要求配置 `accessToken` 和私有 endpoint 参数，登录方式是短信、手机号加密码。
- jike-skill 的 `references/api.md` 写的是：Base URL `https://api.ruguoapp.com`；请求头 `Origin: https://web.okjike.com`；需要登录的接口带 `x-jike-access-token`；刷新 token 用 `POST /app_auth_tokens.refresh`，请求头带 `x-jike-refresh-token`；用户动态 `POST /1.0/personalUpdate/single` 每页约 25 条；搜索用 `POST /1.0/search/integrate`。
- myartings/jikeskill 的 MCP 工具以 `get_login_qrcode` / `wait_for_login` 为前提。
- 三者都**没有匿名模式**。

### 两个实用发现
1. **帖子 ID 里能读出发帖时间**。即刻帖子 ID 是 24 位十六进制（MongoDB ObjectId），前 8 位就是 Unix 秒。例如 `6aca487e…` 解出 2026-10-10，与 JSON 里的 `createdAt=2026-10-10T14:15:26Z` 一致。搜索结果不打开就能按日期过滤。
2. **分享链接里的 `?s=` 参数是分享者信息**。它是 base64 编码的 JSON，例如 `eyJ1Ijoi…` 解出 `{"u":"59e56dec35335f00158a7a57","d":1}`，入库前应该删掉。

## 推荐方案

### 首选：零成本、可自动化、低风险（不需要登录）
1. **固定监控名单**：维护一份圈子 ID 和用户 username 白名单，ID 从分享链接里取。每天 curl 一次：
   - `https://m.okjike.com/topics/{topicId}`
   - `https://m.okjike.com/users/{username}`

   用正则取出 `<script id="__NEXT_DATA__">` 里的 JSON，从 `props.pageProps.posts` 拿帖子，按帖子 `id` 去重、逐日累积。单次只有 10 条，要靠抓取频率来覆盖。AI探索站这 10 条覆盖了 2026-10-03 到 10-11。
2. **关键词发现**：用 Claude 内置 WebSearch 搜 `site:m.okjike.com <关键词>`，不要用 curl 抓 Bing。从搜到的 `originalPosts/{id}` 先用 ID 前 8 位解出日期过滤时效，再 curl 单帖页取计数、作者认证和 5 条评论。
3. **质量排序**：用上一节的字段打分（建议做法，未经实测验证）：`isFeatured`、作者 `isVerified`、`likeCount` / `commentCount`、`type=ORIGINAL_POST`、`withAIGC=False`。
4. **抓取规范**：每次请求间隔 1 秒以上（15 次连发没被限，但官方没有公开限额）；删掉链接里的 `?s=`；**不要用 WebFetch 读计数**（T6 出现了误读）。
5. **兜底**：分享页结构变了，或者想要 RSS 格式时，可以自建 RSSHub（不需要 token，路由 `/jike/topic/:id`、`/jike/topic/text/:id`、`/jike/user/:id`）。它和直接 curl 的数据量一样，只是多一层封装。

### 备选
- **第三方 RSSHub 公共实例**：例如 rsshub.ktachibana.party（实测可用）。它没有 SLA，只适合临时用。rsshub.app 当天被 Cloudflare 拦截。
- **登录态 API**（翻页、站内搜索、圈子热门 / 最新、完整评论）：用 [MidnightDarling/jike-skill](https://github.com/MidnightDarling/jike-skill)（`pip install jike-skill`，再 `jike auth` 扫码），或 [open-jike/jike-sdk](https://github.com/open-jike/jike-sdk)。属于逆向接口，可能失效；请求绑定个人账号，有被风控的风险。本次没有用账号实测。

### 只能由用户手动做的事
- **用即刻 App 扫码登录**，拿到 `access_token` / `refresh_token`。只有登录态方案需要这一步；自动化最多能把二维码显示出来，扫码必须本人操作。
- **决定是否用自己的账号跑逆向接口**，并承担账号风险。即刻没有公开 API，也没有公开频率规则；jike-sdk README 写明「本项目仅供学习交流使用」「不再积极维护」。
- （可选）**提供想长期跟踪的圈子和用户名单**，作为首选方案的白名单起点。

### 未核实或没覆盖的部分
- 即刻用户协议里关于抓取和转载的条款没有查原文，本文件不做判断。
- 新版网页版（搜索结果提到 web-next.okjike.com 公测，公告帖 [66ea433e…](https://m.okjike.com/originalPosts/66ea433ed4cfe34b483e3f7c) 按 ID 解出 2024-09-18）的现状没有核实。
- `isFeatured`、`highlightedPersonalUpdates` 的确切含义是按字段名推断的，没有官方说明。
