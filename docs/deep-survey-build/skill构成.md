# deep-survey 是怎么搭起来的

> 当前流程：2026-10-14 质量优先改造。研究员与独立主笔分开，理解与写作保持连续。设计依据见 [设计理念](设计理念.md)，现行质量标准见 [报告 policy](../../skills/deep-survey/references/report-quality-policy.md)。历史流程图不代表现行规则。

## 1. 按问题选择流程

| 深度 | 路径 | 适用 |
|---|---|---|
| 聚焦调研，默认 | 明确问题 → 一到两人采集归纳 → 独立主笔综合成稿 → 一次冷读 → 机械交付 | 单对象、有限问题或少数选项比较 |
| 完整专题 | 明确问题 → 分块研究 → 同一主笔短备忘 → 核对后续写 → 一次冷读 → 机械交付 | 系统性行业、公司与复杂机制研究 |

两种流程都由独立主笔读懂材料后写，研究员不兼任。聚焦流程只在计划末尾保留三到五条判断；完整专题必要时用一页备忘梳理论证。篇幅与图表服从问题，零图正常。

## 2. 谁读什么

| 角色 | 指南 | 交付 |
|---|---|---|
| 主会话 | SKILL.md、what-to-look-for.md | 计划、协调、检查与交付；不重复写综合稿 |
| 研究员 | researcher.md、自己负责的证据块 | 一份笔记、关键缺口、检索用量 |
| 独立主笔 | writer.md、全部研究笔记与质量 policy | 自定论点和结构，由同一主笔完成报告及修改 |
| 独立审读员 | reviewer.md、报告和确认单 | 一次会影响理解与决定的审读意见 |
| 独立质量评审（版本验收） | 匿名报告、用户问题、冻结 policy、原文 | 八维分数、事实核验账本、严重问题与暂定标记；不看成本与版本 |

子 agent 默认只接收必要任务书和路径，不继承整段历史。主会话按完成或缺口消息推进，不轮询文件大小。模型配置跟随会话，机械转换交脚本。

## 3. 收束与来源

全任务共享查询与抓取预算：聚焦调研默认 30 次，专题 60 次，主笔补查也计入。核心问题有依据、比较口径一致、剩余未知不改变建议时提前停；达到预算时重新判断，扩展仅限可定位且会改变结论的关键缺口，记录追加范围与停止点。预算不是数量目标或自动停止线，未查到要说明影响，不能猜。

笔记、CSV 用 URL 稳定关联。`build_source_table.py` 保留已有编号并追加新来源；`render_table.py --sources ...` 仅在输出时映射编号；`renumber_sources.py` 最终统一编号和链接、同步来源 JSON/Markdown、迁移旧 CSV 数字并保存原件。`check_report.py` 除存在性检查外，还检查正文链接、来源列表和 JSON 是否指向同一页面。

## 4. 文件与质量边界

Skill 本体保留 SKILL.md、角色/清单参考、网页采集说明、质量 policy、主题资产与脚本，没有新增运行框架。`fetch_page.py` 保留原文、结构化数据与失败状态；`measure_run.py` 按显式日志范围去重统计。可选通道只在相关且可用时尝试，失败后共享状态；图表依赖不可用就用文字或表格。

独立冷读检查可读性、答案覆盖和结论一致性，不重新启动一轮联网研究。版本验收的两名质量评审另外核原文、逐维评分，保留关键未核事实与分歧。机械检查不能替代事实核验。运行日志有 token 时区分缓存与非缓存，不能把缓存总量当成浪费或账单。
