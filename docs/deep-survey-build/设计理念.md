# deep-survey 设计理念

> 这是 deep-survey 唯一的设计理念文档：记录这个 skill 为什么长成现在这样。
> 用途：用户自行调整时的依据；对外介绍时的素材；以后改写成 README 的底稿。
> 结构：1 设计理念 · 2 参考内容 · 3 改动记录。每条理念标注来源：**用户倾向**（用户明确说过）、**调研采纳**（从参考内容里学来）、**迭代沉淀**（跑真实用例后改出来的）。
> 最后更新：2026-10-14（质量优先、独立主笔、通用采集与版本化评估）。

---

## 1. 设计理念

### 1.0d 当前执行原则（2026-10-14 后续）

用户指出减 token 不是核心目的。研究员做一次信息采集与归纳，独立主笔决定如何使用材料；理解与写作继续由同一主笔完成。协调者不重复综合，不能为了少一个上下文合并研究员与主笔。

- **工具问题交给通用工具。** 17 次官网操作包含初次读取、重复/失败、成功原文采集和关联资源读取，不等于 17 次失败。统一采集器处理 HTML、内嵌 JSON、公开 JS/GET 数据，保留原文与缺口；单纯正文提取不够，也不承诺所有网站可静态解析。
- **质量标准先于改造结果。** 唯一现行标准为 `references/report-quality-policy.md`。版本、报告及证据冻结，独立评审不知道流程与用量；保留原始分数、证据核验和分歧，不为新版本改锚点。
- **质量和效率分开测。** 真实性、覆盖、综合解释、有用性、密度、表达、来源权威和不确定性分别打分。严重错误不被平均分抵消；token、时间、工具请求属于独立诊断账本。
- **验证层次不混淆。** 脚本测试、真实网页采集、固定材料写作回放和新课题端到端运行各自回答不同问题。AIE 仅作回归样本，不将“参会/现在购票”的具体判断固化进通用 Skill。

来源：用户 2026-10-14 五点修正。此节取代下方历史方案中“主会话兼主笔”的安排，其余有益的事件驱动、按需图表、引用自动化继续保留。

### 1.0c 首轮执行成本方案（2026-10-14，历史）

AIE 参会决策实际用了 51 分 15 秒。问题既有固定多角色、长备忘与串行门禁，也有执行上的频繁轮询、整段历史继承和图表补做。用户已确认按诊断调整。

- **按决定的复杂度分配投入。** 具体决策默认紧凑流程，主会话兼主笔，一到两名研究员、一次冷读；完整专题保留同一主笔的短备忘核对。保留理解连续性，减少重复交接。
- **每次追加查证都要有决策价值。** 全任务共享预算，核心问题足以判断即停；剩余未知如实写，重要缺口才允许一批有上限的补查。此决定更新 10-12 的“不分模式、不设搜索预算”。
- **上下文和文档只保留必要内容。** 子 agent 默认不继承整段历史；按完成事件推进；发现写一次，通过路径引用；机械工作用脚本。
- **制作服务于理解。** 图表按需，零图正常，依赖不可用降级；来源 URL 稳定关联，由脚本统一生成编号、链接及来源表。

来源：用户倾向（2026-10-14“好，按这个调整”）与真实运行诊断。性能改进须经后续同质量实跑验证，不把调用结构变化直接换算成节省比例。


### 1.0b v8 起的补充原则（2026-10-12）

v7 的两个目标不变，加三条：

1. **结构在研究之后定。** 计划只定问题、研究角度与分工；报告的论点、大纲、各章形式由新增的「综合者」读完全部材料后决定，写进 `30-synthesis.md`。每份报告有自己的结构、写法和语气，两份课题的报告不应长得一样。
2. **写作约束分两层：底线与倾向。** 底线（开头没答案、问题没回答、机制只被断言、数字无来源、措辞超依据、不落行动、重复、空话、噪音、图表误导）触发即返工；倾向（结构、段落、标题、数字、机制、结论、形式按内容）是偏向的方向，有更好的理由可以不照做。不规定章节数、段落长度、每章放什么表；不用范文约束（用户 10-12 决定：规范不限死，每篇要有灵魂）。
3. **脚本只查机械项。** 引用、固定部分、图片、表格、凭证。写法由写作指南与审读员判断。审读改为冷读：审读员只读报告，用自己的话复述结论与机制，协调者拿它和综合备忘对照，对不上就是写作失败。

规则准入：以后往写作指南加规定前过三问——不写这条，三份报告里会有两份违反吗；能被脚本机械判定且误报率可忽略吗；约束的是实质还是形态。形态类不进规则。

- 来源：用户倾向（2026-10-12：「约束太高……没有办法发散性地写一个让人看的舒服的报告」「不希望用范文约束，而是规范：倾向和底线，不限死，每篇都有灵魂」）+ 迭代沉淀（秘塔对照：deep-survey 有素材没用、缺类比与用途全景，根因是没有综合步骤）；论证见 `1_方案/v8从零设计与重构判断-2026-10-12.md`

### 1.0 v7 起的总原则（2026-10-12）

skill 只做两件事：**教会报告员写好一份回答用户问题的报告**，**约束流程让研究员把每章的材料找齐**。调研的用途是快速搜集信息、给出尽可能可信的结果，不为单个数字花大量 token。下面 1.1—1.16 中与此冲突的条目已标「v7 推翻」。

- 来源：用户倾向（2026-10-12：「这个 skill 应该有两个目标：如何写好一篇调研报告的说明、流程上的约束」；「证据没那么重要……不要为了一些数字浪费大量 token，所以不要证据审查」）


### 1.1 写给外行，读完既懂行业、又能做决定

读者设定为**从没接触过这个领域的聪明人**。他不缺智商，缺背景。报告要让他循序渐进地建立认识，读完能复述关键知识，并能决定进不进、做什么。

- 来源：用户倾向（2026-10-10 否决 v1：「要想象这是一份给从没接触过这个行业的人看的报告」；选定「既能决策又懂行业」）

### 1.2 三个效果目标

1. **清晰易读**：结构一眼能懂，每段只讲一件事。
2. **真实有用**：信息可信，按认知顺序展开，读者能带走关键知识。
3. **适合传播**：没有阅读压力，愿意转给别人。

- 来源：用户倾向（2026-10-10 读 v3 后提出）

### 1.3 篇幅跟着信息走，压力靠分层阅读解决

「高密度」指每句话的信息量，不是总字数短。v2 把高密度做成了短，被评「信息不够」。

篇幅不设上限，但必须能分层读：

| 层 | 读什么 | 用时 |
|---|---|---|
| 1 | 标题 + 一分钟看懂 | 1 分钟 |
| 2 | 判断句小标题 + 加粗首句 + 图表 | 10 分钟 |
| 3 | 全文 | 30 分钟 |

只读第 2 层也要能讲完整个故事。

- 来源：用户倾向（「篇幅不限」「没有阅读压力」）+ 迭代沉淀（v2、v3 两次反馈）

### 1.4 台前好读，幕后可审计

> **v7 推翻「幕后可审计」**：不再做对抗、逐条核查与审计材料；台前好读保留。防错前置为研究员写笔记时的纪律（每个数字附原文链接、不从图表读数、冲突两说并列、单一来源写明）。

幕后照常做严格的事：对抗分析、逐条核查、置信度定级、打回记录、来源可达性。台前只呈现过了核查的结论。

- 正文**不贴【高 / 中 / 低】标签**；可信度用文字交代：官方披露直接写，第三方写「据 X 估算」，推测写「推测」并给依据。
- 对抗表、打回表、可达性备注**留在 research_notes**，不进报告。

- 来源：用户倾向（「不要增加【中】这种文字」）+ 迭代沉淀（v1 被评「不是给人看的报告」）

### 1.5 报告质量的根源是信息质量

> **v7 调整**：信息质量仍是根源，但「够不够」改为按章判断（笔记末尾的「够不够」），不再按来源数、证据族数计；不设搜索次数预算，按停止条件收工。

写得再好，信息不够也没用。所以搜集要有计划、有门槛、能度量：

1. 研究前写**信息需求清单**：每个模块需要什么信息、最低证据量多少。
2. 研究后过**覆盖率门禁**：没达标就定向补研，最多三轮。
3. 三轮仍不够，写进「还不知道的」，列出试过的渠道。
4. 出一张覆盖率报表：来源数、独立证据族数、一手占比、最新日期。
5. 脚本只数数量，质量靠人看：只有搜索摘要的条目不算数；协调者抽查每个「达标」背后的证据是否满足样本量、时效、一手的要求。v4 实测时，「国内用户画像」按数量达标，背后却只有 4 个个案访谈。

6. **信源分层，先查高信噪比的**：先查用户自己长期筛过的信息流（Info2Action 召回），再走中文平台的专用通道（知乎官方接口、即刻与 36 氪的移动端页面），最后才是通用网页搜索。每个课题结束把好用和踩坑的来源写回固定信源库。v4 的 281 条来源里没有一条来自用户的信息流，而只读召回「AI陪伴」「情感陪伴」两个词就得到 118 条，其中 71 条是长文。
7. **判断被拦看正文，不看状态码**：36 氪的拦截页返回 200，即刻计数会被 WebFetch 读错。

- 来源：用户倾向（「决定报告质量的根源是搜集的信息的质量」；建固定信源库、先查自有信息流）+ 迭代沉淀（v3 国内用户只有 4 人的访谈；2026-10-11 中文平台取数实测）

### 1.6 查不到就说查不到，绝不估算

没有来源的数字不进正文。缺口写进「还不知道的」，它同时是下一轮调研的问题清单。

- 来源：调研采纳（「数据宪法：查不到就标未查到，禁止估算」；daymade 的 Information Black Box）+ 用户倾向（保留「还不知道的」，沿用其历史文档的「存疑 / 待查」思路）

### 1.7 生成与审查分离

> **v7 推翻**：删对抗分析员、验证者、终稿核查、反例名单去处、论证地图只用通过表。保留一名审读员，只看是否回答了问题、一分钟看懂是否关键、外行能否读懂，不核数字。代价已知：Jev 课题核查打回 53 条中的 18 条，其中有工具从图表上「读」出原文没有的数字这类系统性错误——改由「不从图表读数」等纪律防。

写结论的人不审自己的结论：

- **对抗分析员**专门找反证、替代解释、改变判断的条件。
- **验证者**逐条打开原文，确认「来源确实这么说」。
- 并列数字要用来源自己的占比、合计反算归属。run-1 中，一家媒体把两款产品的收入写反了。
- **来源说了，不等于撑得住结论**：验证者还要核口径。合并口径当子类证据、期间或分母不同还直接比、大公司规模的数当成读者的数，都打回。
- **反例必须有去处**：对抗分析交一份反例名单，每一项都要出现在报告里，脚本逐个比对。v4 丢了 Nomi、Kindroid 两个反例。
- **写完再核一次**：报告写完后，验证者专核分析一节和每张数据图。分析是报告员新写的推理，图在报告员手里生成，原来没人核。

- 来源：调研采纳（Apodex 的 Statement Review、对抗分析员角色）+ 迭代沉淀（对抗分析员发现中国新规已正式施行，验证者发现数字写反；2026-10-11 两份独立审查共 76 条意见）

### 1.8 图文分工：看读者要对信息做什么

| 读者要做的事 | 用什么 |
|---|---|
| 比较、看形状、看结构 | 图或表 |
| 跟着推理走 | 文字 |
| 感受处境 | 引语卡 |

- 观念也可以画：机制循环画成环更好懂。
- 没有数据的地方不画数据图，否则会制造假精确。
- 数据图从数据文件渲染，每个数值可追溯；生图模型只做封面和示意，不画任何带数字的图。
- 产品调研要有产品截图；官网常拦截自动截图，优先应用商店页。
- 所有图都输出成图片嵌进 md：VS Code 默认预览不渲染 Mermaid，图片在哪都能看。
- 图表风格不写死：颜色、字体、形状都放进主题文件；不设默认，每份报告按文档风格自选一套，蓝色系、橙色系优先，全报告统一（数据图、结构图、导引图同一套）。三个家族：干净信息图、电子杂志、瑞士国际主义，后两者的配色直接取自 guizang-ppt-skill。
- 数据图只用齐平数字的字体，旧式数字（Georgia、Didot）会让「80」看着像「8o」。

- 来源：用户倾向（「传递数据适合图形化」）+ 迭代沉淀（v3 全文只有 1 张图；v4 实测 Mermaid 与截图的兼容性）

### 1.9 竞品用固定维度的档案表

每个维度一张表，每家填同样的字段，例如价格表要写档位、价格、权益、免费版限制、来源、日期。研究员按字段收数据，表和图从数据渲染。

- 来源：用户倾向（「每个竞品调研都要有清晰的维度和足量的信息」）+ 调研采纳（weizhena 的「对象 × 字段」矩阵、haines 的固定模板档案）

### 1.10 有分析，不只有事实

事实章节之后要有分析：归纳、对比归因、机制模型、反直觉、二阶推演。每条洞见注明「依据见第 X 节」，让读者能顺着前文理解；和事实分开写，让读者分得清查到的和推出来的。

- 来源：用户倾向（「好的调研报告应该有分析模块……能够给到读者足够的洞见」）

### 1.10a 开头一张导引图，结尾一份推荐阅读

- 「一分钟看懂」里放一张导引图：每个模块一张卡，编号、短标题、一句核心判断、3—5 个关键词，一眼看出报告有哪些模块、每块讲什么。
- 文末「推荐阅读」：5—10 条好信源，分入门、深入、一手三组，每条写推荐原因。读者想继续深挖时知道先读什么。

- 来源：用户倾向（2026-10-10）

### 1.10b 报告的章节跟着读者的问题走

章节不再按一套骨架锁死。每类对象给一套默认大纲（AI 工具：是什么 → 输入输出 → 怎么实现 → 效果与边界 → 格局 → 接入成本 → 集成判断 → 还不知道的；产品、行业、公司沿用原顺序），S2 时协调者按确认单里的问题增删章节，写进计划，和分工一起请用户批准。检查脚本只管固定头尾，以及报告是否按批准的大纲写。

骨架原本照第一个真实课题（AI 陪伴，行业类）定死；第二个课题 Jev 是 AI 模型，用户问「是什么、怎么实现、有什么用」，输入输出被挤成第一节里的一个小节，用户读完说「没有专门的章节解释输入输出」。

- 来源：迭代沉淀（Jev 调研）+ 用户倾向（2026-10-12 选「类型默认大纲 + 计划里确认」）

### 1.11 写法规则

| 规则 | 来源 |
|---|---|
| 小标题写成判断句 | 调研采纳（a16z、晚点） |
| 「一分钟看懂」= 一句话定义 + 关键事实表（行由对象类型规定，末行结论）+ 导引图；不写反差、不用「对你」「带走的知识」这类角色标签 | 用户倾向（2026-10-12 读 Jev 报告：「应该有最关键的信息，比如输入输出、效果，而不是一些文字」）；取代 v3—v5 的「定义 + 反差 + 5—7 条要点」 |
| 段落不超过 3 句；每个小节 = 加粗结论 + 证据要点 | 用户倾向（「大量整段文字，读起来很累」） |
| 钱写成可复算的账：参数、假设、算式、结果 | 调研采纳（晚点、36 氪智能涌现） |
| 每个关键数字配参照：和对手比、和去年比、和普通产品比 | 调研采纳（a16z） |
| 一个主线案例贯穿，2—4 个对照各证一个变量 | 调研采纳（晚点） |
| 结论写成选项 + 代价 + 先验证什么 + 会改变判断的信号 | 调研采纳（晚点 AI 应用稿） |
| 宣传口径和实测口径并列 | 调研采纳（36 氪智能涌现） |
| 论断加证据、数字贴结论、不写过渡废话 | 用户倾向（知识整理 SOP、事实句写作偏好） |

### 1.12 尊重用户的控制权

- 开工前的确认单一轮最多 3 个问题，用户给了材料就先从材料里提取。
- 调研计划先给用户批准再跑。
- 报告落点**每次交付前询问**，不写死在 skill 里；默认建议 `知识/调研/` 的现有分类。
- 已有同名文件不覆盖。

- 来源：调研采纳（borghei 的 Clarify First；AIsa「先列清单、批准再执行」）+ 用户倾向（落点每次问）

### 1.13 成本如实说，默认轻量

完整模式（每维度一名研究员 + 对抗 + 验证 + 报告员）约是不用 skill 的 15—20 倍 token。默认用轻量模式；要给别人看、要据此花钱时再用完整模式。

- 来源：迭代沉淀（run-1 实测约 17 倍）

### 1.14 协调者只调度，不亲自搜索和组装

主会话只做确认单、计划、派工、终审、交付。搜索结果和几百行笔记会把主会话的上下文填满。子 agent 结束时只回报数量，不回报内容，避免协调者在核查前采信未核的数字。

- 来源：调研采纳（Anthropic 内置 deep-research 的协调者设计）+ 迭代沉淀（run-1 组装阶段）

### 1.15 可扩展

对象类型一类一个框架文件（产品、行业、公司、AI 工具、通用）。新增类型只加文件，不改 SKILL.md 主体。

- 来源：用户倾向（「再增加一个 AI 工具，支持以后扩展」）

### 1.15a 写给具体的读者

读完知道不该做什么还不够，要知道该做什么：

- 确认单只多问 3 件事：读者是谁、读完要做什么决定、能投入多少。
- 结论表加通过或放弃线、周期、预算三列；成本账按读者的规模算，大公司的成本只作参照。
- ~~末尾放「留给你的问题」~~：2026-10-12 取消。Jev 报告里报告员从笔记缺口凑出五条，用户评为「对我没有任何用」。要亲自验证的事写进结论表的「先验证什么」。
- 写稿前协调者先画论证地图：3—5 个核心判断，各配证据、反证、对读者的含义。报告员照着写，不按章节堆事实。

- 来源：迭代沉淀（v4 独立审查：结论第七节只有 27 行，「获客」全文出现 1 次、「备案」0 次）+ 用户决定（2026-10-11：读者画像只问几个简单问题；一手研究不加，问题放末尾）

### 1.16 不做什么

| 不做 | 为什么 |
|---|---|
| 正文贴置信度标签 | 读着像噪音（v1） |
| 把审计材料塞进报告 | 挤占阅读路径（v1） |
