# 通用改造与报告质量验证

本轮目标是改善采集、角色分工与报告质量，并建立可重复的独立评估；不以减 token 作为首要目标。Skill、policy 和通用脚本已修改，三份报告已完成独立盲评；新初稿暴露的问题已经定向修订并经两位独立评审复核。本轮实施与评估完成，不等于已经证明新版整体质量更高。

## 改了什么

- 研究员做一次采集归纳，独立主笔决定论点、结构和材料用途，并连续完成写作与修订。协调者不重复综合；聚焦调研与完整专题都保持角色独立。
- `fetch_page.py` 统一公开 HTML、内嵌 JSON、应用脚本与声明式 GET 数据提取，保留原文、哈希、时间和提取方法；未取得内容明确标注。借鉴 Info2Action 的请求、正文提取和错误识别，但不复制其 5,000 字预览裁剪，也不依赖其服务或凭证。
- `measure_run.py` 显式限定日志、主 turn、子任务和时间，按响应去重，单列缓存与非缓存，不把累计上下文快照相加。
- [质量 policy v1.0.0](../../../../skills/deep-survey/references/report-quality-policy.md) 在评分前冻结。八维加权；关键错误不能被总分抵消；抓不到原文是未核，不直接判真假；耗时与 token 不计质量分。
- 初始检索预算保留为重新判断的节点，取消“最多追加三分之一”的硬停止线。必要且可定位的核验继续，重复背景材料收束。

## 17 次官网操作的具体原因

历史 17 次是异质工具操作：3 次初读、4 次重复或失败（锚点重复、浏览器超时、两次沙箱 DNS 失败）、3 次成功原始 HTML 读取、7 次关联资源/API 读取。问题不只是网络不通，也包括正文工具没有暴露公开应用数据、同一资源重复定位以及临时解析。

所以不应描述成“17 次都抓不到”，也不能用新脚本 HTTP 次数与旧工具操作数直接算降幅。新脚本减少人工编排并保留明确状态，不能保证任意网站无需浏览器。

## 定向修订结果

修订稿 R64 补充首次术语解释、人物的组织与角色、各类核实问题对应的既有公开入口，并合并重复边界说明；没有新增来源。两位评审独立对照修订差异和原始证据，三类问题均判为 resolved，未发现身份扩大、入口职责扩大或必要限定丢失。详见 [复核三](correction-judge-three.md)、[复核四](correction-judge-four.md)。

这是知晓修订目标的定向复核，不是新一轮盲评，没有给 R64 新的整体分数。R63 的 86.9 分和未通过质量未退化检查的结论不变；R64 的已知问题已解决，整体质量优势仍未建立。修订稿机械检查为 0 错误、0 警告；单次冷读曾未发现这些问题，说明机械检查和冷读均不能替代正式独立质量评估。

修订后的读者报告：[AIE 上海报告](<工作区>/知识/调研/AIE上海2026参会决策-2026-10-14-3/AIE上海2026-参会决策报告.md)。原初稿另外冻结保存；policy、历史报告和原始评分均未改写。

## 工具验证

详见 [fetch-validation.json](fetch-validation.json)。三个 AIE 入口真实只读采集用了 13 次 HTTP 传输尝试，分布为官网 4、Luma 1、国内售票 8；确认取得 21 条题目和摘要、默认/渠道价格及取消/延期条款。`ok` 只表示提取路径成功，覆盖度仍为 `not_assessed`。

额外测试 Vercel 普通技术文章时，发现正文已经完整却继续下载应用脚本，导致共享上限触发并返回 partial。修复为可解释的自动模式：已有丰富 JSON 或足量 article 正文时保留停止原因，缺关键字段可显式继续。用同批真实原文回放，四个入口全部 ok，14 次离线读取、0 次联网；Vercel 单独只读 1 份文件。这是修复后回放，不能冒充另一次实时测量。

计数区分入口尝试、HTTP 传输尝试（含重定向）与证据读取。DNS 预校验失败不算发起 HTTP；离线回放不算联网。原有 31 项与新增 14 项脚本测试通过；新增覆盖动态证据、短价格页、空壳/拦截、资源上限、重定向计数、二进制状态、快照时间/哈希及 token 范围与去重。Skill 基本校验和 git diff 空白检查通过。
