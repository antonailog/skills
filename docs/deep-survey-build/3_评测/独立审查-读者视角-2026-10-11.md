- 被审对象：`知识/调研/AI陪伴型产品赛道-2026-10-10/AI陪伴型产品赛道-2026-10-10.md`（713 行，正文约 1.15 万汉字，18 张表，25 张图）

## 一句话总评

巨头的处境讲得清楚，读完足够做出「不正面做泛陪伴」的决定；但「做什么、在哪个市场做、要花多少钱和时间、用户从哪来」都答不了，核心的成本账和「陪伴难赚钱」的几条论据还混用了口径。

## 最影响阅读和决策的 5 个问题（按严重程度排序）

### 1. 读完知道不该做什么，不知道该做什么：独立开发者最需要的信息基本缺席

- **问题**：报告的样本全是巨头和大厂产品，跟独立开发者处境接近的产品只点了名、没有展开。获客、分发、上线门槛、启动资金和时间这些问题，正文里没有，第八节的「还不知道的」里也没有列。
- **证据**：
  - 第 3 行把范围定为 Character.AI、Replika、Talkie / 星野、猫箱、Pi，五家都是融了上亿美元的公司或者大厂产品。
  - 第 70 行点名 Candy、CrushOn、Janitor AI、Spicychat 进了 a16z 网页榜前 50，第 136 行说 PolyBuzz 反超了 Talkie。这几家最可能是小团队，但全文没有一句话写它们是谁做的、团队几个人、靠什么获客、怎么收钱。
  - 「获客」全文只出现 1 次（第 557 行，在信号清单里）。「分发」只出现在第六节的标题里（第 465 行），五个分析小节都没有讨论。「备案」一次都没出现。
  - 第八节的 9 个待查问题（第 564–572 行）问的是性别比例、Replika 收入、安卓渠道这类分析师关心的事，没有一条问小团队案例、获客成本、合规成本或启动周期。
  - 第七节的选项表（第 536–543 行）只写到「先验证什么」，没写怎么验证、要几周、要花多少钱。
- **建议**：加一节「小团队样本」。从报告自己点过名的网页产品里选 3–5 家，写清团队规模、上线时间、流量、收费方式和获客渠道；实在查不到，就把「查不到」写进第八节。在选项表后面加一张「从零到验证」的门槛表：MVP 要几个月，1 千和 1 万日活时每月的推理与审核成本，年龄验证、法务这类一次性成本，主要获客渠道。第八节补上这些读者真正关心的未知项。

### 2. 成本账用的参数读者拿不到，没法算自己的账

- **问题**：第四节的核心参数「每小时不到 1 美分」，是 Character.AI 用自研模型、每秒处理 2 万次请求的规模下做到的成本，个人开发者拿不到。「商业 API 贵 13.5 倍」用的是 2024 年的价格。真正给读者的底线建议是「开源模型自建或低价推理」，可这一项恰恰没有任何数字。另外，商店分成没有算进去。
- **证据**：
  - 第 342、346 行写参数来自 Character.AI 2024 年的自述，第 425 行写它当时每秒处理约 2 万次请求。
  - 第 340 行的小标题说「自建推理几乎是纯利」，但第 361 行自己承认「只算推理，不含存储、带宽、人员和审核」。
  - 第 496 行说「商业 API 基本做不到」，第 547 行又建议「低价推理」。读者分不清 DeepSeek、Qwen 这类开源模型的 API 算「商业 API」还是「低价推理」。
  - 第 565 行给的补法是「自己上线一周，用日志算」，可读者正是要在上线之前做决定。
  - money-flow.png 画了「应用商店分成」这个节点，但全文没有给比例；unit-economics.png 直接拿 9.99 美元全额当收入。
- **建议**：做一版「独立开发者成本账」。先写明假设：每小时聊多少轮、每轮上下文多少 token。再列 2–3 个开源模型 API 今天的单价（注明查询日期），扣掉 15% 或 30% 的商店分成，算出免费用户和付费用户的比例到多少能打平。如果规则要求不估算，至少给一个可以填数的公式和一个标明「假设」的算例。Character.AI 那组参数降级为「规模化之后的下限参照」。

### 3. 支撑「陪伴难赚钱」的几个关键数字，口径不是陪伴

- **问题**：MiniMax 的「AI 原生产品」除了 Talkie / 星野，还包括视频产品海螺 AI 等。图的副标题写明了这一点，正文却把这个口径的毛利率、付费率、收入增速都当成陪伴产品的证据。买量占比从 2.85 倍降到 23%，大半是分母变了，不是买量效率变了。
- **证据**：
  - minimax-mix.png 的副标题写着「AI 原生产品含 Talkie / 星野、海螺 AI 等，公司不单列陪伴产品」。
  - 一分钟看懂第 3 条（第 13 行）「MiniMax 的 C 端产品毛利率只有个位数」，依据是第 382 行，指的是 AI 原生产品整体。
  - 第 365、371 行的付费率 6.4% 是「MiniMax AI 原生产品 177 万 ÷ 2760 万」。
  - 第 387、392 行「同期 C 端收入反而翻倍」，第 393 行据此推测「前两年的投放没换来留得住的用户」。但同一时期星野月活掉了一半（第 142 行），翻倍更可能来自海螺。
  - 第 555 行的信号「AI 原生产品毛利率超过 20%：陪伴产品的单位经济可以转正」，直接把两个口径画了等号。
  - minimax-marketing.png 的副标题写分母是「当期总收入」，而 2026 年上半年总收入里 63% 是企业服务。我算：2026 年上半年销售开支 2700 万 ÷ AI 原生收入 4260 万 ≈ 63%，不是 23%。分子的口径也换过（「营销费用」换成了「销售及分销开支」）。
- **建议**：能用 Talkie / 星野单列数字的地方一律换掉（第 103、133 行已有 1875 万、1945.8 万这类单列数）。只能用 AI 原生口径的地方，在正文里注明「含海螺 AI，不是纯陪伴」，同时把一分钟看懂第 3 条的语气降下来。买量占比改用 AI 原生收入做分母重算，或者删掉「降到 23%」这个说法和第 393 行的推测。

### 4. 标题和摘要里有几条说法被正文自己的数据推翻，或者建立在最弱的数字上

- **问题**：一分钟看懂和小标题是读者最可能只看的部分，这里恰好集中了几处夸大或自相矛盾。

### 5. 篇幅和版式没有服务决策：决策内容在 75% 处，公司故事讲了三遍，手机上图和表都读不动

## 二、结构

### S1. 决策内容排得太靠后，一分钟看懂里的行动建议太抽象

- **问题**：读者是来做决定的，选项表却在第 532 行，在全文 75% 的位置。一分钟看懂里唯一的行动条（第 15 行）是「从成年人的具体场景切入，用便宜模型、按用量收费」，没有点出任何一个具体选项。
- **证据**：第 15、532–549 行。
- **建议**：在一分钟看懂下面加 3 行「如果你是独立开发者」，写明推荐哪 1–2 个选项、不推荐什么、第一步验证做什么（第 539 行已经有「20 个目标用户两周」这样的好设计，应该提到前面）。

### S2. 同一批公司的故事讲了两到三遍

## 做得好的 3 点

1. **数字自带口径和限定，读者能自己判断信多少。** 第 91–92 行说明 Appfigures 只含商店内购，并指出「破百万的 33 款约等于前 10%」，所以不能拿来证明长尾能赚钱。第 228 行承认 80 分钟没有分母。第 250 行提醒商店评论的排序可能制造假象。第 270 行写明 App Store 和 Trustpilot 都不是随机样本。第八节每个未知项都写了试过哪些渠道、怎么补。这种做法让我敢用报告里的其他数字（问题 4 列的几处是例外）。
2. **单位经济的推导完全透明，可以拿自己的数重算。** 第 344–349 行的参数表单列一栏「谁给的、什么假设」，第 351–353、375–376 行逐步列出算式，第 379–383 行再用 Talkie / 星野「每个月活每月 0.10 美元」做现实校验。「免费用户才是问题」「收费必须和用量挂钩」这两个结论由此推出，并直接落到第 547–548 行的底线里。参数要换（见问题 2），但这条推导的骨架可以直接留下来用。
3. **价格、付费墙和流失原因可以直接拿来当产品设计参考。** 价格表的「买到什么」一列（第 292–310 行）、免费版限制表（第 314–321 行）、第 326 行「付费墙设在哪」（Replika 把恋人关系锁在付费墙后，国内用「看广告续聊」给不付钱的用户留一条路），加上流失原因表（第 235–240 行）按换人、审核、限额、记忆四类，把中外用户原声对照着放，等于给出了一份付费墙怎么设、哪几个流失触发点要防的清单。第 551–558 行「会改变上面判断的信号」也很具体，每一条都能观察、能证伪。
