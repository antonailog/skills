## 0. Skill 化决策（S0 结论）

已是在用的 skill，本次是重构，不是新建。重构而不是小修的理由：v5、v6 把篇幅花在调度细节和证据审查上，讲「好报告是什么」的只有一行指向，模型因此优化「过检查、照模板」而不是「回答问题」——Jev 报告的三个问题（标签式要点、没有输入输出章、凑出来的「留给你的问题」）都是形式压过内容。用户 10-12 定：skill 只做两件事，教会写好报告、约束流程把材料找齐。

资格条件：☑ 会重复使用 ☑ 容易被路由错（与知识整理、头脑风暴、单篇总结相邻） ☑ 有脚本能省重复劳动（取数、出图、来源编号、报告体检） ☐ 需要治理

## 1. 收料结论（S1）

### 1.1 需求与场景

- **使用者与处境**：用户本人。拿到一个产品、行业、公司或 AI 工具，想**全面**弄懂它，并据此做决定（要不要进、要不要用、要不要接）。
- **现在怎么解决、哪一步最烦**：手工搜、手工写，结构每次重造；v5 用了 skill 以后，报告形式合规但没回答他问的问题，审查环节花掉约四分之一 token。
- **理想产出**：一份 md 报告，开头 1 分钟拿到关键事实；每个问题一章讲透；需要时配图；数字能点回原文。
- **什么算做对了**：读完能说出每个问题的答案、说出它怎么运转、据此做决定；没有编造的数字。

### 1.2 已有决策与约束

| 类别 | 内容 | 可否推翻 |
|---|---|---|
| 目标 | 两件事：写好报告的指导、流程约束 | 不可（10-12） |
| 触发 | 只在明确要深度调研或要报告时用；不分意图强弱 | 不可（10-12） |

| 证据 | 不做证据审查；防错前置成研究员写笔记时的纪律；不为单个数字反复追 | 不可（10-12） |
| 审读 | 保留审读员：不核数字，只看是否回答问题、一分钟看懂是否关键、外行能否读懂 | 不可（10-12） |
| 分工 | 研究员按章分工；确认单、大纲、分工合成一次确认 | 不可（10-12） |

## 2. 设计

### 2.1 要解决的问题

替用户把「全面弄懂一个对象并据此做决定」需要的信息找齐，写成一份他 1 分钟拿到关键事实、30 分钟读懂全貌的报告。

### 2.2 定位与边界

**定位**：一份回答用户问题的调研报告。像一位做足了功课的行业老手给聪明的外行讲课——先把关键事实摊在桌上，再按他问的问题一章一章讲透「它是什么、怎么运转、效果如何、对你意味着什么」，不把一堆资料或一份固定格式的模板甩回给他。

**核心立场**：用户要的是自己那几个问题的答案和足以做决定的理解，不是对象的百科介绍，也不是可审计的证据档案。所以章节跟着问题走、开头给关键事实；可信靠读原文和给链接，不靠事后审查。

**范围**：给定一个对象（或 2—6 个同类对象的对比）和 1—5 个问题，调研并产出一份 md 报告。一次只做一个课题。

**不处理**：

| 不处理什么 | 交给谁 |
|---|---|
| 顺口一问「X 和 Y 哪个好」「X 是什么」 | 直接回答 |
| 单篇文章总结 | 直接回答 |
| 已有材料、只要整理成文，不需要再搜 | 知识整理 SOP / book-to-mindmap |
| 想法阶段的发散 | forge-brainstorm |
| 代码仓库架构分析 | project-learner |
| PRD 与界面评审 | prd-analyzer |
| 企业工商、司法数据 | 查不到，写进「还不知道的」，提示用企查查类接口 |

**≥3 个"很像但不该触发"的 query**：

1. 「Cursor 和 Claude Code 哪个好用？」——顺口比较，没要调研或报告
2. 「帮我总结一下这篇讲 AI 陪伴赛道的文章 https://mp.weixin.qq.com/s/xxxx」——单篇总结
3. 「我已经搜好了 20 篇关于 AI 陪伴的文章放在 知识/调研/陪伴素材/，帮我整理成一份报告，不用再搜了」——有材料只要整理
4. 「我想做个 AI 陪伴产品，帮我头脑风暴一下切入点」——想法阶段
5. 「Replika 的官网和定价页在哪」——一步查询

### 2.3 触发与意图路由

**触发层素材**

- 应触发：「用 /deep-survey 调研一下 jev，我想知道它究竟是什么、如何实现、有什么作用，我希望有一个全面的认知」；「深度调研一下具身智能这个行业」；「出一份 MiniMax 的公司调研报告」；「帮我全面调研一下 AI 耳机这个品类，出个报告」
- near-miss：见 2.2 的 5 条；另：「评估一下 Agent-Reach 能不能替代 twitterapi.io」——没要调研也没要报告，直接分析即可（用户说「出个报告」「调研一下」时才触发）
- 可能抢活的隔壁：anthropic-skills:deep-research（同样会搜会写）、知识整理 SOP

**路由层**：不分流（用户 10-12）。触发条件收窄到「明确要深度调研或要报告」，进来的都按强意图处理，直接走全流程；确认单填不出的项在第 1 步一次确认里问。

### 2.4 输出框架

**固定骨架**（顺序不可改）

1. 标题（一句判断）+ 导读行
2. 一分钟看懂：一句话定义 + 关键事实表（行见计划，末行「结论」）+ 导引图 + 读法导航
3. 正文各章：按计划大纲，第一章「是什么」
4. 还不知道的（最后一章）
5. 推荐阅读（标题带链接）
6. 口径与来源

**必出模块**

| 模块 | 入选条件 | 内部结构 | 对应考点 |
|---|---|---|---|
| 一分钟看懂 | 总是 | 定义 + 事实表 + 导引图 + 读法导航 | K2 |
| 问题章 | 确认单里每个问题至少一章 | 「<章号>、<模块名>：<判断>」+ 加粗结论句 + 证据要点 + 图 | K1 |
| 是什么 | 总是，第一章 | 新旧对比、谁做的、怎么运转 | K3 |
| 结论 / 集成判断 | 读者有要做的决定时（几乎总是） | 选项表：适合谁、代价、先验证什么、通过 / 放弃线、周期、预算 | K5 |
| 还不知道的 | 总是，最后一章 | 问题 / 试过的渠道 / 怎么补 | K6 |
| 推荐阅读 | 总是 | 5—10 条，三组，标题带链接 + 推荐原因 | K7 |
| 口径与来源 | 总是 | 口径一段 + 编号列表 | K4 |

**触发式模块**（大纲里有才写）：输入输出、怎么实现、效果与边界、格局（含第二梯队表）、用户、钱、接入成本、主线案例、分析。各类对象的默认组合写在框架文件里；第 1 步按问题增删。

模块总数：固定 7 + 可选 9。可选模块由大纲选用，单份报告通常 6—8 章。

### 2.5 执行流程

| 步 | 做什么 | 调什么 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|---|---|
| 1 计划 | 填确认单；按框架默认大纲和问题定章节、事实行；按章分工；一次确认 | Read 框架、AskUserQuestion | 用户的话 | `00-plan.md` | 非交互 → 按默认，导读行注明 |
| 2 研究 | 召回自有信息流；研究员并行，每人 1—2 章 | own_feed_recall、Agent × N | `00-plan.md` | `10-<章>.md`、可选对比表 CSV | 信息流不可用 → 跳过；网页被拦 → 研究指南降级链 |
| 3 补缺 | 读每份笔记末尾「够不够」；不够的章补一轮，最多两轮；建来源表 | Agent、build_source_table | 笔记 | `11-<章>.md`、`sources.json` | 两轮后仍缺 → 进「还不知道的」 |
| 4 写作 | 报告员按写作指南写正文、出图，跑检查到零错误 | Agent、出图脚本、check_report | 计划、笔记、来源表 | 报告、`charts/` | 脚本报错 → 报告员修；修不了在交付时说明 |
| 5 审读 | 审读员按审读清单读，报告员改一轮 | Agent × 2 | 报告 | `20-review.md`、改后报告 | — |
| 6 交付 | 重编号；看每张图；问落点；写回信源库 | renumber_sources、make_chart、AskUserQuestion | 报告 | 落盘的报告 | 同名文件加序号，不覆盖 |

研究员停止条件：本章每个问题都有材料，或连续两轮没有新信息；安全上限每人搜索 + 抓取 60 次，只防失控。
