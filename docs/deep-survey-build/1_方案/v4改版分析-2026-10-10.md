## 0. 先对齐目标

用户提出的三个效果，各自靠什么实现、怎么检查：

| 效果 | 具体指什么 | 靠什么实现 | 怎么检查 |
|---|---|---|---|
| 清晰易读 | 结构一眼能懂，每段只讲一件事 | 跳读路径、短段落、图文节奏 | 段落长度、非文字元素间隔（脚本） |
| 真实有用、循序渐进、带得走 | 信息可信；按认知顺序展开；读完能复述关键知识 | 信息需求清单、覆盖门槛、核查、分析模块 | 覆盖率报表；读者复述测试 |
| 适合传播、没有阅读压力 | 3 分钟抓住要点，愿意转给别人 | 一分钟要点、图表、可分享版本 | 只读标题、加粗句和图，能否讲完整个故事 |

**核心洞见：「篇幅不限」和「没有阅读压力」并不矛盾，解法是分层阅读。**

| 层 | 读什么 | 用时 |
|---|---|---|
| 第一层 | 标题 + 一分钟看懂 | 1 分钟 |
| 第二层 | 小标题（判断句）+ 每段加粗首句 + 图表 | 10 分钟 |
| 第三层 | 全文 | 30 分钟 |

写完后的检查标准：只读第二层，故事是否完整。

## 1. 哪些模块适合图形化

### 判据：看读者要对信息做什么

你的直觉「观念用文字、数据用图」大体对。我建议换一个更好用的判据：**看读者要对这块信息做什么动作。**

| 读者要做的事 | 用什么 | 例子 |
|---|---|---|
| 比较 3 个以上对象或数值 | 图或表 | 四家的融资、时长对比 |
| 看形状：趋势、分布、集中度 | 图 | 网页访问逐月下滑 |
| 看结构：流程、因果环、分层、位置 | 图，哪怕内容是「观念」 | 时长→成本→收费→流失的循环 |
| 跟着推理走：有条件、有转折、有例外 | 文字 | 为什么 Google 买人不买公司 |
| 感受：用户的处境和情绪 | 引语卡 | 「她不是她了」 |

两条推论：

- **观念也能画**。机制循环是观念，画成环比写成一段好懂。
- **没有数据的地方不画数据图**。「三类动机」没有占比数据，画饼图会制造假精确，应该用文字加引语。

## 3. 怎么实现

| 方式 | 擅长 | 不擅长 | 在哪能看 | 建议用途 |
|---|---|---|---|---|
| Markdown 表格 | 比较、价格、矩阵 | 形状、趋势 | 任何地方 | 所有表 |
| Mermaid | 流程图、时间线、象限图、简单柱线 | 样式控制弱；新图型（xychart、quadrantChart、sankey）的兼容性需实测 | Obsidian、GitHub；VS Code 需扩展 | 结构图 |
| 脚本出图（matplotlib → SVG / PNG） | 精确、数据驱动、可复现 | 要写代码、要配中文字体 | 图片文件，到处能看 | **所有数据图** |
| 手写 SVG 模板 | 数据卡、单位图、定制时间线 | 每种图要先做模板 | 同上；`rsvg-convert` 可转 PNG | 定制图 |
| HTML 页面（Artifact，配合 dataviz skill） | 交互、深浅色、一个链接就能分享 | 不适合当存档原件 | 浏览器 | 传播版 |
| 飞书文档 + 白板 | 发给别人、可评论 | 写入流程较重 | 飞书 | 传播版（已有 SVG → 白板流水线） |
| codex image_gen | 封面、概念插画 | **任何带数字或文字的图**：会画错，且无法追溯来源 | 图片 | 只做封面和示意 |
| 浏览器截图（gstack / playwright） | 产品界面、定价页 | 需要登录的页面 | 图片 | 产品截图 |

本机已确认：matplotlib 3.10、中文字体（冬青黑体、华文宋体）、`rsvg-convert` 都可用；没有装 Mermaid 命令行工具 `mmdc`。

**推荐组合：**

1. **数据图走「数据文件 → 脚本 → 图片」。** 每个数值带来源编号，存在 `charts/data/*.json`；图下注「来源：[n]」；校验脚本同时检查图的数据。
2. **结构图用 Mermaid。** 渲染不了的退回 SVG。
3. **截图和封面是增强项。** 截图走浏览器；封面走全局 codex 生图规则。
4. **出两个版本。** md 版存档、可审计；传播版（HTML 页面或飞书文档）给别人看。

## 4. 导语为什么写成这样

### 现状

- 第一段 4 句话，塞了 10 个数字、4 个引用编号。
- 第二段一段里讲了三个结论，再加一条建议。
- 「三个问题」像目录：第二个问题里塞了三个子问题。

### 原因，从表象到根因

1. **规则在错的位置生效。** 文风要求「每句至少一个新事实」，报告员在导语也照做，钩子变成了数字堆。导语的任务是让人想读下去，不是信息密度。
2. **默认读者懂行。** 用「Google 带走了创始人」制造反差，但外行不知道这为什么是坏事。反差要有背景才成立。
3. **搬了范本的形式，没搬范本的前提。** 晚点写豆包，读者已经知道豆包，一个反常现象就够。我们的读者连「AI 陪伴」是什么都不知道，开头必须先给一句话定义。
4. **问题是目录换了问号。** 读者真正想问的是「这东西是什么、能赚钱吗、我该不该做」。
5. **v2 的「先看结论」被 v3 删了。** 为学范本改成散文，丢掉了最适合跳读的一层。
6. **引用编号打断节奏。**

**根因：** skill 只规定了「导语三段」的形式，没有定义导语的任务，也没有限制长度、数字个数、术语，更没有「外行能否看懂导语」的检查。

### 改法：导语改成「一分钟看懂」

| 块 | 要求 |
|---|---|
| 一句话定义 | 它是什么、给谁用 |
| 一个反差 | 最多 2 个数字，并说出为什么反常 |
| 五条要点 | 每条不超过 40 字，最多 1 个数字，不带引用编号（编号放在正文对应处） |
| 读法导航 | 一行：想知道 X 看第几节 |

## 5. 整段文字太多，读起来累

### 现状

| 指标 | v3 |
|---|---|
| 正文段落 | 48 段，平均 108 字 |
| 超过 150 字的段落 | 12 段 |
| 全文的图 | 1 张 |
| 全文的引语卡 | 1 处 |
| 没有任何表或图的节 | 第三、五、六节（各约 1000 字） |

### 原因

- 模板每一节写的是「<……一段……>」，报告员自然写成段落。
- 文风只约束了「每句有信息」，没约束「怎么排」。

### 改法

- 段落不超过 3 句、100 字，一段只讲一件事。
- 每个小节的形式固定为：**加粗结论句** + 2—4 条证据要点，而不是一段论证。
- 并列 3 项以上用列表；3 个以上数字用表或图；用户声音用引语卡。
- 每 400—600 字至少一个非文字元素。
- 口径说明移到图注，不在句子里加括号。
- 校验脚本加两条警告：段落超过 120 字；连续 600 字没有非文字元素。

## 6. 调研深度不够

例子：国内用户只有第一财经采访的 4 个人。

### 原因

1. **预算按人头定，不按信息需求定。** 一个研究员要管「用户与动机」的中美两边，预算先被英文学术研究用完了。
2. **只允许补研一轮，而且触发条件是「核查打回过半」，不是「信息不够」。**
3. **没有「够不够」的标准。** Gaps 写完就算完成，没人追。
4. **中文社区抓不到。** 小红书、知乎、B 站经常返回 403，没有退到浏览器或本机爬虫；本机的小红书抓取默认是关的。
5. **研究员按维度分，没按「维度 × 市场」分。** 中文来源被英文来源挤掉。

### 改法

- 研究前先写**信息需求清单**：每个模块需要哪些信息、最低证据量是多少（见第 8 节）。
- 研究后跑**覆盖率门禁**：没达标的需求自动派定向补研，最多 3 轮。3 轮仍不够，写进「还不知道的」，并列出试过的渠道。
- 消费类产品默认**按市场拆研究员**（中国 / 海外）。
- 用户原声默认**开启本机抓取**；403 的站点退到浏览器。

## 7. 竞品要有清晰维度和足量信息

### 现状

价格散在一段文字里：9.99 美元、19.99 美元、6 元 600 星钻。没有权益，没有比较。

### 改法：固定字段的「竞品档案表」

每个维度一张表，每家都填同样的字段。研究员按字段收数据，而不是写自由笔记。

以价格为例，字段如下：

| 字段 | 说明 |
|---|---|
| 产品、档位 | 如 Character.AI c.ai+ |
| 价格 | 原币、折合美元 / 月 |
| 地区、计费方式 | 月付、年付、买断 |
| 核心权益 | 消息额度、记忆长度、语音、图片 / 视频、免广告、模型档位 |
| 免费版限制 | 每日条数、等待、广告 |
| 来源、日期 | 编号 + 抓取日期 |

表后接一段**价格分析**：每美元买到什么、和 ChatGPT Plus（20 美元 / 月）比如何、付费墙设在哪里。

其他维度表：

| 表 | 字段要点 |
|---|---|
| 功能矩阵 | 记忆、语音、图片 / 视频、群聊、用户自建角色、成人内容政策、年龄验证 |
| 规模 | 月活、日活、下载，各标口径与日期 |
| 收入 | 收入、年化、每付费用户收入，标「披露 / 估算」 |
| 融资与团队 | 轮次、金额、投资方、人数、关键人物 |
| 口碑 | 分平台评分、条数、最高频好评与差评 |
| 合规 | 年龄分级、年龄验证方式、未成年人政策、处罚记录 |

**实现方式：研究员产出结构化数据（CSV / JSON），每一格带来源编号或「未查到 + 试过的渠道」；报告里的表和图从数据渲染。** 这也给第 1 节的图提供了数据源。参考了同类 skill 盘点里 weizhena 的「对象 × 字段」矩阵和 haines 的固定模板档案。

**放在哪：** 正文第二节只放一张汇总表；价格权益表放第四节；完整竞品档案放附录，供查阅，不挡阅读路径。

## 8. 搜索如何规划，质量如何保证

分三层：规划、执行、度量。

### 8.1 规划：按信息需求定方向和门槛

| 信息需求 | 搜索方向 | 优先来源 | 最低证据量（产品类默认） |
|---|---|---|---|
| 是什么、机制 | 官方介绍、技术博客、长文解读 | 官网、官方博客、晚点、The Information | 每家 1 个一手来源 + 1 篇解读 |
| 市场规模与增长 | 第三方统计、榜单 | Appfigures、Sensor Tower、a16z、QuestMobile、点点数据、七麦 | 2 家机构，含当年最新一期 |
| 产品与价格 | 定价页、商店内购、应用内 | 官网定价页、各区 App Store 内购列表、截图 | 每家每档的价格与权益，标地区与日期 |
| 用户画像与动机 | 调查、学术、平台披露 | Pew、Common Sense、YouGov、arXiv、SSRN、HBS | 每个市场至少 2 份样本 500 人以上的调查 |
| 用户原声 | 社区与评论 | Reddit、小红书、知乎、微博、豆瓣、B 站、App Store 评论 | 每个市场至少 10 条、3 个平台、近 12 个月 |
| 财务 | 招股书、财报 | 披露易、SEC、公司新闻稿 | 上市公司必须读原文 |
| 公司动态与内幕 | 深度报道 | 晚点、The Information、36 氪、极客公园、Bloomberg | 每家至少 2 篇独立报道 |
| 监管 | 原文与解读 | 政府网站、律所解读 | 每个法域读原文，标「已生效 / 待生效 / 征求意见」 |
| 人物与故事 | 访谈、播客 | 创始人访谈、播客、长报道 | 主线案例至少 3 段原话 |

### 8.2 执行规则

- 中英文各一套查询词；用 `site:` 定向（如 `site:latepost.com`、`site:hkexnews.hk`）。
- 搜索摘要只用来找原文，不能当证据。
- 遇到 403 或付费墙，依次试：替代镜像 → 浏览器 → 本机爬虫 → 记为不可达。
- 招股书、研报这类 PDF，下载后用 pdf 工具读全文。
- 每条记录：URL、日期、类型、证据族、获取方式。

### 8.3 质量保证

- **覆盖率门禁**（第 6 节）。
- **核查**：独立验证者 + 对抗分析（已有）；并列数字用占比反算归属（run-1 中发现过一次写反）；时效检查（法规状态、最新一期报告）。
- **度量**：research_notes 里出一张覆盖率报表，列出每个信息需求的来源数、独立证据族数、一手来源占比、最新日期、是否达标。
- **已知短板**：中文社区站难抓；付费数据源不接（用户已拍板不注册）。

## 9. 分析模块

### 现状

v3 第六节「什么决定成败」只算半个分析模块。它有判断、有反例，但更像在归纳规则，缺少读者自己想不到的东西。

### 好的分析做五件事

| 类型 | 做什么 | 本报告可以写的例子 |
|---|---|---|
| 归纳 | 跨案例找共同规律 | 四家里两家的创始团队被大厂以「许可 + 雇人」带走：大厂愿意为模型人才付几十亿，不愿为陪伴产品本身出价 |
| 对比归因 | 条件相近，结果为什么不同 | Replika 融资 1100 万美元活了九年，Pi 融资 13 亿美元却停更：差别在有没有收费 |
| 机制模型 | 画出生意的因果环 | 时长↑ → 推理成本↑ → 必须收费 → 付费墙 → 流失；用这个环解释每家的选择 |
| 反直觉 | 指出常识错在哪 | 只有 11.8% 的用户说陪伴是主要用途，但 92.9% 的聊天记录里有陪伴对话：问卷会低估情感需求 |
| 二阶推演 | 如果 X 发生会怎样 | 开源推理再降一个数量级，成本门槛消失，竞争全部转向分发和合规 |

### 写法

- 每条洞见：一句判断 + 「依据见第 X 节」+ 对读者意味着什么。
- 放在事实章节之后、结论之前。读者先有了前文的知识，再看洞见。
- 和事实分开写，让读者分得清「这是查到的」和「这是推出来的」。

## 10. 「还不知道的」保留并升级

保留。升级成**问题清单**：每条写缺什么、试过哪些渠道、怎么补。它可以直接作为下一轮补研的任务输入，也就是续查入口。

**待用户确认的三处设计：**

1. 要不要单独加一节「带走的知识」（5—7 条可迁移的知识点，例如「陪伴产品的成本随聊天时长线性增长」），还是并进「一分钟看懂」。
2. 传播版用什么形态：HTML 页面链接、飞书文档，还是只要 md 加图片。
3. 竞品档案放附录（倾向），还是拆进正文各节。
