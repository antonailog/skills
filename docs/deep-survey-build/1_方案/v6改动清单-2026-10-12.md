# deep-survey v6 改动清单

> 2026-10-12 · **已并入 v7 重构**（`v7重构方案-2026-10-12.md`）。起因：Jev 调研（第一个 AI 工具类真实课题）交付后用户的四条反馈 + 一条追加。用户已定两项设计（见「已定」）。快照：`4_迭代/snapshot-v6-pre-2026-10-12/`（只留本机）。

## 一句话

报告形状从「一套为产品 / 行业写死的骨架」改成「按对象类型给默认大纲、在计划里让用户确认」；「一分钟看懂」从吸引人读下去的文字改成关键事实表；删掉「留给你的问题」；推荐阅读带超链接。研究、核查流程不动。

## 用户反馈与根因

| # | 反馈 | 根因（文件） |
|---|---|---|
| F1 | 一分钟看懂有「**对你**」「**带走的知识**」这类标签 | `report-template.md` 第 17 行写着 `**带走的知识**：<一条规律>`；`report-style.md` §2 要求最后两条是「带走的知识」 |
| F2 | 一分钟看懂该放最关键的信息（输入输出、效果），而不是一些文字 | `report-style.md` §2 明写「这里不追求信息密度，追求让人想读下去」，要求一个反差 + 5—7 条短句 |
| F3 | 没有专门解释输入输出的章节 | `SKILL.md`、`report-template.md`「顺序锁死」，骨架照 AI 陪伴（行业）定：格局 / 用户 / 钱 / 主线案例 / 分析；AI 工具类只改第四、七节标题；`check_report.py` E3 强制这个顺序。没有任何机制把用户的问题变成章节 |
| F4 | 「留给你的问题」没用 | 10-11 决定「一手研究不做，问题放末尾」；模板强制 3—7 条，报告员只能从笔记缺口里凑 |
| F5 | 推荐阅读要超链接 | 模板格式只给 `[编号]`，不给 URL |

## 已定（用户 10-12）

1. 章节：**类型默认大纲 + 计划里确认**。每类对象给一套默认大纲，协调者在 S2 按确认单里的问题增删章节，写进 `01-plan.md`，和分工一起请用户批准；脚本只管固定的头尾，以及「大纲是否按计划写了」。
2. 一分钟看懂：**关键事实表**。一句话定义 + 一张事实表（行由对象类型规定）+ 导引图 + 读法导航；去掉「反差」段和标签式要点。
3. 删掉「留给你的问题」（推翻 10-11 的决定）；「带走的知识」不再进一分钟看懂（推翻 10-10 v4 决定 1）。
4. 推荐阅读每条标题带超链接。
