## 0. S0 结论：为什么要独立 skill

本机已有 anthropic 自带的 deep-research skill（协调者 + 并行研究员 + 报告员），能搜能拆题能写叙事报告。但它缺三样东西，而这三样正是"调研"与"搜资料"的区别：

1. 动手前没有把问题钉死的确认单（对象类型 / 受众 / 问题类型 / 口径 / 来源白名单）
2. 没有对抗角色和独立核查，结论是叙事不是可审计的论断
3. 输出是散文，不是对比矩阵 + 置信度 + "未查到"清单

扩展 deep-research 不合适：它是 synced 下发的只读 skill，改了会被覆盖。所以做一个**调研层** skill，前后两头包住 deep-research，中间的搜集与并行拆题直接复用。

资格条件：会重复使用（产品 / 行业 / 公司调研是高频活）✅；容易被路由错（与 deep-research、forge-brainstorm 相邻）✅；有确定性脚本能省劳动（引用完整性、未查到清单检查）✅。

## 3. 定位与流程骨架（S2 草案）

**定位**：调研分析师 + 独立核查员。不是再造 deep research，而是让每条结论可审计。

**核心立场**：用户要的不是"资料多"，是"哪些结论站得住、哪些查不到"。所以产出按置信度分层，未查到的显式列出，而不是用估算填空。

流程：

1. **调研确认单**：对象类型（产品 / 行业 / 公司 / 技术 / 其他）、受众、问题类型（描述现状 / 诊断 / 预测 / 建议）、时间与地域口径、权威来源白名单。一轮 ≤3 问；用户给了材料先从材料提取。
2. **按对象类型选维度框架**：产品类六维（定位与目标用户 / 核心机制 / 商业化 / 增长与数据 / 用户口碑 / 团队与融资）；行业类、公司类各一套。维度即子研究员分工。
3. **数据宪法 + 费用预审**：列出查什么、用哪些来源、哪些要付费，批准后才跑。无接口则只用公开来源并降置信度。
4. **四类角色并行**：收集者按维度跑；正向分析员找机会；对抗分析员专找"为什么不成立"；验证者独立核查每条关键论断。
5. **Statement Review**：进"核心结论"的论断必带来源、置信度（高 / 中 / 低）、"未查到"标记；核查不过的降入附录。
6. **固定输出骨架**：核心结论 → 对比矩阵 → 证据链 → 对抗分析 → 未查到与待确认清单 → 附录（来源表、被打回论断）。文风沿用知识整理 SOP。可选发飞书。

**档位**：完整档（有 tool 编排、输出要给别人看、路由错有代价）。

**目录预期**：`SKILL.md` + `references/`（维度框架、来源白名单、核查清单、口碑抓取指引）+ `assets/`（确认单模板、报告模板）+ `scripts/`（引用完整性与未查到清单检查）。

## 4. 效果预览：以「AI 陪伴型产品」为例

> 以下数字均为占位示意，不是事实。

1. **确认单**（3 问）：看"赛道值不值得进"还是"某几款怎么做的"？读者是自己还是给别人看？口径只收 2025 年至今中英文公开来源，是否接付费数据接口？
2. **调研计划待批准**：5 个维度子研究员（市场规模与融资 / 头部产品机制对比 / 商业化与留存 / 用户口碑与争议 / 监管与伦理风险）+ 1 对抗分析员 + 1 验证者；来源白名单：a16z 与 Sensor Tower 报告、产品官网与应用商店、Reddit 与小红书原帖、36 氪与 TechCrunch；标明"下载与收入数据无付费接口，只能引媒体转述，置信度中"。
3. **报告骨架**：
   - 核心结论 5 条，各带置信度与来源编号。例："陪伴类收入高度集中于头部两三款，长尾月活过百万但付费率不足 N%【中，来源 3、7】"；"留存靠记忆与人设一致性而非模型能力，差评中 X% 指向『它忘了我说过的话』【高，来源 12—15 原帖】"。
   - 头部产品对比矩阵：Character.AI、Replika、Talkie / 星野、Pi 等按六维列表，格内只放事实 + 来源编号，查不到写"未查到"。
   - 用户口碑证据链：每条痛点标帖子数、代表原话、时间与链接，按"记忆断裂 / 审核过严 / 付费墙 / 情感依赖"归类。
   - 对抗分析：单独一节写"为什么这个赛道可能不成立"（未成年人监管、通用助手侧翼挤压、情感依赖舆情风险），每条带证据。
   - 未查到与待确认清单：集中列出，并标出接 AIsa 后哪几项能补。
   - 附录：全部来源表、被核查打回的论断及原因。
4. **可选发飞书**，未查到清单作为下次续查入口。
