## 0. 先说三个被忽略的前提

### 0.1 「约束太多」只是症状，病根是「写作者没有理解过对象」

Jev v7 第四章的每个小节都是「加粗判断句 + 3—6 条带编号的要点 / 一张表」。读起来累，不是因为某条排版规则，而是因为报告员拿到的输入就是「事实清单」：研究员按章交笔记，每条一个事实加链接；报告员在一个上下文里读 200—250 KB 笔记，立刻按既定大纲往章里填。它从没有经历过「读完所有材料，想明白这是个什么故事」这一步。`30-judgments.md` 名义上是这一步，但它由报告员在读笔记和动笔之间顺手写、没人看、且大纲已锁定，判断只能塞进预定章节。

证据：秘塔对照第四节指出 deep-survey「有素材没用」（自有信源池里 22 个 Jev 玩法、具身方向两篇，确认单第 3 问要的就是这个），以及「没有抽出一份通用的适配清单」「缺能对应上机制的类比」。这三条都不是模板导致的，是没有综合步骤导致的：事实被按章分拣后，跨章的洞见和「这东西到底是什么」的直觉没有人产出。

所以：**只拆「契约 / 形态」、只放宽模板，报告仍会是事实清单的另一种排法。** 必须加一个综合步骤，并改变研究员交给报告员的东西。

### 0.2 「发散性地写」的反面不是「没有约束」

v1（审计材料进正文）、v2（砍到 151 行被评信息不够）、秘塔报告（「70–500 毫秒」重复 6 次、「这一点非常重要」）都是没有约束时 LLM 写作的真实样子。现版的约束每一条都是对真实失败的反应。问题在于**约束放错了层**：放在形态层（段落几句、哪章必须有哪张表、推荐阅读几条、小节必须加粗起手），而不是实质层（有没有一个论点、机制讲没讲通、读者读完能不能复述）。

形态约束的代价是可预测的：报告员的注意力被格式占满（问题梳理 D 条已指出），脚本把写作判断当错误报，报告员为过检去改坏正常写法（v7 审稿 M1 实测四类误报）。

### 0.3 规则是被「每条反馈变成一条永久规则」的棘轮推上去的

三天 8 个版本，改动记录里每一版都在「加」：加导引图、加推荐阅读、加结论表三列、加第二梯队、加 W16—W18。v7 删了审查角色，但写作规则一条没减。上一轮对话提出的「契约 / 形态拆开」是对的，但没有处理棘轮本身：下一个课题用户再提一条意见，它还会变成一条新规则进 writing-guide。需要一条**规则准入标准**（见 2.6），否则这次减掉的会在两周内长回来。

另外，这个工作区已经两次得出同一个结论：humanwrite「范文优先，基线胜出，加规则 = 走错路」、xhs-note 同。deep-survey 的 writing-guide 220 行里没有一段范文。

## 1. 从零构建：我会怎么做

目标不变：读者带着问题来，读完建立对对象的理解、信得过这份理解、能据此行动。好的人写分析（晚点、a16z、Stratechery、Ben Evans）的共性是：**有一个论点、有叙事弧、机制靠类比和因果链讲清、数字只用来锚定、推理由散文承载**。它们不是要点堆。

### 1.1 流程：在研究和写作之间加「综合」，结构在综合之后定

```
1 定题（一次确认）→ 2 研究（按问题 / 角度并行）→ 3 综合（一人，出论点备忘与大纲）→ 4 写作 → 5 冷读审读 → 6 交付
```

| 步 | 与现版的差别 |
|---|---|
| 1 定题 | 只确认：问题、对象范围、读者、要作的决定、研究角度与分工。**不定章节**。框架文件在这里提供「这类对象通常要查什么」的清单，不提供大纲 |
| 2 研究 | 研究员按「问题 / 角度」而非「章」分工。每人交两样：原始笔记（证据，供追溯）+ **一页理解备忘**（≤1500 字：这块最重要的三件事、机制是什么、什么让我意外、哪里有争议、什么没查到） |
| 3 综合 | 新角色。先读全部理解备忘（6 人 ≈ 9000 字，一屏可读），再按需翻笔记。产出 `30-synthesis.md`：一句话论点、3—5 个核心判断（各配依据、反证、适用边界）、对象的运行机制（文字版）、读者的决定及其条件、**报告大纲与各章形式**。大纲到这一步才存在 |
| 4 写作 | 报告员照综合备忘写，笔记当证据库。允许 ≤10 次定向补查（写作时发现的、挡住一句话的缺口）。现版「报告员不做新研究」把每个此类缺口都变成「未查到」或写薄 |
| 5 审读 | 冷读：审读员不拿清单，像读者一样读完，写 300 字「我读到的结论与机制」+ 在哪里卡住 + 哪个问题没得到回答。协调者把这 300 字和综合备忘的论点对照：对不上，是写作失败，退回。现版 8 项清单跑出 27 条、全改，那是合规，不是质量 |
| 6 交付 | 同现版 |

为什么综合要单独一人、单独一步：报告员一个上下文里既要理解又要写几万字，理解一定被挤掉。人类研究团队就是分析师交备忘、主笔定故事再写。

### 1.2 两层约束：契约硬、工艺软

**读者契约（硬，脚本或审读员查，≤7 条）**

1. 开头一屏给答案：对象是什么、关键事实、结论。形式按课题：事实表、五句话摘要、或一张结构图加三行字。
2. 定题时的每个问题，都能在目录里找到正面回答它的地方。
3. 机制被解释，不只是被断言：至少能回答「它为什么能这样 / 为什么会这样」。
4. 每个数字可追溯；查不到写「未查到」；口径（官方 / 第三方 / 推算）写在句子里。
5. 结尾落到读者的行动：做什么、先验证什么、什么情况下放弃。
6. 列出没查到的、会影响判断的事。
7. 来源列表。

**写作工艺（软，范文 + 原则，审读员用判断，脚本不查）**

- 原则只留几条：一段一事；没有一句不带信息；分析类标题写成判断；数字配参照；机制用因果链和一个能对应上机制的类比；同一事实只讲一次。
- **范文**：3—4 段带批注的样章（各 1500—3000 字）：一段机制讲解、一段格局对比、一段结论与验证、一段开头。批注写「为什么这样写」。范文从 Jev v7 与 AI 陪伴 v5 里挑最好的段改出来即可，不用新写。
- 形式按内容类型推荐，不按章名规定：对比 → 表；机制 → 短段落 + 结构图；时间线 → 分类时间轴；决策 → 选项 / 验证 / 放弃线；用户处境 → 引语。

### 1.3 脚本只查机械项

保留：引用编号一致、表无空格、图片存在、相邻方括号、推荐阅读有链接、编号连续、来源标题残留、内部工具名、凭证扫描。
不查：章节结构、事实表形状、段落长度、连续字数、过渡词、推荐阅读条数、结论表列名、导引图有无。
理由：脚本一旦查写法，写作者就为脚本写。

### 1.4 框架文件改成「研究清单」

现版框架 = 默认大纲 + 每章信息需求 + 事实行。其中「每章要查什么、优先来源、常见不可得项」是真正积累下来的领域知识，应保留并继续积累；「默认大纲」和「事实行」应删，因为它们是把两个课题的报告形状写成了规定。

另外，结构更多由**问题类型**决定，而非对象类型：「该不该接入 X」「X 怎么运转」「Y 赛道格局」「做 Z 有哪些资源」是四种不同的报告。个人博客课题是第四种，被套进了「是什么 / 格局」。框架按对象类型给研究清单，大纲由综合按问题类型定。

### 1.5 保留什么

研究侧是这个 skill 的护城河，秘塔对照已证明（4 个来源 vs 100 个、把官方口径当定论 vs 一手与第三方分开、算术错误）。以下全部保留：每个数字带原文链接与日期、不从图表读数、来源分级、聚合站只用于定位、自有信息流优先、中文平台专用通道、停止条件、「未查到」纪律、图表从数据渲染且每个数值带来源、来源重编号、「还不知道的」、不写凭证。

### 2.6 规则准入标准（防棘轮）

以后往 writing-guide 加一条规定前，过三问：

1. 不写这条，三份报告里会有两份违反吗？否 → 进范文批注或审读判断，不进规则。
2. 它能被脚本机械判定、且误报率可忽略吗？否 → 不进脚本。
3. 它约束的是实质（论点、机制、可追溯、落到行动）还是形态（几句、几列、哪章放什么）？形态 → 不进规则。

同时 writing-guide 设上限（如 100 行），加一条要删一条。

全部取数脚本、`make_chart.py`、`render_visual.py`、`render_table.py`、`build_source_table.py`、`renumber_sources.py`、主题文件、红线 4 条、失败处理、协调者不自己搜不自己写、一次确认。

## 3. 预期代价与风险

- 综合步骤新增约 10—15 万 token（读 9000 字备忘 + 翻部分笔记 + 写 2000 字），同时去掉 27 条逐项修改的循环，总量大致持平。
- 没有形态规则后，首版报告可能出现 v2 式的「薄」或秘塔式的重复。防线是范文 + 冷读审读 + 契约第 3 条（机制被解释）。如果冷读审读发现「读完说不出机制」，退回，不是加规则。
- 大纲后置意味着用户在第 1 步看不到章节。协调者在交付回复里附综合备忘的论点与大纲，用户不满意可只重写不重研。

## 4. 验收方式

用个人博客课题（研究笔记已有，`知识/调研/个人博客搭建-2026-10-12/research_notes/`）跑第 3—6 步：补写各章理解备忘 → 综合 → 写作 → 冷读。对照项只有三个：审读员冷读 300 字能否复述论点与机制；用户读完是否觉得「像人写的分析」；秘塔对照里列的三样（类比、用途全景、通用清单）这次有没有自然出现。
