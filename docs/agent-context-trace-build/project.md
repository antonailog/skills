## 0 原则与术语

**原则**

- 页面只展示客观的调用链路，不替用户判断「该读没读」。
- 要加统计，放在每个代理的总览里，不插在链路中间。
- 界面上的名字一律用计算机术语，不用口语。

**层级**

| 术语 | 英文 | 指什么 |
|---|---|---|
| 追踪 | Trace | 一次圈定的范围，也就是整个页面 |
| 主代理 / 子代理 | Main agent / Subagent | 链路上的节点 |
| 初始上下文 | Initial context | 第一次 LLM 请求时上下文里已经有的内容 |
| 系统提示词 | System prompt | |
| 工具定义 | Tool definitions | |
| 注入内容 | Injected context | 运行环境自动注入的 CLAUDE.md、记忆索引、skill 列表、环境信息等 |
| 任务提示词 | Task prompt | 主代理调用子代理时传入的 prompt |
| 用户消息 | User message | |
| 分段 | Segment | 两次写入之间的所有事件，以一次写入结束 |
| 事件 | Event | 分段里的每一行：一次工具调用，或一条系统提醒 |
| 请求 #N | Request #N | 第 N 次 LLM API 请求 |
| 上下文构成 | Context composition | 某次请求时，上下文里各类内容各占多少 |
| 焦点文件 | Focus files | 用 `--focus` 指定的文件或目录 |

**事件的操作类型（行首标签）**

| 标签 | 英文 | 对应的调用 |
|---|---|---|
| 读取 | Read | Read 工具；Bash 的 cat、head、tail、sed -n、nl。读图片也算读取 |
| 查找 | Search | Grep、Glob 工具；Bash 的 grep、rg、find |
| 过滤 | Filter | Bash 的 awk |
| 列出 | List | 只做了 ls 的 Bash 调用 |
| 执行 | Exec | 其余 Bash 命令和脚本 |
| 写入 | Write | Write 工具；只写文件、不做别的的 Bash 调用（重定向、heredoc） |
| 编辑 | Edit | Edit 工具；Bash 的 sed -i |
| 抓取 | Fetch | WebFetch、WebSearch |
| 调用 | Spawn | 用 Agent 工具调用子代理 |
| 返回 | Return | 子代理把结果返回给主代理 |
| 提醒 | Reminder | 运行中注入的 system-reminder |
| 用户 | User | 用户消息 |

**事件的客观属性**：只在点开事件时的标题行显示，不在链路树上标。

| 术语 | 指什么 |
|---|---|
| 全文读取 / 部分读取（行 18–64） | 读取范围 |
| 输出截断（仅前 2KB） | 工具结果太长，模型只拿到前 2KB 预览 |
| 执行失败 | 工具结果标记为出错 |
| 与当前文件一致 / 不一致 | 读到的内容和生成页面时磁盘上的文件比对的结果 |
| 字符、tokens | 长度单位，不用「字」 |

## 1 目的

用户在调 skill 或 prompt。一次运行的产出不理想，要找出原因，再去改 skill 或 prompt。原因只会落在两处：

1. **模型当时上下文里有什么**：指令（任务提示词、SKILL.md、注入的 CLAUDE.md、记忆、skill 列表）和材料（读取的文件、命令输出、图片）。
2. **模型按什么顺序做的**：读取了什么之后写入初稿，又读取了什么之后编辑。

所以页面要把一次运行还原成**按时间排列的调用链路**：每次写入都能看到它之前发生的事件；原文里提到的每个文件都能点开看内容，并在链路中定位它出现的位置。

## 2 要回答的问题

| | 问题 | 在页面哪里看 |
|---|---|---|
| a | 读没读到我改过的 SKILL.md？是不是新版？只读了一半？ | 链路里读取 SKILL.md 的事件；点开后标题行写着读取范围、与当前文件是否一致 |
| b | 传给子代理的任务提示词原文是什么？ | 主代理下的「调用」事件 |
| c | 某个文件在哪次请求读取、读了几次、多大？ | 点这个文件，链路里它出现的每个事件都会高亮；代理总览里有文件表 |
| d | 注入内容有没有干扰？ | 每个代理的「初始上下文」 |
| e | 写某个文件之前读过什么？ | 分段展开就是写入之前的事件；点写入事件能看到那次请求的上下文构成 |
| f | 哪些文件读了不止一次？ | 代理总览里的文件表；点文件定位 |
| g | 原文里提到的文件内容是什么，在链路中出现在哪？ | 原文里的路径都能点，点开在右侧栏看内容，同时在左边定位 |

## 3 结构：自顶向下

```
追踪（顶栏）
└ 主代理
   ├ 用户消息
   ├ 事件 …（主代理在调用子代理之前自己做的事）
   └ 调用 子代理
      └ 子代理
         ├ 初始上下文：系统提示词、工具定义、注入内容、任务提示词
         └ 分段（以一次写入结束），展开是这一段的事件
```

以前按「怎么进来的」分组（读的文件、命令、产出、逐次请求），时间和因果被打散了。现在时间是主轴，「怎么进来的」变成每个事件前面的操作类型标签。

**切段规则**（通用，不依赖某个 skill 的步骤）：

- 结束一个分段的有四种：Write 或 Edit 工具的写入、圈范围时指定的那个产出（不管是怎么写出来的）、调用、返回。
- 事件的口径：每个读取的文件、每张图片各一行；每个写入或编辑的文件各一行（包括 Bash 写的，它们不切段）；一次调用除了读写文件还做了别的（比如运行脚本），另加一行执行；每条系统提醒一行。
- 连续几次写入，中间没有任何事件的，合成一行，比如「编辑 图片说明.md ×3」。调用和返回不跟别的合并。
- 一次工具调用读取了几个文件时，每个文件一行，这几行用同一个请求编号。
- 请求编号：读取类和执行类事件用结果第一次出现在上下文里的那次请求；写入类和编辑类事件用发出这次调用的那次请求。编号相同时，读取排在写入前面。
- 长分段的合并（D2）：连续读取 3 张以上图片，合成一行「读取图片 ×N」；连续读取同一目录下 3 个以上文件，合成一行「读取 xx/ 下 N 个文件」。合成的行都能展开。

## 4 页面长这样

公开例子见 `skills/agent-context-trace/examples/cafe-poster-trace/`：一次无界面运行的 image-prompt（写一张咖啡店海报的 prompt）。主 Agent 用 Skill 工具加载 SKILL.md，先 grep 两份参考文件的标题，再各读开头一段，最后回复一段 prompt；没有写文件，所以整条链路只有一段。

一个写作 skill 的真实运行（主 Agent 改完 SKILL.md 后派一个子 Agent 写文章，子 Agent 71 轮）默认展开到段这一层是这样：

```
主 Agent
├ 上下文
├ 用户  用户消息                                         41
├ 编辑  SKILL.md
└ 1 次操作 → 调用  <子 Agent 描述>                     1,037
   ├ 读取  作者说的.md                                  863
   └ 子 Agent <描述> · 71 轮
      ├ 上下文      系统提示词 · 工具定义 11 · 注入内容 14 · 任务提示词
      ├ 9 次操作 → 写入 写作思路.md                     691
      ├ 38 次操作 → 写入 材料笔记.md
      ├ 43 次操作 → 编辑 写作思路.md
      ├ …
      └ 返回
```

展开「9 次操作 → 写入 写作思路.md」，能看到写之前读了 SKILL.md、两份索引、作者档案和参考文件，每行右侧是字符数。点这一段，中间显示写入的内容和写入那一轮的上下文构成。

## 5 两个子 Agent 怎么接起来

```
主 Agent
├ 用户  用户消息
├ 调用  子 Agent Researcher
│  └ 子 Agent Researcher · 70 轮
│     ├ 上下文
│     ├ 117 次操作 → 写入 材料梳理.md
│     ├ 1 次操作 → 编辑 材料梳理.md
│     └ 返回
└ 调用  子 Agent Writer
   └ 子 Agent Writer · 38 轮
      ├ 上下文
      ├ 38 次操作 → 写入 写作思路.md     （第 8 轮读取的 材料梳理.md 来自 Researcher 第 69 轮写的版本）
      ├ …
      └ 返回
```

主 Agent 在两次调用之间做的事按时间排在两次调用之间。追踪总览画出这条文件流转：Researcher 写入 → Writer 读取。

## 7 点开后中间显示什么

| 选中项 | 中间显示 |
|---|---|
| 读取 / 查找 / 过滤事件 | 模型拿到的内容。标题行写：请求编号、操作类型、调用方式（Read、Bash cat…）、读取范围、是否输出截断、与当前文件是否一致；下面是命令原文和内容；最后列出这个文件在链路中的其他事件，可以点过去 |
| 图片读取 | 图片本身 |
| 执行 / 列出 / 抓取事件 | 命令或参数原文，加上工具结果；顺带写出的文件列在标题行 |
| 写入 / 编辑（分段行） | 写入的内容（编辑显示改前和改后）；下面是这次请求的上下文构成，每一条都能点，点了在左边定位 |
| 调用 | 用户消息在上，任务提示词在下 |
| 返回 | 子代理返回给主代理的内容 |
| 初始上下文 | 一条横条显示系统提示词、工具定义、注入内容、任务提示词各占多少；下面按类列出。工具定义只列工具名和说明 |
| 提醒 | system-reminder 原文 |
| 代理总览（点代理行） | 请求数、时间、上下文 tokens 首次 → 末次；各操作类型的事件数；读取的文件表（路径、次数、首次请求、字符数）；写入的文件表；给了 --focus 时加焦点文件覆盖表 |
| 追踪总览（点顶栏名字） | 一张小图，画各代理之间的调用和文件流转（例：Researcher 写入的材料梳理.md → Writer 读取） |

## 8 文件引用：点开看内容，同时在链路中定位

- **哪些算引用**：中间内容里出现的文件名或路径（带扩展名）。生成页面时按下面的顺序找对应的文件，只找到唯一一个才做成链接，找不到或对上好几个的照原样显示：
  1. 绝对路径，或者 `~/` 开头的路径；
  2. 相对于这段文字所在文件的目录（SKILL.md 里写的 `references/写法.md`）；
  3. 相对于代理的工作目录（任务提示词里写的 `文章.md`）；
  4. 和这次链路中读取、写入过的某个文件结尾一致（SKILL.md 里只写了 `关于我.md`，链路里读取过 `内容/自媒体/写作档案/关于我.md`）；
  5. 在这段文字所在文件的目录下按结尾找（`体裁/索引.md` → `references/体裁/索引.md`）。
- **样子**：所有引用一样显示，路径加下划线，不区分读没读。
- **点开以后**：
  - 右侧栏显示文件内容。顶部写「在链路中出现 N 次」，列出每个事件，点哪个跳到哪个；出现 0 次也照实写。
  - 左边链路中，这个文件出现的每个事件自动展开并高亮，滚到第一处。
- **侧栏显示哪个版本**（D6）：
  - 文件运行后没改过：显示生成页面时磁盘上的全文，模型读取过的行区间标出来。
  - 改过：显示模型最后一次读取到的内容，顶部注明「运行后文件已变更，显示请求 #N 读取到的内容」。
- **在 Finder 中打开**（D12）：按住 Command 点文件，或者右键选「在 Finder 中显示」。
- **目录引用**（11-03 新增）：内容里写的是目录（比如 `~/work/site/`），同样做成链接。点击后用 VS Code 打开这个目录（`vscode://file/<目录>`），不开侧栏。按住 Command 点或右键，和文件一样。解析规则同上：绝对路径、`~/` 开头，或者相对路径以 `/` 结尾、能解析到唯一一个存在的目录。

## 9 显示原则

- 内容就是模型拿到的文字，不显示 JSON 外壳（role、type、tool_use_id）。用户消息只显示文字，工具结果只显示内容，图片直接显示。
- 不显示行号，读取的行区间写在标题行。
- Markdown 渲染后显示，适用于 .md 文件内容、任务提示词、用户消息、返回内容、写入 .md 的内容。只渲染能保证是原文连续一段的：全文、cat、head、tail、sed 行区间都算；grep、awk 的结果，被截断的输出，代码文件，命令输出，仍按原样用等宽字体显示。
- 链路树上不标状态。客观属性只写在事件详情的标题行。
- 不加说明小字、操作提示、页签、筛选器、实心按钮。
- 只能上下滚，不横滑。滚动条滚动时出现，停下就隐藏，不占宽度。

## 10 交互

- 点一行，中间显示它；有子项的行点一下同时展开或收起。
- 点内容里的文件路径：打开右侧栏，同时在左边定位。
- 左栏、右侧栏都能拖宽，右侧栏能关闭。
- 按住 Command 点文件，或者右键：菜单有「在 Finder 中显示」「在 VS Code 中打开」「复制路径」三项。
