# agent-context-trace 数据结构 v2.0

## 和 v1 相比改了什么

`schema_version` 改为 `"2.0"`。保留 v1 的 `nodes / items / requests / sources / images / edges / focus` 及原文、哈希、归属账本；增加按时间排列的事件、分段、上下文构成、文件引用与文件侧栏索引。页面应使用 v2 的导航字段，不再把 v1 的 groups 当左侧树。

- `events`：每次读取的文件、每张图片、无文件读取的工具调用、系统提醒、用户消息、调用和返回；以 ID 连接原有条目、请求、读取/写入记录与原文。
- `segments`：Write/Edit 工具、所选产出的写入、调用、返回结束分段；相邻写入合并，普通 Bash 编辑/顺带产出不切段。
- `context_compositions`：每个分段结束请求的八类上下文字符数及可定位 ID，按该次请求的真实 ownership 计数。
- `file_references`：页面文字中的文件链接，包含来源、Unicode 码点位置和绝对路径。
- `files`：以绝对路径为键的文件侧栏索引，包含链路事件、版本选择、模型读取区间、1 MiB 以内的当前文本。
- `operation_labels / context_category_labels`：本版操作类型和上下文类别；`trace_overview` 引用可画图的节点和边。
- 每个 `Node` 增加 `event_ids / segment_ids / timeline / initial_context / overview`；调用边和文件流转边增加统一的 `source_node_id / target_node_id / source_event_id`，文件流转另有 `target_event_id`。
- 主代理从所选第一次调用前最近的用户消息起，还原到最后一次所选调用，包含调用前、两次调用之间自己的事件。没有重编号；其他并行任务的调用仍保存在原请求中，不扩进本次追踪树。
- T3a 返工第 1 轮：Bash 识别出的每个写入/编辑文件独立成事件，使用发出调用的请求；读取、列出和执行使用结果首次进入上下文的请求。Bash 普通写入仍不切段，分段事件数随拆分变化。
- T3c：主代理范围内有分段写入时，也展示初始上下文、分段和 D2 组；范围开始的用户消息独立置前。执行事件字符数扣除同次调用已分给读取的输出；循环标题保留循环头。追踪总览按代理去重，按调用顺序排列。
- T3d：`file_references` 同时保存文件和目录引用，以 `kind: file/dir` 区分。目录只接受唯一存在的目标，不进入 `files`；点击目录用 VS Code 打开，文件仍打开侧栏。
- `--tree` 改成主代理 → 用户/事件/调用 → 子代理 → 初始上下文/分段/事件，D2 组可见且展开列出子事件。`data --tree` 可以省略 `-o`，仅输出结构；保留 JSON 时仍显式指定本地路径。

下文 v2 字段是 T3b 的直接读取契约；末尾保留 v1 存储字段说明，便于审计和兼容旧页面。所有示例均为虚构数据。新页面不需要重新解析日志、命令或文件路径。

## v2 顶层与导航

| 字段 | 类型 | 用途 |
|---|---|---|
| `events` | map<ID, Event> | 叶事件和 D2 组事件 |
| `segments` | map<ID, Segment> | 分段及结束它的写入/调用/返回 |
| `context_compositions` | map<ID, Composition> | 分段末请求的上下文构成 |
| `file_references` | FileReference[] | 原文中可点击的文件和目录引用 |
| `files` | map<绝对路径, File> | 文件侧栏 |
| `operation_labels` | map<操作 key, 中文> | read 读取、search 查找、filter 过滤、list 列出、exec 执行、write 写入、edit 编辑、fetch 抓取、spawn 调用、return 返回、reminder 提醒、user 用户 |
| `context_category_labels` | map<类别 key, 中文> | 见上下文构成表 |
| `trace_overview` | object | `node_ids`、`edge_ids`；直接从 nodes、edges 取图节点/连线 |

`nodes` 仍为数组。每个节点的新字段：

| 字段 | 含义 |
|---|---|
| `event_ids` | 按请求号及实际时间排列的叶事件，不包含组事件；相同编号下，读取/结果先于结束分段的写入/调用 |
| `segment_ids` | 分段顺序，主代理也有分段数据可供详情使用 |
| `timeline_mode` | `segments` 或 `events`；子代理，以及范围内有 `ends_segment:"write"` 的主代理使用 segments，其余主代理平铺 |
| `leading_event_ids` | 分段主代理开头的用户消息，保持时间顺序；不计入第一分段事件数，仍在 event_ids 和代理总览中 |
| `timeline` | `{kind:"event"|"segment", id}` 数组；segments 模式先是 leading_event_ids，再是 segment_ids；events 模式按时间列出所有事件。初始上下文在前置用户消息与分段之间展示 |
| `initial_context` | 初始内容、条目与字符数；主代理和子代理类别差异见后文 |
| `overview` | 请求数、起止时间、tokens、操作计数、读取/写入文件表和焦点覆盖 |

调用事件的 `child_node_id` 指向子代理节点，节点的 `parent_id` 保留。跨代理不要按请求编号排序：请求号属于各自日志，应使用节点关系与时间。

## Event：事件与组事件

| 字段 | 类型 / 含义 |
|---|---|
| `id / node_id / kind` | 唯一 ID、所属代理；`kind` 为 `event` 或 `group` |
| `request_id / request_number / timestamp` | 读取、列出、执行使用结果首次进入上下文的请求；所有写入/编辑（包括 Bash）使用发出调用的请求；时间使用记录中的结果/请求时间 |
| `operation / operation_label / method` | 操作 key、中文标签、实际调用方式，如 `Bash grep` |
| `tool_use_id` | 工具调用 ID；消息/提醒/返回可为空 |
| `display_name / directory_hint` | 文件名或前约 60 字符的首条有效命令；目录按下面的缩写规则 |
| `characters / visible_characters` | Unicode 码点数；前者沿用 v1 的模型收到文字口径，包含工具行号/包装，已切分输出只数本文件的那段；执行/列出扣除同次调用读取片段的区间并集，避免重复计数。后者为 `content_ref` 实际展示文本长度，执行详情仍可查看完整工具结果。页面行的 characters 为 0 时留空 |
| `is_focus` | 仅检查事件自己的 path 是否为焦点文件；同次调用的其他读写路径不传递星标。组事件仍汇总其子事件 |
| `path / read_id` | 文件的绝对路径与 v1 Read occurrence ID，可空；失败的 Read 通过 `file_access:"read"` 记录尝试，保留失败字段 |
| `item_ids / raw_refs / call_ref` | v1 条目、原始结果/消息切片、原始工具调用块；`call_ref` 中仍有完整 command/input |
| `content_ref / image_ids` | 已整理的展示文本引用、v1 图片池 ID；去掉 Read 行号、工具传输包装，不改原始 source |
| `written_files` | 写入/编辑事件自己的文件明细（单元素数组），读取和执行事件为空：`path/item_id/write_id/method/content_ref/before_ref/after_ref/content_kind/failed/timestamp`；content_kind 的 full/append 区分全文和追加片段；生成文件若从同次调用的独立全文读取结果取得内容，还附 `content_request_id` |
| `read_range` | v1 coverage 的 `kind/label/selectors`，全文、行区间、字节或筛选说明 |
| `output_truncated / truncation / failed` | 输出是否截断、截断说明、工具结果是否报错 |
| `comparison_status / comparison` | `same/different/missing/unavailable` 及比较依据；保留 v1 的完整比较证据 |
| `shared_with / output_split` | 无法独立切出的同一输出内其他文件；是否已按 echo 分隔切出 |
| `call_failed / output_partition / result_shared` | 读取来自的整个调用是否失败；切分依据 echo、matched_file_content 或 shared；执行/列出是否与同次其他事件共享工具结果 |
| `producer_edge_ids` | 指向具体历史写入版本的文件流转边 |
| `ends_segment / segment_id` | `write/spawn/return/null`；归属的分段 ID |
| `child_node_id` | 调用事件的目标子代理 |
| `file_reference_ids` | 此事件显示文字中的文件引用 ID |

事件口径：每个读取文件一条、每张图片一条，每个 Bash 写入/编辑文件也独立成一条，与同次调用的读取并列。v1 的“命令改了它”及追加为编辑，文件新建/生成/重定向写出为写入。命令还包含额外执行（例如 node look2.js）时，另有一个执行事件，标题从该执行子命令开始；单纯的文件编辑脚本不重复生成执行行。目录列出保持调用级粒度：无文件读取时才单列，带读取时仍可从原工具结果查看目录输出。Write/Edit 回执不形成事件；普通 Bash 写入/编辑不切段，只有工具 Write/Edit、指定产出、调用、返回形成边界。未进入所选请求范围的结果不使用调用请求冒充结果请求。

`Read`、cat/head/tail/sed -n/nl 是读取；grep/rg/find 和 Grep/Glob 是查找；awk 是过滤；只有 ls、echo、重定向到 /dev/null、ls 的循环/输出截短时为列出；for 循环里的其他执行仍按执行处理。纯重定向/heredoc 写文件是写入，sed -i 是编辑。Bash 类型为写入/编辑不代表切段，只有 `ends_segment` 决定边界。queued_command 附件显示为「用户 / 用户消息（运行中插入）」。

D2 组事件 `kind:"group"` 的 `child_event_ids` 保存叶事件，`request_range` 为首尾编号。连续至少 3 张图片跨目录可合组；连续至少 3 个读取文件要求父目录字符串完全相同。两个图片不合并；查找/过滤/执行会打断读取组。组只用于展示，统计使用叶事件，组本身不重复计数。

目录规则按优先级：scratchpad 特殊路径 → `scratchpad/…`；Claude tool-results 特殊路径 → `tool-results/…`；同一会话目录的其他文件去掉会话前缀（如 `subagents/…`）；代理 cwd 下取相对路径；工作区根 `~/claudecode_workspace/` 下去掉前缀；其他家目录路径缩成 `~/…`。根本身用 `./`。真实路径、ID 和 source 中仍保留会话编号，显示字段不会把会话目录带进树。

命令名静态移除开头的 cd、mkdir -p 和字面量变量赋值，按原始命令片段截取，保留引号、空格和 `2>/dev/null` 的写法；路径缩写规则不变。for 循环体里的执行显示所属循环头，不从 `$(…)` 内部或循环体截出一个命令当标题；最多 60 个码点。只做静态分析，不执行日志中的命令；内联程序正文不会变成命令标题。

## Segment：分段

| 字段 | 含义 |
|---|---|
| `id / node_id / number` | ID、所属代理、从 1 开始的分段序号 |
| `end_kind` | `write/spawn/return/open`；open 是选中范围结束时尚未遇到边界 |
| `event_ids / event_count` | 边界之前的叶事件及数量；**不包含结束它的写入/调用/返回** |
| `tree_event_ids` | D2 合并后的显示顺序，叶事件与组事件混合 |
| `ending_event_ids` | 结束本段的一个或多个事件；连续写入之间无任何事件就合并；调用、返回各自结束一段，不与写入合并 |
| `writes` | 结束本段的写入明细，并附 `event_id`；包括一个请求内的多个 Edit |
| `request_range` | 包括段内事件和边界事件的最小/最大请求号 |
| `ending_request_range` | 树中标题使用的边界请求范围，如 `[25,27]` |
| `operation_counts / image_count` | 各操作的叶事件数；图片是 read 的子集，另给图片数用于核对 |
| `context_request_id / context_composition_id` | 最后一次边界请求与其上下文构成；open 使用段内末次事件请求 |

例如分段有两个读取事件，随后 #5 Write 与 #6 Edit，中间只有写入回执，则 `event_count=2`、`ending_event_ids` 有两条、`ending_request_range=[5,6]`。事件数按叶事件计，D2 不改变数量。相邻同文件同操作的写入仍保留每次记录，树把连续同名边界显示为 `×N`；同操作只写一次，例如「写入 替你写的.md、文章.md」，混合操作为「写入 替你写的.md，编辑 图片说明.md ×3」。

## 初始上下文与上下文构成

`Node.initial_context` 包含第一请求锚点 `request_id`、总 `characters` 和 `categories`。子代理类别为 system、tools、injected、task；主代理为 system、tools、injected，有范围开始前的对话时另加 history（范围开始前的对话），用户消息沿用链路事件。每类有 `label/item_ids/characters/entries`；entry 有 `item_id/content_ref/characters/first_request/available_in_first_request`。工具 entry 另给 `name/description_ref`，页面可只显示名字和说明。history entry 使用 content_refs 数组引用首个请求中的原文切片（content_ref 为空），不包含后来加入的内容，也不重复存储图片。

主代理初始上下文严格取范围内第一个请求的内容。子代理维持 T3a 口径：注入内容沿用 v1 的整个 automatic 分组，因此实际在 #2 才加入的延后工具/环境等也列在这一入口中，**不伪称它在 #1 已经存在**：entry 的 `first_request` 和 `available_in_first_request` 保留真实出现时机。各分段的上下文构成只计算当次实际存在的内容，不使用这里的汇总替代。

`Composition` 有 `id/node_id/segment_id/request_id/characters/categories`。固定八类：

| key | 显示名 |
|---|---|
| system | 系统提示词 |
| tools | 工具定义 |
| injected | 注入内容 |
| task | 任务提示词 |
| previous | 之前分段的事件 |
| current | 本分段的事件 |
| model | 模型输出 |
| reminders | 提醒 |

每类为 `{label, characters, item_ids, event_ids, parts}`；part 是 `{raw_ref, characters, item_id, event_ids}`。链接点击优先定位 event，没有事件时定位初始上下文/模型输出等 item。按结束请求的 ownership 逐个位置计数，保留截断、压缩、已移除消息的真实状态；多文件共享输出只计一次。模型的文字/thinking 数正文，工具定义、tool_use 参数块及 tool_addition 按 `json.dumps(..., ensure_ascii=False)` 计结构字符；签名和图片 base64 不计为文字。原始图片 token 只能由 API 的 usage 反映，不从字符估算。

## FileReference 与 File：点击路径和侧栏

| FileReference 字段 | 含义 |
|---|---|
| `id / source_id / text_ref` | 引用 ID、展示字符串的 source ID 与完整 Ref |
| `start / end` | 相对此展示字符串的 Unicode 码点范围，前闭后开；JS 必须先 `Array.from(text)` |
| `owner_ids / node_id / source_path` | 所属事件/条目、代理、这段文本所属文件（非文件文本为 null） |
| `path / file_id / resolution_level` | 唯一解析到的绝对路径、侧栏 ID、命中第 1–5 级；目录的 file_id 为 null |
| `kind` | `file` 或 `dir`；旧数据缺省按 file 处理 |

扫描事件内容、读到的内容、任务提示词、用户消息、返回、写入/编辑前后文本、注入内容、系统提醒，以及页面可见的命令/参数、系统提示词和工具说明。不扫 base64 或模型 thinking。相同文本在不同文件目录/代理中可以解析成不同目标，不能仅按 source ID 合并引用。

解析顺序固定为：①绝对/`~/`；②文本所属文件的目录；③代理 cwd；④链路中读取/写入路径的后缀；⑤所属文件目录下递归按后缀找。不遍历目录符号链接。某一级有多个匹配就不链接，不拿更低级覆盖歧义；不存在且未被链路记录的文件不生成引用。只认带扩展名的文件；保留代码/引号内带空格路径；URL 不当本地文件。

目录沿用五级顺序，仅识别绝对路径、`~/` 路径或以 `/` 结尾的相对路径；每个目标必须是当前存在的目录。第④级使用链路文件的父目录及祖先目录，第⑤级按目录后缀查找。目录路径与紧随其后的文件名作为一个完整 token 解析，不拆成两个引用。`files` 中不加入目录，也不读取目录内容作为侧栏快照。

页面目录链接同样下划线，带 `data-path` 和 `data-kind="dir"`，href 为逐段 URL 编码的 `vscode://file/<绝对路径>`；普通点击跳转 VS Code，不开侧栏、不定位链路。文件链接 `data-kind="file"`，仍走侧栏。Command 点击与右键菜单沿用文件操作（Finder、VS Code、复制路径），不安装或改动 Finder 小程序。

`files` 为绝对路径 → File，每个文件一条，已读、已写或仅被引用的文件都包含：

| 字段 | 含义 |
|---|---|
| `id / path / display_path / exists / type / bytes` | 文件 ID、真实/显示路径、存在性、text/image、当前磁盘字节数 |
| `event_ids / reference_ids` | 链路中读取/写入/编辑事件与文字引用；纯引用文件的 event_ids 为空 |
| `comparison_status / comparison_basis` | 与当前文件的比较结果和证据；没有历史读取证据就是 unavailable |
| `content_ref / content_version` | `current` 为当前磁盘全文；`last_read` 为模型最后一次读取版本；图片为 recorded/path_only |
| `last_read_event_id / last_read_request_id / last_read_request_number` | 最后一次读取的位置；改过的文件用于侧栏版本提示 |
| `read_ranges` | `{start,end,kind,event_id,request_id}` 数组；行号 1-based，两端含；全文为 kind=full |
| `image_ids / omitted_reason` | 已读取图片的原图片池引用；文本未嵌入原因 over_1mb、not_text、not_utf8_or_unreadable、missing、no_recorded_read |

全文读取按全文逐字符比较（忽略传输丢失的末尾换行）；部分读取即使片段一致，文件 mtime 晚于代理结束也判为变更。晚于最后读取的成功 Write 全文是更近的比较证据。变更或文件已消失时，只能指向最后实际读取内容；没有历史读取就保留空内容和客观状态。

未变更/仅被引用的文本只在当前文件不超过 **1 MiB（1,048,576 bytes）** 时嵌入；读入时再次限长，排除 NUL/非 UTF-8。已经保存在原记录中的大内容可继续由引用定位，不额外复制磁盘大文件。未读取过的图片只记路径，不加载图片字节。

读取区间只在 current 版本上给出。Read 的 offset/limit、head/tail 行数、sed 的数值行区间及可确定的流水线可映射；grep/rg/awk、字节截取、截断和共享输出不给行号。多个事件的区间分别保留，用 event_id 定位，不把它们伪装成同一次全文读取。

## 输出切分、总览与校验

Bash 的 echo 分隔串在工具输出中必须是完全相等的一整行。按命令顺序分桶，重复分隔串允许重复出现，但出现次数必须和命令一致；缺少、额外或乱序标记时保留共享输出。一个桶仍含多个文件时，每个事件只取得该桶，`shared_with` 列其他文件。原始 v1 read 的 raw_ref/visible_ref 仍保留；页面使用 v2 content_ref。

调用整体失败不再自动丢弃其全部读取：对命令里全文读取的文件，仅在当前全文逐字出现在已记录输出中时恢复该读取，保存 `result_text_slice`（相对原工具结果文字的码点位置），按命令顺序匹配；未匹配的后续文件不假定读过。恢复读取保留 call_failed=true，但 failed=false，原始失败结果和哈希均保留。磁盘上存在本身不算读取证据。

能静态确认的 cat heredoc 正文也有 content_ref，追加片段标为 append；未加引号且含变量/命令替换的 heredoc 不冒充执行后的内容。同次调用多次改同一路径时不把其中一个字面量当最终全文。脚本产出的内容优先使用该调用实际返回的独立读取片段，无法恢复时仍保留命令和写入路径证据。

`Node.overview` 提供 `request_count/start/end/context_tokens/operation_counts/image_count/read_files/written_files`。读取文件表有 `path/display_path/count/first_request/characters/event_ids`；写入表有 `path/display_path/count/event_ids/write_ids`。有 --focus 时，`focus_coverage` 每个文件有 `path/display_path/appeared/event_ids`，只描述是否出现在该代理链路里，不作应不应该读取的判断。

`trace_overview` 的边沿用 v1 dispatch/file_flow，增加统一的两端节点 ID、事件 ID；file_flow 继续保留具体版本 `version_write_id/version_request_id/read_id/read_request_id`。没有重新推断“看起来相关”的连线。

`verify.py` 除 v1 校验外，还检查 v2 引用、叶事件与分段覆盖、D2 展开、统计、上下文构成加和、侧栏读取区间和文件链接。原日志已经存在的 blob 哈希冲突仍如实保留 `stored_blob_hash_conflict`，不会修改原记录或重写声明哈希以得到零差异。实际生成会话数据只存用户指定的本地文件，不写入仓库。

## 入口与边界

Python 3.9+，只用标准库。`trace.py` 和 `verify.py` 均支持 `python3 -I`，仅补入脚本自身目录以加载同目录模块。入口是 `skills/agent-context-trace/scripts/trace.py`，三个子命令：

```sh
python3 -I trace.py list --projects-dir ~/.claude/projects --since 2026-01-02 --grep demo
python3 -I trace.py find --file ~/demo/report.md
python3 -I trace.py find --file ~/demo/report.md --json > /tmp/find.json
python3 -I trace.py data --from-output ~/demo/report.md --focus ~/demo/rules -o /tmp/trace.json --tree
python3 -I trace.py data --node /tmp/session.jsonl --range 10-15 -o /tmp/range.json
python3 -I trace.py data --focus ~/demo/rules --since 2026-01-02 --until 2026-01-03 -o /tmp/focus.json
```

`--projects-dir` 默认 `~/.claude/projects`，三个命令均接受。`--node`、`--focus` 可重复；`--range` 是主会话的全局请求号，含两端，不作用于子 agent。日期按北京时间解释；`--until YYYY-MM-DD` 包含当天，精确时间作为不含端点的结束边界。只给关注文件时按时间过滤请求，不支持的旧记录跳过；点名不支持的节点直接报错。

`find` 默认只打印会话、节点、请求号、方法、证据、时间、脚本名，不打印可能含密钥的命令。`--json` 保留完整命令。`data` 需要 `-o` 或 `--tree`；`--tree` 只显示结构、文件名、简短命令标题和计数，不打印提示词与工具输出正文。JSON 本身保留原文，应当留在本地；新建 JSON 权限为 `0600`。脚本不执行会话里的任何命令、不修改源记录或被分析文件。

退出码：`0` 成功；`find` 的 `1` 表示没有候选；`2` 是无法完成（按哈希找不到消息、没有范围、旧格式等）。Claude Code 存储 blob 自带的哈希与完整内容不符，不属于还原失败：保留原文及 `hash_mismatches/issues`，与真正缺失消息的 `missing_messages` 分开记录，退出码仍为 0，文字树不额外显示校验提示。

`python3 -I verify.py --node <日志>` 可重复，验证还原；`python3 -I verify.py --data <JSON>` 可重复，校验引用、图片哈希、逐请求原文覆盖和消息哈希。校验只打印统计；记录自带的 blob 哈希差异不影响成功退出，消息缺失或产物完整性校验失败返回 2。合成回归：`python3 -m unittest discover -s skills/agent-context-trace/scripts -p 'test_*.py'`。

## 编号、原文与计数

- 请求号是节点自身日志中 `api-request` 的顺序，从 1 开始。主会话范围不重新编号。读取的“第 N 次起”来自工具结果首次实际进入请求；写入的“第 N 次”来自该次模型回复。
- 时间原值保留为 UTC ISO 字符串，`*_bjt` 为带 `+08:00` 的 ISO 时间。文字树、list、find 显示北京时间 `01-02 08:00`；树顶同日范围压成 `01-02 08:00–08:10`，跨天时两端都带月日。节点结束取最后回复时间；不取之后无关记录的时间。
- 字数是 Python `len(str)`，即 Unicode 码点数，不是 UTF-8 字节数、汉字数或 token 估计。工具定义按 `json.dumps(tool, ensure_ascii=False)` 的默认空格计数，再逐工具求和；不包含外层列表的括号和分隔符。系统提示只数文本；指令文件只数文件正文。文件读取数工具实际给模型的文本（包括传输行号），共同输出会在各文件条目下各计一次，不能跨文件直接相加当作上下文总字数。图片 base64 不算文字。
- `group_stats.characters` 是条目展示字数之和；`last_context_characters` 是最后请求归属切片的字数：字符串按长度，文本块按正文，其余结构按 `json.dumps(..., ensure_ascii=False)` 计数，图片使用去重引用表示。它们口径不同，前者用于树，后者用于审查归属，均不估 token。
- 上下文 tokens 只取该次回复最后一条 usage 的 `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`；没有 usage 就是 `null`。
- 消息哈希使用 SHA-256，输入为 `json.dumps(message, sort_keys=True, separators=(',', ':'), ensure_ascii=False).encode('utf-8')`。回复按 `apiBlockIndex` 排序，保留 `caller`，优先使用 `wireToolInputs`；工具结果与随后 `isMeta` 的字符串或列表说明合并。缺消息直接失败；已有 blob 的哈希冲突保留 blob 原文及冲突证据。
- 字符切片 `start/end` 也按 Unicode 码点，前闭后开。**T2 的 JavaScript 应用 `Array.from(text).slice(start, end).join('')`，不要直接按 UTF-16 下标 `text.slice()`。**

WriteCandidate 使用 Write 的 `path/method/evidence/confidence/inputs/script` 字段，没有 id、请求和原文引用。

产出比较只采用最后一笔的 Write 全文，或最后一笔之后、范围内最后一次独立的全文读取。没有证据就为 `unavailable`，不会把追加/修改前的旧 Write 当成最终版本，也不会运行生成脚本。

命令解析用 shlex 拆分 `; && || |` 和换行，保留引号里的分隔符；跟踪 `cd`、字面量变量赋值及已知 `$PWD/$HOME`；不执行变量、命令替换或脚本。glob 只按当前磁盘展开。head/tail 的带值选项、grep 的上下文选项和模式、sed/awk 脚本均不当文件。未解出的变量保留在命令输出，不假造路径；heredoc 正文从 shell 读取识别中移除，内联脚本的相对路径按该 heredoc 命令开始时的 cwd 解析，不受后续 cd 影响。Python/JavaScript 内联脚本仅以静态字面量和写文件调用识别目标，读入文件不会因为同段代码写了另一个文件就变成产出。

脚本的长选项 `--xxx` 后紧跟的非选项值以及 `--xxx=value` 的值不当位置参数，不进入推断写入候选。只有 `-o/--output/--out/--output-file` 的值算明确输出，记 `explicit`。位置参数生成仍属于推断：优先取与首个输入同格式的最后文件（允许末尾额外图片参数），否则取末尾文件；候选尚不存在、或候选与首个输入同目录同格式，记 `inferred`。已存在的异目录参数可能全是检查工具的输入，记 `ambiguous_argument`，保留在产出和命令候选中，不用来自动扩展文件流转。当前磁盘状态影响这种推断；evidence/confidence 必须向用户保留。

`find` 与 `--from-output` 共用选择顺序：文件还存在时先排除操作时间晚于当前文件 mtime 的候选；Write、Edit、重定向、heredoc 写文件、明确输出选项等优先于位置参数推断；同类里最后一笔排在首位，data 选择首项。文件不在时无法应用 mtime 过滤，其余顺序不变。这不改变历史文件流转的时间线。

关注状态只有 `读全了 / 读了一部分 / 没读到 / 只运行过没读内容`。目录递归展开、忽略 `.DS_Store`、重复关注路径去重；自动带上的指令文件也能命中 M2。文字树先列读到的文件，再列仅运行过的文件，末尾单列“没读到 N 个”及文件名；JSON 的 focus 顺序不变。主会话派活条目的请求号显示“第 N 次派”，读取仍显示“第 N 次起”。多节点读取次数从各 `item.reads` 取，不能把不同节点的第 N 次视为同一全局时间线。

派活沿 meta.toolUseId 逐级找父亲。父为主会话时只保留该工具调用和之前最近的真实用户消息，排除 isMeta、工具结果、纯 system-reminder 与压缩总结；父为子 agent 时补完整节点。`--from-output` 沿同会话文件写入递归补子 agent。文件版本取读之前的最后写入；主会话中间改过同一路径，会使更早子 agent 的版本失效，不能把旧版本冒充为实际读到的版本。文件流转是时间和路径证据，不宣称语义因果，也不能察觉未记录的外部编辑。

T2 连线入口：M4/M7/M8 的 `request_ids` → M12；M11 每一笔 `context_request_id` → M12；M12 的 `context_item_ids` → 各组条目；派活 edge 两端互跳；file_flow 指定具体 Write 与 Read；M2 的 `item_ids` → 各节点 M8/M7。显示派生树时，主会话与直接子 agent 同级呈现；子 agent 再派出的节点按 parent_id 缩进。图片在文件条目所在目录内显示，不另建图片区。
