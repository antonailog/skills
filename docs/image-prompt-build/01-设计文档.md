## 0. Skill 化决策（S0）

满足的资格条件：☑ 会重复使用 ☑ 容易被路由错 ☐ 有脚本能省重复劳动 ☑ 需要治理

- **重复使用**：生图横评一周内写了 37 题、四轮审题；公众号头图、写真、Seedance 首帧、砼核壁纸都是同一件事——把一句需求写成生图 prompt。
- **容易被路由错**：「写个 prompt」现在会落到 prompt-craft，而 prompt-craft 是给 LLM 写任务指令的（九模块、防注入），套到生图上全错；「收录 prompt」归 prompt-vault；小红书封面归 xhs-note。
- **需要治理**：模型参数在变。GPT Image 2.6 美国时间 11-04 才发布，Flare / Sunburst、quality、complexity 这些旋钮只该在一个地方维护、写明核实日期，不该每次凭记忆现编。

替代方案和为什么不选：
- 扩展 prompt-craft：它的架构（角色、输出格式、注入防御、对抗审查）是为 LLM 指令设计的，生图 prompt 用不上，硬塞会让两边都变胖。
- 写进 CLAUDE.md：模型参数卡和模板加起来几百行，每个会话都加载，太贵。
- 不做：基线对照会回答「Claude 不读 skill 写得有多差」。预期差距在：参数名和取值、编辑类的保留项、画面文字的写法、梗角色先对图。

## 1. 收料结论（S1）

### 1.1 需求与场景

- **使用者与处境**：作者本人（独立开发者、自媒体作者）在会话里要一张图——公众号配图、横评题目、写真、视频首帧、海报、信息图，或者改一张已有的图。也包括别的工作做到一半需要出图的时候。
- **现在怎么解决、哪一步最烦**：让 Claude 现写。三处返工有记录：
  1. 梗角色长相写错（大肥鱼写成头顶鲸鳍、豆姐写成黑 T 恤），四个模型跑完才发现，28 张重跑（11-06）。
  2. 跑之前没给作者审 prompt，作者要求以后「先给 prompt + 目的 + 输入图审过再批量跑」（11-06）。
  3. 参数版本多：2.6 Flare / Sunburst、2.5、Nano Banana Pro / 2.1、Seedream 5.0 Pro，每家旋钮不同，每次重查。
- **理想产出**：能直接复制的 prompt 原文 + 这张图做什么用 + 用哪个模型、参数怎么设（单列，不混进 prompt）+ 出图后看哪几处。
- **什么算做对了**：作者审一遍就能说「跑」；出图后的翻车点在「看哪几处」里提前点到了。

### 1.2 已有决策与约束

| 类别 | 内容 | 可否推翻 |
|---|---|---|
| 交付到哪 | 只交 prompt 和参数，不调生图。出图走现有路线：没指定模型用 codex 内置 image_gen（全局 CLAUDE.md），指定模型走 Lovart 命令行 | 否（作者 11-06 定） |
| 覆盖模型 | GPT Image 2.6（Flare / Sunburst）、GPT Image 2.5、Nano Banana Pro、Nano Banana 2.1、Seedream 5.0 Pro；codex 内置生图按 GPT Image 写法 | 否（作者 11-06 定） |
| 评测深度 | 触发评测 + 有 / 无 skill 各写一版 prompt 按判分标准比，不真出图 | 否（作者 11-06 定） |
| 语言 | prompt 默认中文（作者全部历史 prompt 都是中文，几家模型中文理解都够）；画面里要出现的英文原样保留 | 作者要英文可改 |
| 作者偏好 | 先审后跑；梗角色和二创形象先找图对长相；真人照片不上网，参考图用授权图或生成的虚拟人 | 否（记忆里的明确反馈） |
| 合规 | 不替作者判断能不能二创（梗角色是他的选题），但真人肖像不写成「某某本人」 | 可讨论 |

参考对象及不借鉴什么：

| 参考 | 借鉴什么 | 明确不借鉴什么 |
|---|---|---|
| 调研报告 | 视觉规格书的公式、编辑类「只改 / 保持 / 禁止」结构、失败模式表、场景模板 | 未核实的参数（以 02-事实核对 为准）；16 个模板全量照搬；「建 10–30 题 benchmark 测误改率」那套工程团队流程 |
| prompt-craft | 「规程优于形容词」：「高质量」改写成看得见的规格 | 九模块架构、注入防御、对抗审查清单——都是 LLM 指令专用 |
| xhs-note 的 cover-image.md | 「写死到模型不需要再做设计决策」；需求模糊时先出方向再写 | 调 codex 的命令（本 skill 不出图）；3:4 固定规格 |
| 横评审题文件 | 交付格式（目的 / 画幅 / prompt 原文分开）；角色外形写成一段固定描述、多题复用 | 「四个模型同一 prompt 原样跑」——那是评测的公平要求，日常用要按模型调参数 |

### 1.3 基建盘点

本 skill 不编排 tool，只用 Claude 自带能力：

| 能力 | 什么时候用 | 必调/看情况 | 失败时 |
|---|---|---|---|
| Read 看参考图 | 用户给了图片路径（要照着写、要编辑、多图合成） | 看情况 | 读不到就请用户确认路径，不凭文件名猜内容 |
| WebSearch / WebFetch | 需求里有梗角色、吉祥物、特定实物的外观 | 看情况 | 找不到图就请用户发截图；prompt 里写出打算用的外形描述并标「待确认」 |

没有 schema 要逐字段标注（门禁第 4 条按「无 tool」处理）。

## 2. 设计

### 2.1 要解决的问题

把一句出图需求写成一份能直接粘进指定模型的视觉规格书，并把该走接口参数的东西单独列好，作者审一遍就能跑。

### 2.2 定位与边界

**定位**：给生图模型写「视觉规格书」的美术指导——把「摄影师或设计师拿到这段话能不能直接开工」讲透：每一句都是画面里看得见的东西，模型不用再替你做设计决策；画面里的字逐字给定；尺寸、质量这类旋钮交给接口参数，不写进 prompt 碰运气。

**核心立场**：作者要的是一张能用的图，不是一段好看的咒语。所以 prompt 只写可见状态（主体、构图、光、材质、文字、要保留的、要排除的），每个模型的旋钮按它真有的参数单列；拿不准的外观（梗角色、真实产品）先对图，不猜。

**范围**：给定一个出图需求（文字，可带参考图、目标模型、用途），产出 prompt + 参数 + 看图要点。一次一张图的需求；同一需求的一组图（故事板、同一人多场景、GIF）算一个需求；批量多题时逐题按同一格式出。

**不处理**：

| 不处理什么 | 交给谁 |
|---|---|
| 给 LLM 写任务指令、system prompt | prompt-craft |
| 收藏、整理、入库别人的 prompt | prompt-vault |
| 视频 prompt（Seedance、即梦、可灵的镜头运动） | 不处理；头像转头视频归 avatar-look |
| 小红书笔记封面（在写笔记的流程里） | xhs-note |
| 活动推送海报（HTML 渲染，不是生图） | ai-events-push |
| 实际出图、批量跑图 | codex image_gen（全局规则）/ Lovart 命令行 |
| 比较模型谁画得好、该订哪家 | 直接回答或 deep-survey |
| 网页、App 界面设计稿 | forge-design / impeccable |

**很像但不该触发的 query**（门禁第 1 条）：

1. 「帮我写个 prompt，让模型给评论区每条打情绪分」→ prompt-craft
2. 「这条 Midjourney 提示词挺好，帮我存进 prompt 库」→ prompt-vault
3. 「给 Seedance 写个提示词：猫在灶台前炒菜，镜头慢慢推近」→ 视频，不归这里
4. 「这篇小红书笔记写完了，配个封面」→ xhs-note
7. 「这篇文章里每张图下面都附了 prompt，帮我把它们存下来」→ prompt-vault（原 prompt 已经存在，要的是收藏，不是反推）
5. 「prompt 我写好了，直接用 codex 生成出来」→ 直接出图
6. 「GPT Image 2.6 和 Nano Banana 哪个人像更真」→ 直接回答

### 2.3 触发与意图路由

**触发层素材**

- 应触发：「帮我写个生图 prompt」「这张图怎么跟模型描述」「这个 prompt 出来字老是错，帮我改」「换件衣服别的不动，编辑指令怎么写」「三张参考图合成一张怎么说」「砼核风格手机壁纸，给我提示词」「把这段英文 prompt 改成 2.6 能用的」「信息图用 2.6 的 quality 和 complexity 怎么配」；英文 "write an image prompt for…"。哪怕用户没说 prompt，只说「我要一张 xx 的图，你先把描述写好」也触发。
- near-miss：见 2.2 的 6 条。
- 抢活的隔壁：prompt-craft（「写 prompt」字面重叠）、prompt-vault（「prompt」+ 文章链接）、xhs-note（封面）、avatar-look（头像图）。

**路由层分流**

| 意图 | 判断信号 | 应答 |
|---|---|---|
| 强 | 有具体画面内容（主体 + 场景或动作），用途、画幅、模型至少给了一样 | 直接出完整一套 |
| 弱 | 只有主题没有画面（「给这篇文章配张图」「来张好看的海报」） | 出 3 个画面方向，每个一句「你会看到什么」，标一个默认；默认那个的完整 prompt 同条写好，作者想换再换 |
| 改已有 prompt | 用户贴了 prompt 原文，或说某个 prompt 出图有问题 | 对照失败模式诊断 → 改写 → 列出改了哪几处 |
| 编辑 / 多参考图 | 给了图片，要「改」「换」「合成」「保持这个人」 | 走编辑结构：只改什么 / 改成什么 / 保持什么 / 匹配什么 / 别动什么 |
| 照图复刻（11-06 作者追加） | 给了图片，要「复刻」「反推 prompt」「照这个风格画个别的」 | 看图逐项写可见要素，字逐字抄，另列风格要点；默认纯文字 prompt |
| 潜在 | 在做别的（写文章、做页面），提到需要一张图 | 一句话问要不要先写生图 prompt，不展开 |

### 2.4 输出框架

**固定骨架**（每张图一套，顺序不变）

1. 一行：这张图做什么用 · 用哪个模型（不是作者指定的，就写一句为什么选它）
2. prompt 原文（代码块，整段可复制）
3. 参数（按出图渠道：API 字段 / Lovart 的附加说明 / ChatGPT 界面选项；不混进 prompt 原文）
4. 看图时查什么（2–4 条，指向这道题最可能翻车的地方）

**必出模块**

| 模块 | 入选条件 | 内部结构 | 对应考点 |
|---|---|---|---|
| 用途与模型 | 每题 | 一行 | K1 模型选择跟需求匹配（精细编辑、密集小字、多参考图各有更合适的） |
| prompt 原文 | 每题 | 交付物开头 → 主体与场景 → 构图 → 光线材质风格 → 画面文字 → 保留与排除 | K2 交付物开头；K3 只写可见状态（无 masterpiece / 8K / 扩散参数）；K4 画面文字逐字加引号、写位置、写「除此之外不要别的字」；K5 编辑类有「只改 / 保持 / 别动」；K6 多参考图逐张写角色；K7 内部不自相矛盾 |
| 参数 | 每题 | 按渠道分列 | K8 参数名和取值在该模型真实存在；K9 画幅、分辨率走参数而不是只写在 prompt 里（渠道没有参数时才写进 prompt） |
| 看图要点 | 每题 | 2–4 条 | K10 指向本题具体的风险点，不是「检查画质」这种空话 |
| （复刻专用） | 照图复刻时 | 同上 | K11 复刻 prompt 覆盖原图的关键可见要素（媒介、构图、光、主体、年代地域细节），图中文字逐字抄，不点名真人 |

**触发式模块**

| 模块 | 触发条件 | 命中多个时 |
|---|---|---|
| 外观待确认 | 需求里有梗角色、吉祥物、二创形象、具体真实产品 | 放最前面；没确认之前 prompt 照写，但标「待确认」 |
| 画面方向 | 弱意图 | 放在 prompt 前；只写默认方向的完整 prompt |
| 改动说明 | 改已有 prompt | 放在 prompt 后，≤5 条，每条「原来 → 现在 → 为什么」 |
| 风格要点 | 照图复刻 | 放在看图要点后，3–5 条；对应考点 K11 |

> 模块总数 8 个（必出 4 + 触发 4）。多模型版本并进「参数」模块（同一 prompt，每个模型一行参数；只有写法确实要不同时才分版本）；连续编辑计划并进「prompt 原文」（拆成第 1 轮、第 2 轮）。

### 2.6 辅助资源

| 资源 | 类型 | 为什么需要 |
|---|---|---|
| models.md | references/ | 各模型参数卡（模型 ID、quality / complexity / 尺寸 / 参考图上限、渠道差异），带核实日期和来源；写参数段时才读 |

### 2.7 输入输出定义

**预期输入**：会话里一句或几句出图需求，可能附图片路径、目标模型、画幅；也可能是一段已有 prompt 加一句「出图有问题」。

**真实 query 样本**（从横评项目和作者平时用法里来）：

1. 「横评再加一题：DeepSeek 的大肥鱼坐在工位上抱着一大碗白米饭吃，二次元，3:4，四个模型都要跑」
2. 「猫子柒那种，写实，异瞳白猫在四川小院土灶前炒回锅肉，给 Seedance 当首帧，16:9，用 Nano Banana 2.1」
3. 「做一张豆姐和大肥鱼的电影海报，片名《在线等，挺急的》，标语和上映日期都要对」
4. 「照着这张 1985 年西宁街景写个 prompt，让模型生成一张以假乱真的，原图不给它看」（附图片路径）
5. 「把 图/参考图/ref-人像.png 这个人放到海边，换白衬衫，脸别变」
6. 「这篇公众号讲 AI 模特图翻车，配一张头图，16:9，别太吓人」
7. 「这个 prompt 出来字老是错：一张科技感海报，写上未来已来，8k，大师作品，超高清——帮我改成 2.6 能用的」
8. 「帝王蝶生命周期四个阶段的科普图，只要四个标签，用 2.6 sunburst，quality 和 complexity 怎么选」
9. 「这张图（附砼核巨构图路径）的 prompt 帮我反推一下，我想换成沙漠里的场景」——11-06 作者追加的复刻用法

**预期输出**：按 2.4 的骨架，Markdown，prompt 在代码块里。
