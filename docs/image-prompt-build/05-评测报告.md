# image-prompt 评测报告（v1，2026-11-06）

## 结论

10 道真实出图需求，带 skill 的回答盲评平均 18.5 分，不带的 12.1 分。增益集中在 Claude 自己不知道或想不到的地方：新模型的参数、梗角色外观先对图、看图要点、需求模糊时给方向。写法层面的老规矩（第一句说交付物、不写 8K 和 masterpiece、编辑写保留项）两边一样，Claude 本来就会，第一轮迭代已经把这些从 SKILL.md 删掉；删完重跑受影响最大的三题，分数持平，花费降 15%、耗时降 20%（见 06-迭代记录）。

代价：每条回答花费约 2 倍（0.81 vs 0.43 美元），耗时约 2 倍（188 vs 87 秒），篇幅约 1.3 倍（平均 2441 vs 1836 字）。

## 这份评测靠不住的地方

1. **考点是按 skill 的设计定的**。看图要点、外观核对、给方向这几项是 skill 自己规定的交付格式，without 组没人告诉它要给，分差里有一部分是「按考卷答题」。真正不依赖格式的增益是 K8（参数）和 K12（外观），这两项的失败在横评里真实发生过。
2. **评委可能偏爱更长、更有结构的回答**。with 平均长 1.3 倍。
3. **每题只生成了 1 次**，生成本身的波动没测；盲评 3 次几乎没有波动，说明评委稳定，不说明回答稳定。
4. **没有出图**。prompt 更规范不等于图更好，这一点没有证据。
5. **没测触发**。不知道用户自然说话时它会不会被调起。
6. **评委对考点的批评**（本机 `runs/judge/*.json` 的 rubric_critique）：回答完全不给参数时 K8 该怎么判没写清；K8 和 K9 会为同一个错误重复扣分；K10「2 条以上」门槛太低；K12 和 U 有张力（为确认外形留占位，可能在 U 上被当成「还得追问」）；把事实表之外但真实存在的模型（Seedream Lite）判成编造偏严。
