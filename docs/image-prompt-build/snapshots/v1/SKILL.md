# image-prompt — 把出图需求写成视觉规格书

交付一套能直接用的东西：prompt 原文、按模型列好的参数、出图后该查哪几处。不调生图工具。

## 定位与边界

像一个给生图模型写规格书的美术指导。判断标准只有一个：摄影师或设计师拿到这段话，能不能不再问问题就开工。所以每一句都是画面里看得见的东西，模型不用替你做设计决策；画面里的字逐字给定；画幅、分辨率、质量交给参数，不写进 prompt 碰运气。

用户要的是一张能用的图，不是一段好看的咒语。「masterpiece、8K、大师作品、超高清」这类词不提供任何画面信息，这一代模型读的是句子，删掉它们，换成具体的主体、光和材质。拿不准的外观（梗角色、吉祥物、具体产品）先对图，不凭文字报道猜。

边界之外的交出去：给大模型写任务指令交给 prompt-craft；收藏、入库别人的 prompt 交给 prompt-vault；视频提示词（Seedance、即梦、可灵）不在这里写，头像转头视频归 avatar-look；写小红书笔记时的封面归 xhs-note；prompt 已经写好只要出图，没指定模型走 codex 内置生图（全局 CLAUDE.md 的生图规则），指定模型走 Lovart 命令行。

## 按需读取

| 文件 | 什么时候读 |
|---|---|
| `references/models.md` | 写参数段之前；用户问某个模型怎么设、哪个模型适合 |
| `references/templates.md` | 需求属于常见一类（人像、动物首帧、产品、剧照、大场景、年代照、海报、封面、信息图、Logo、插画、组图、GIF、局部编辑、多图合成）时，写之前先看那一节 |

## 意图分流

| 意图 | 信号 | 怎么应答 |
|---|---|---|
| 强 | 有具体画面（主体 + 场景或动作），用途、画幅、模型至少给了一样 | 直接出完整一套 |
| 弱 | 只有主题没有画面：「给这篇文章配张图」「来张好看的海报」 | 出 3 个画面方向，每个一句「你会看到什么」，标一个默认，默认那个的完整一套同条写好。不停下等他挑——他想换再换 |
| 改已有 prompt | 贴了 prompt 原文，或说某个 prompt 出图有问题 | 对照第四步的自查表诊断，改写，附改动说明 |
| 改图 | 给了图，要「改」「换」「合成」「保持这个人」 | 第三步的编辑写法 |
| 照图复刻 | 给了图，要「复刻」「反推 prompt」「这张图怎么写出来的」「照这个风格画个别的」 | 第三步的复刻写法 |
| 潜在 | 在做别的（写文章、做页面），顺口提到要一张图 | 一句话问要不要先写生图 prompt，不展开 |

批量多题（横评、组图）：逐题按同一套格式出，几题共用的角色或产品描述先单独列一次，再在每题里原样复用。

## 第一步 读需求

拿出六样：用途、画面内容、画面里要出现的字、参考图、目标模型、出图渠道。

- 有参考图就先打开看，写 prompt 时描述你看到的、跟这次需求有关的东西，别凭文件名猜。
- 画面里要出现什么字，用户没说而这张图又需要字（海报、封面、信息图），问一句；别替他编文案。其他缺项按常见做法补，交付时一句话说明替他定了什么。
- 信息图、图表里的数字和事实，只用用户给的或有出处的。模型补的数据是编的，印在图上发出去就收不回来。

**外观核对**：需求里有梗角色、吉祥物、二创形象、具体真实产品时，先搜 1–2 张图给用户确认「是不是这个」，同时写出你打算用的外形描述。找不到图就请他发截图。确认之前 prompt 照写，但在最前面标「外形待确认」。二创形象版本多、文字报道描述不全，凭描述写错了要等整批图跑完才发现。

## 第二步 选模型和渠道

用户指定了模型就用他的。没指定时默认 codex 内置生图（全局生图规则的默认路线），按 GPT Image 的写法写。需求明显更适合别的模型时（要 GIF、要多张参考图融合、要超长横幅……），按 `references/models.md` 第 0 节提一句建议，理由写一行。选定后读那个模型的一节：prompt 长度上限、比例写在哪、哪些参数会报错，每家不一样。

渠道决定参数写在哪：

| 渠道 | 参数写在哪 |
|---|---|
| API | 请求字段，prompt 里不重复 |
| Lovart 命令行 | 发给 Lovart 的前置说明里（画幅、分辨率），prompt 前加「原样使用、不改写」 |
| ChatGPT / Gemini 网页或 App | 界面里能选的去界面选，选不了的写进 prompt 末尾 |
| codex 内置生图 | 没有可调参数，画幅写进 prompt |

参数卡里没有的模型（Midjourney、Flux、即梦等）：用通用写法，参数段写「这个模型的参数没核过」，不编参数名。

## 第三步 写 prompt

### 顺序

交付物 → 主体 → 场景 → 构图 → 动作 → 光线 → 材质 → 风格 → 画面文字 → 要保持的 → 要排除的

不是每一格都要填，对画面没影响的就不写。复杂的图可以按「场景：」「主体：」「文字：」「约束：」分段，方便读和改；格式本身没有魔力，JSON 也一样，选最好读、好改的。

### 写法

1. **第一句说交付物**：「一张电商主图」「一帧电影剧照」「一张竖版信息图」。交付物一说，模型就知道该用什么版式、光和精度，后面的描述都按它来规划。
2. **只写看得见的**：「高级感」写成什么材质、什么光；「氛围感」写成雾、逆光还是暖色窗光。要写实就直说「真实照片 / 写实摄影」，相机型号、镜头焦段只是外观提示，模型不会真的按物理去算。
3. **空间关系说死**：谁在左、谁在右，前景中景背景各是什么，主体占画面多少，看向哪里。一个画面只定一个景别。
4. **画面文字逐字给**：放进「」里，写位置、字体类别、出现几次，最后一句「除此之外画面里不要有其他文字」。生僻词、品牌名可以逐字拼出来。字越多越容易错，能删就删。
5. **数据给全**：信息图、图表的每个数字和标签都写进 prompt，再加一句「不要补充我没给的数据」。
6. **固定外观写成一段固定描述**：同一个角色或产品出多张时，那段描述每张原样复用。措辞一变，模型就当成另一个角色。
7. **写实要写不完美**：毛孔、碎发、衣服褶皱、随手拍的构图、胶片颗粒。不写的话，默认出来的是棚拍精修感。
8. **排除项少而具体**：先正面描述想要的状态（「空无一人的街道」比「不要有人」可靠），末尾只留 1–3 条最容易出错的排除（多余文字、水印、某个已知的翻车点）。几十个负面词堆在一起，模型分不清哪个重要。
9. **不写扩散模型的参数**：CFG、steps、sampler、seed、负面提示词字段，这几家都没有对应接口，写进 prompt 只是噪音。画幅、分辨率、质量按 models.md 放在该放的地方：多数走参数；Seedream 官方建议比例写进 prompt；codex 没有参数只能写进 prompt。

### 改图和多参考图

编辑按这个顺序写：只改什么 → 改成什么 → 保持什么（身份和脸、姿势、背景、机位、裁切、光线）→ 新的部分要匹配原图的透视、阴影、色温 → 不要加别的。

「保持什么」那句别省，省了模型常会顺手改脸和背景。一次要改很多处时拆成几轮，每轮一个维度，按「第 1 轮、第 2 轮」分别给 prompt——一次改五处，漂了说不清是哪处带的。

多张参考图逐张写角色：「图1 是人物身份，图2 是服装，图3 是场景」，并在交付里写明按什么顺序上传。一张图只担一个角色。

### 照参考图复刻

用户给一张图，要写出能把它重新生成出来的 prompt：

1. 打开图仔细看，按上面的顺序逐项写看到的：它是什么（照片、插画、海报、截图）、主体的外形、场景、构图（景别、机位、主体位置、前中后景）、动作、光（方向、软硬、色温）、材质、媒介和质感（胶片颗粒、笔触、上色方式）。画面里的字逐字抄下来，看不清的标「看不清」，不猜。
2. 写看得见的特征，不写猜出来的名字：图里的真人不认、不点名，只描述外形；风格写成看得见的特征（「低饱和冷灰、阴天漫射光、大面积留白」），不写「这是某某画师的风格」——猜错了，模型会照着错的名字画。
3. 另列 3–5 条「风格要点」：保留这几条就还是这个味道。用户想换主体（「照这个风格画一只猫」）时，保留风格要点、换掉主体那几句。
4. 默认只给纯文字 prompt，换哪个模型都能用。渠道能传参考图时，加一句提醒：把原图一起传、prompt 开头写「参照图1 的风格和构图」，会更像。

「看图时查」写复刻最容易走样的地方：光的方向、画面比例、年代或地域细节、画面里的字。

### 改已有 prompt

先用第四步的表找出问题，再改写。改动说明最多 5 条，每条「原来 → 现在 → 为什么」。原 prompt 里对的部分不动。

## 第四步 自查

写完对一遍，命中就改：

| 症状 | 为什么不行 | 改成 |
|---|---|---|
| 「美女，电影感，8K，masterpiece，超细节」 | 没有主体关系、构图和光线，模型只能自己猜 | 写清人物、动作、场景、景别、光线、材质、用途 |
| 「超广角特写，全身，远景城市」 | 空间指令互相打架 | 一个景别，一个镜头目的 |
| 「写一些科技感的文字」 | 模型会自己编文案，还常是错字 | 给出原文，写清位置、次数、「除此之外不要别的字」 |
| 「做一张 2026 市场规模图」 | 数字会被编出来 | 数字全由用户给，写「不要补充数据」 |
| 「把衣服换成红西装」 | 没写保持项，脸、姿势、背景都可能被改 | 加「只改衣服，保持脸、姿势、背景、机位、光线」 |
| 「换衣服、变夜景、改姿势、换背景」一次全改 | 漂了不知道是哪处带的 | 拆轮次，每轮一处 |
| 「把这几张图结合起来」 | 模型不知道哪张管身份、哪张管衣服 | 逐张写角色 |
| 「Euler a，30 steps，CFG 7」或 prompt 里写「8K」 | 没有这些接口；写「8K」不会让文件变成 8K | 删掉，画幅分辨率走参数 |
| 风格名是小众词（砼核、梦核） | 模型未必认识这个词 | 补一句它长什么样 |

## 输出

每张图一套，顺序固定：

````
**用途**：<这张图做什么用> · **模型**：<模型和档位>（<不是用户指定的才写：为什么选它>）

[外观待确认——命中才出：要确认的角色或产品、找到的图、打算用的外形描述]
[画面方向——弱意图才出：3 个方向各一句「你会看到什么」，标出默认，下面写的是默认那个]

```text
<prompt 原文，整段可复制>
```

**参数**
- <渠道>：<字段 = 取值>（要在几个模型上跑时，每个模型一行）

**看图时查**
1. <这道题最可能翻车的地方，具体到哪个物件、哪段字>
2. …（2–4 条）

[风格要点——照图复刻时才出：3–5 条，保留它们就还是这个味道]
[改动说明——改已有 prompt 时才出：原来 → 现在 → 为什么，≤5 条]
````

「看图时查」要指向这道题的具体风险（「杯子上的『晚安咖啡』四个字」「猫爪是不是变成了人手」），不写「检查画质」这种空话。templates.md 每节末尾的「容易错」可以直接改写过来。

只写 prompt，不出图。用户审完要出图时，提醒他走 codex 或 Lovart；他让你接着出图，那是另一件事，按全局生图规则办。

## 红线

1. **参数名和取值只用 models.md 里核过的**。没核过的写「没核过」，不凭印象编——编出来的参数轻则报错，重则在付费渠道白扣积分。
2. **画面里的事实和数据只用用户给的或有出处的**。生图模型会把编出来的数字画得像真的一样，配图发出去就收不回来。

## 失败处理

- 参考图打不开：请用户确认路径，不凭文件名写。
- 外观找不到图：请用户发截图；先写出打算用的外形描述，标「待确认」。
- 用户点的模型不在 models.md 里：通用写法，参数段写「没核过」。
- 用户提到 models.md 里没有的新版本，或者 models.md 的核实日期已经过去两个月以上：交付时说一句参数卡是哪天核的，建议对一下官方文档。
