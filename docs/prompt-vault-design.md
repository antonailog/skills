## 0. Skill 化决策（S0 结论）

用户的 prompt 散落三处：自己写的（飞书 wiki）、别人整理成篇的、埋在文章里的片段，格式不一、图文割裂、回头难找。要把它们统一收进 GitHub 一个公开仓库，每次看到新 prompt 都要走一遍「抽取 → 规范化 → 归类 → 配案例 → 建索引 → push」，这是持续重复的多步流程，且文档模板必须跨会话一致——扩展已有 skill 不成立（lark-export 只做忠实镜像，是本 skill 的输入通道；prompt-craft 管写 prompt，管不了收藏管理）；写进 CLAUDE.md 装不下带脚本的流程。

满足的资格条件：☑ 会重复使用 ☑ 有脚本能省重复劳动（索引重建、图片下载）☑ 需要跨会话统一 ☐ 容易被路由错（但与 prompt-craft 名字相近，边界必须写死）

## 1. 收料结论（S1）

### 1.1 需求与场景

- 使用者与处境：用户本人（PM）。两种时刻——刷到文章/推文里有好 prompt 想存；想把飞书 wiki 里的存量 prompt 收编进库。
- 现在怎么解决、哪一步最烦：存飞书或浏览器收藏夹。烦点是格式不一、prompt 和效果图割裂、回头找不到。
- 理想产出：GitHub 公开仓，每条 prompt 一个 markdown（原文 + 案例图 + 来源 + 标签），一层主题目录，自动生成的总索引 README，手机能直接浏览。
- 什么算做对了：收录一条只需一次确认交互；索引页扫一眼能定位到条目；案例图在 GitHub 页面上直接渲染出来。
- 检索方式（钢人论证确认）：人翻 GitHub → 复制进 AI 对话用。检索本身不需要 skill（本地有 clone，直接浏览或 grep）。

### 1.2 已有决策与约束

| 类别 | 内容 | 可否推翻 |
|---|---|---|
| 存储 | GitHub 公开仓，真源；位于工作区 `项目/prompt-vault`，远端挂 GitHub | 已拍板 |
| 飞书关系 | 单向、手动触发的收编导入（经 lark-export），不做自动双向同步 | 已拍板 |
| 交互 | 网页来源抽取后出「确认卡」，用户点头才入库；飞书批量导入（自己的内容）汇总确认一次 | 已拍板 |
| 层级 | 一层主题目录 + frontmatter 标签 + 脚本生成总索引，拒绝深层树 | 已拍板 |
| 分类 | 通用五类起步：image-gen 生图 / video-gen 生视频 / writing 写作文案 / coding 编码开发 / agent Agent·系统 Prompt；不合适再调 | 可调 |
| 案例 | 图片下载入库（分类目录下 assets/）；视频只存封面帧 + 原链接，视频文件不进 git | 已拍板 |
| 合规 | 公开仓 ⇒ 每条必须标来源（原文链接 + 作者/出处）；这是红线 | 已拍板 |

参考对象及不借鉴什么：

| 参考 | 借鉴什么 | 明确不借鉴什么 |
|---|---|---|
| awesome-prompts 类仓库 | README 索引表的可扫读性 | 万条堆砌、无案例、无来源的收藏癖形态 |
| lark-export | 作为飞书输入通道直接调用 | 忠实镜像思路——本 skill 是再加工，要提炼重排 |
| diary-studio 仓库模式 | 独立仓库 + GitHub 远端 | 它的本地服务形态，本库是纯静态内容仓 |

## 2. 设计

### 2.1 要解决的问题

用户看到一条值得存的 prompt（飞书里自己写的，或网页文章里别人的），skill 替他完成抽取原文、规范化成统一文档、扒案例图、标来源、归类入库、重建索引、push GitHub 的全套动作——他只需要丢来源和点头确认。

### 2.2 定位与边界

**定位**：个人 prompt 资产库的图书管理员——把「一条散落的 prompt 变成随时找得回、看效果就能挑的馆藏」讲透：抽准原文、配上效果案例、标清来源、放对架位、更新目录卡。

**核心立场**：这个库的消费方式是人翻 GitHub 找到后复制去用，所以一切组织为「扫一眼索引能定位、点进详情能一键复制」服务——浅目录、重索引、案例图必须在场。宁可少收一条，也不收一条抽错的：网页抽取必经用户确认才入库。

**范围**：给定一个来源（飞书 wiki 链接 / 网页 URL / 用户直接粘贴的 prompt 文本），抽取其中的 prompt 与案例，规范化入库。一次处理一个来源（一个来源里可含多条 prompt）。

**不处理**：

| 不处理什么 | 交给谁 |
|---|---|
| 写、优化、评审 prompt 本身 | prompt-craft |
| 飞书文档忠实镜像（目的与 prompt 库无关） | lark-export |
| 在库里找某条 prompt 来用 | 直接浏览 GitHub 或 grep 本地仓库，无需 skill |
| 收藏非 prompt 内容（整篇文章、笔记） | 一般收藏/导出流程 |
| 构建、评测 skill 包 | skill-build |

**≥3 个"很像但不该触发"的 query**（门禁第 1 条）：

1. 「帮我写一个小红书文案的 prompt」→ prompt-craft（要的是造，非收）
2. 「把这篇飞书文档导出到本地」→ lark-export（镜像，非提炼入库）
3. 「这条生图 prompt 效果不行，帮我改改」→ prompt-craft
4. 「把这篇公众号文章全文存下来」→ 一般抓取，非 prompt 提炼
5. 「我记得存过一条改文风的 prompt，帮我找找」→ 检索，grep 本地库即可

### 2.3 触发与意图路由

**触发层素材**（措辞打磨在 S3）

- 应触发：「收录这条 prompt + URL」「把这篇文章里的 prompt 存进我的库，案例图也要」「飞书那个 prompt wiki 批量导入」「这条 prompt 帮我存一下：<粘贴全文>」「prompt 库重建下索引」
- near-miss 负例：见 2.2 五条
- 可能抢活的隔壁：prompt-craft（名字都含 prompt，以"造 vs 收"分界）、lark-export（都碰飞书，以"镜像 vs 提炼入库"分界）

**路由层分流**

| 意图强度 | 判断信号 | 应答粒度 |
|---|---|---|
| 强·网页单篇 | query 含非飞书 URL，或粘贴了 prompt 文本 | 走完整流程：抓取→提炼→确认卡→入库 |
| 强·飞书批量 | query 含 feishu wiki 链接或指名飞书 prompt 库 | 批量线：lark-export 拉取→逐篇提炼→汇总确认→入库 |
| 强·维护 | 「重建索引」「我手动改了文件」 | 只跑索引脚本 + commit push |
| 弱 | 「想整理我的 prompt」无具体来源 | 报库现状 + 索引链接，问收哪个来源 |

### 2.4 输出框架

**单条 prompt 文档固定骨架**（锁死顺序；产出物模板见 assets/prompt-doc-template.md）

1. frontmatter：`title / category / tags / model（适用模型，可空）/ source_name / source_url / collected（日期）/ media（案例数）`
2. `# 标题`
3. 引言一句话：这条 prompt 干什么、什么时候用
4. `## Prompt 原文`——代码块包裹，方便一键复制；多版本（中/英、变体）各一块
5. `## 效果案例`——图片用仓库内相对路径内嵌；视频=封面帧图 + 原视频链接；无案例整节省略
6. `## 来源`——原文链接 + 作者/出处 + 收录日期（公开仓红线，必出）
7. `## 使用备注`——触发式：用户有心得才写

**确认卡**（入库前展示给用户的中间产出，必出）：拟定标题、拟归分类（拿不准给 2 个候选）、tags、prompt 原文全文、抓到的案例图数、来源。用户点头或改。

**收录报告**（入库后，必出）：文件路径 + commit 结果 + GitHub 页面链接。

**仓库结构**

```
prompt-vault/
├── README.md          # 脚本自动生成：按分类分节的索引表（标题|一句话|标签|案例✓）
├── image-gen/
│   ├── <slug>.md
│   └── assets/        # 该分类的案例图，文件名与 md slug 对应
├── video-gen/  writing/  coding/  agent/   # 结构同上
```

模块总数 3 个产出物（prompt 文档 / 确认卡 / 收录报告），不超限。

### 2.5 执行流程

| 步 | 做什么 | 调什么 | 失败怎么办 |
|---|---|---|---|
| 1 | 判别来源类型，走 2.3 路由 | — | 判不了就问一句 |
| 2a | 网页线：抓正文与图 | WebFetch / curl | 反爬或登录墙 → 请用户贴正文/截图，人工兜底 |
| 2b | 飞书线：拉子文档 | lark-export skill | 导出失败 → 报错停，不做半截导入 |
| 3 | 提炼：识别 prompt 段落、案例媒体、元信息 | 模型判断 | prompt 边界模糊 → 确认卡里如实标注存疑段落 |
| 4 | 出确认卡，等用户点头/修改 | AskUserQuestion | 用户否 → 弃或改后重出 |
| 5 | 写 md + 下载案例图入 assets/ | scripts/save_media.py | 微信图 403 → 带 Referer 重试一次，仍败则文档里存原 URL 并明示 |
| 6 | 重建 README 索引 | scripts/build_index.py | 脚本报错 → 修文件后重跑，不手写索引 |
| 7 | git commit + push | git | push 失败 → 本地已 commit，报告"已入库未推送"，禁止 force |

### 2.6 辅助资源

| 资源 | 类型 | 为什么需要 |
|---|---|---|
| build_index.py | scripts/ | 每次入库后都要重建索引，纯机械 |
| save_media.py | scripts/ | 带 Referer/UA 下图 + 按 slug 重命名，防盗链逻辑每次一样 |
| prompt-doc-template.md | assets/ | 会被复制进产出的单条文档模板 |

不建 references/：仓库结构与 frontmatter 规范体量小，直接进 SKILL.md 正文。

### 2.7 输入输出定义

**≥5 条真实 query 样本**（门禁第 5 条）：

1. 「收录这个 https://mp.weixin.qq.com/s/NAdhdFrUq9-BKelqzqpwBQ 里面有几段生图prompt 案例图也扒下来」
2. 「把 https://my.feishu.cn/wiki/F957wGdEfiJCHqksyQWck7wrnDg 下面的子文档都导入我的prompt库」
3. 「这条prompt挺好的帮我存一下：你是一位资深文案编辑，请把下面的文字改写成…」（粘贴全文，没给来源）
4. 「刚看到个雕像自拍的nano banana prompt想收进库 链接 https://x.com/…」
5. 「prompt库重建下索引 我手动改了两个文件的分类」
6. 「我想整理下我的prompt」（弱意图，报现状后反问）

**预期输出**：见 2.4 三个产出物。
