# 《avatar-look Skill 设计文档》

> 阶段：S2 设计已确认，S3 撰写、S4 轻档评测已完成（2026-10-16）
> 读者：用户本人，确认边界和流程
> 档位：轻档 + 脚本（自己用；手写 5–10 条请求测试触发，不做基线对照）

## 0. Skill 化决策（S0 结论）

2026-10-15 至 10-16 在个人博客里手工做过一遍「3D 头像看向鼠标」：照片 → 3D 头像图 → 即梦生成头绕一圈的视频 → 量朝向 → 视频 seek 组件，返工了三轮才定型。这套流程会重复用（换形象、换衣服、给项目做吉祥物、给别人做），其中视频处理、朝向测量、组件生成每次一模一样，适合写成脚本；三轮返工得出的结论（选什么方案、提示词怎么写）需要跨会话保留，否则下次还会从「按姿态挑帧」重新踩起。没有现成 skill 覆盖：forge-design-impl 管设计稿转代码，impeccable 管通用前端交互，都不含 AI 生成素材这一段。

满足的资格条件：☑ 会重复使用 ☐ 容易被路由错 ☑ 有脚本能省重复劳动 ☑ 需要跨会话统一

## 1. 收料结论（S1，从对话历史提取）

### 1.1 需求与场景

- 使用者与处境：自己（或帮别人）做个人网站、产品官网时，想要一个会看向鼠标的 3D 卡通头像，放在首屏头像框、名片、吉祥物位置。
- 现在怎么解决、哪一步最烦：手上只有一张照片或一个想法；不知道该用 3D、帧图还是视频；视频要自己写提示词去即梦生成；后期处理全靠临时写脚本。
- 理想产出：一个目录，内含视频素材、正脸图、朝向数据、组件脚本、演示页，加三行接入代码；任何页面引进去就能用。
- 什么算做对了：鼠标绕头像一圈，头转向鼠标，转动连贯不跳帧；放在任意位置、任意尺寸都对；控制台零报错；用户亲手试过说顺。

### 1.2 已有决策与约束（来自 10-15、10-16 的纠正，不可推翻）

| 类别 | 内容 | 可否推翻 |
|---|---|---|
| 效果定义 | 「360°」= 看向屏幕平面上任意方向，头、颈、眼一起动；不是头转一整圈（看到后脑勺），也不是只有眼珠动 | 否 |
| 素材 | 一张图 + 一段视频（首尾帧都用这张正脸图）；不分段生成关键帧，不做朝向网格图 | 否 |
| 视频提示词 | 写明不眨眼、表情不变、固定机位、身体不动；不加粉尘、发丝浮动、「冷酷」 | 否 |
| 选帧 | 播放头沿时间轴连续走、途经每一帧；不按姿态直接挑帧（10-16 实测一顿一顿） | 否 |
| 出画面 | 视频 + seeked 串联 + 全关键帧编码；不用帧图混合（10-16 用户对比后否掉，混合帧有重影） | 否 |
| 3D | 不走 Three.js / 图片转 3D 模型（长相走样，眼珠在贴图上转不了） | 否 |
| 改页面 | 只接入用户指定的页面；别的会话正在改的页面不动 | 否 |
| 人工环节 | 生视频必须用户自己去即梦操作；生图默认 agent 用 codex image_gen，不满意再给提示词让用户自己出 | 用户已定 |
| 合规 | 只处理用户本人或已获授权的形象照片 | 否 |

参考对象：

| 参考 | 借鉴什么 | 明确不借鉴什么 |
|---|---|---|
| 小红书原帖（视频跟随鼠标的简历站） | 视频当时间轴、seeked 串联 | 「鼠标相对移动距离 × 0.8 灵敏度」：那是拖时间轴，不是看向鼠标；只有左右一维 |
| face_looker（Replicate，LivePortrait 生成眼神网格） | 无 | 网格图方案，用户否掉了 |
| 苹果产品页滚动序列帧 | 无 | 滚动驱动，不是鼠标驱动 |

## 2. 设计

### 2.1 要解决的问题

把一张照片或一个想法，变成一个能嵌进任何网页、会看向鼠标的 3D 头像组件：机械活（视频处理、朝向测量、组件、验收）全由 agent 做，用户只负责生视频（和可选的生图），每一步拿到现成的提示词和挑选标准。

### 2.2 定位与边界

**定位**：一个做过这件事、踩过坑的动效工程师朋友——把「哪一步要你动手、动手时怎么填、生成完怎么挑」讲透，其余全包，最后交一个三行就能接入的组件。

**核心立场**：用户要的是「页面上一个顺滑地看向鼠标的头像」，真 3D 不是目标。所以一切围绕「一段头绕一圈的视频 + 连续时间轴 + seek」组织，不在方案上重新发散；被验证过更差的路线（Three.js、帧图混合、按姿态挑帧、眼神网格）不再提供，除非用户主动问。

**范围**：输入是照片、文字想法、现成的 3D 头像图或现成的绕圈视频之一，从对应的步骤进入；输出一个组件目录，可选接入用户指定的页面。一次只做一个形象。

**不处理**：

| 不处理什么 | 交给谁 |
|---|---|
| 只要一张静态 3D 头像图（发公众号、换平台头像） | 直接用 codex image_gen 出图（全局规则），不走本 skill |
| 视频剪辑、压缩、转 GIF | 直接用 ffmpeg |
| 鼠标跟随的光标特效、粒子、视差等通用动效 | impeccable |
| 可旋转的真 3D 模型展示、Live2D、数字人 | 不在本 skill 范围，直接告诉用户 |
| 滚动驱动的序列帧动画（苹果产品页那种） | impeccable / forge-design-impl |
| 页面整体设计、首屏布局 | forge-design / forge-design-lab |

**很像但不该触发的请求**：

1. 「帮我用这张照片生成一个皮克斯风格的头像，公众号要换头像」
2. 「把这个 mp4 压到 2MB 以内，转成 GIF 发群里」
3. 「首页加个鼠标跟随的小光点特效，参考 React Bits 那个 Splash Cursor」
4. 「用 Three.js 做个能拖动旋转的 3D 模型展示我的手办」
5. 「做一个往下滚动时 AirPods 跟着转的苹果式动画」

### 2.3 触发与意图路由

**触发层素材**

- 应触发：头像看向鼠标、头跟着鼠标转、3D 头像跟随鼠标、视频头像跟随鼠标、avatar look at cursor、给网站做会看人的吉祥物、把即梦视频做成跟随鼠标的头像、头像转起来卡/太飘（已有组件调手感）
- near-miss 负例：见 2.2 的 5 条
- 可能抢活的隔壁：impeccable（「鼠标跟随」「动效」字面重合）、xhs-note（「头像图」）。description 里写清「AI 生成头像素材 + 视频 + 看向鼠标」这个组合

**路由层分流**

| 意图强度 | 判断信号 | 应答 |
|---|---|---|
| 强 | 给了素材路径（图片 / 视频），或点名 avatar-look | 判断从哪步进入，直接开干 |
| 弱 | 说要「会看鼠标的头像」，但没给素材 | 一段话讲清 5 步和哪两步要他动手，然后问要照片还是想法 |
| 潜在 | 在做个人站首屏 / 头像框，问「头像能不能动起来」 | 简答一句能做成看向鼠标的 3D 头像 + 反问要不要 |
| 维护 | 已有组件，说卡、太飘、太慢、换形象 | 调 `TAU_MS` / `MAX_SPEED`，或从第 1 / 2 步重做素材 |

**进入点判断**：有视频 → 第 3 步；有 3D 头像图 → 第 2 步；有照片或想法 → 第 1 步。

### 2.4 输出框架

**人工环节的固定骨架**（第 1 步自己出图时、第 2 步生视频时，每次都按这个顺序）

1. 去哪做、怎么设置（工具、模式、时长、比例）
2. 提示词（代码块，可直接复制；生视频给主版 + 两个备选）
3. 挑选标准（逐条可判断）
4. 做完回我什么（文件路径）

**最终交付的固定骨架**

1. 一句现状：做好了，接到了哪里
2. 三行接入代码
3. 验收数据：自动测试的结果（报错数、每秒跳转次数、8 个方向是否正确），并明说「这是自动测试，手感请你亲手试」
4. 产出目录的链接、演示页链接

**必出模块**

| 模块 | 入选条件 | 内部结构 |
|---|---|---|
| 提示词块 | 每个人工环节 | 主版 + 备选；不带粉尘、冷酷等干扰项 |
| 挑选标准 | 每个人工环节 | 生视频：转满一圈 / 长相不走样 / 帽子眼镜等硬物不变形 / 不眨眼 |
| 九宫格核对图 | 第 3 步之后 | 8 个方向 + 正脸各选一帧拼图，给用户看方向对不对 |
| 验收数据 | 交付时 | 见上 |

**触发式模块**

| 模块 | 触发条件 |
|---|---|
| 重新生成视频的建议 | 脚本报缺口 > 60°、人脸识别率 < 90%、找不到绕圈段 |
| 接入指定页面 | 用户点名了页面 |
| 手感调参 | 用户说卡、飘、慢 |

模块总数 7 个（固定骨架两套 + 4 必出 + 3 触发），合并后不超过 8。

### 2.5 执行流程

| 步 | 做什么 | 谁 / 用什么 | 输出 | 失败怎么办 |
|---|---|---|---|---|
| 1 出 3D 头像图 | 照片或想法 → 3D 卡通半身像：正脸、居中、身体正对、纯色背景、头顶留白、16:9 | 默认 agent 用 codex image_gen；用户要求或出图不满意时，给提示词让用户在 image2 / 即梦 / GPT 出 | 一张 png，用户确认 | codex 不可用或两次不满意 → 给提示词让用户出 |
| 2 生成视频 | 即梦首尾帧都用这张图、5 秒、16:9，按提示词生成 3–4 条挑一条 | **用户** | 视频路径 | 三条都没转满一圈 → 换备选提示词；仍不行 → 拆两段（抬头→右→低头、低头→左→抬头）再拼 |
| 3 处理视频 | 自动找脸裁方形 → 全关键帧 mp4 + 正脸图 → 逐帧量朝向、剔除眨眼帧、算圆周时间轴 → 九宫格核对图 | `scripts/process_video.py`（uv + mediapipe 0.10.14、ffmpeg、cwebp） | 产出目录 + 自检报告 | 依赖装不上 → 走代理重试，两次不通就停下报告；自检不过 → 回第 2 步并说明原因 |
| 4 产出组件 | 复制 `avatar-look.js`、演示页到产出目录；用户点名页面的话接入 | agent | 组件目录 | — |
| 5 验收 | 自动测试：零报错、每秒跳转次数、8 个方向选帧 | `scripts/verify.py`（Playwright + 本机 Chrome） | 验收数据 | 没有 Chrome → 用 Chromium，说明 H.264 可能不支持；Safari 未测要明说 |

产出目录默认放在用户项目里他指定的位置；没指定就问一句，不自作主张放进别人正在改的页面目录。

## 5. 构建记录（S3、S4）

**包结构**：`skills/avatar-look/` = SKILL.md（133 行）+ references/{prompts.md, how-it-works.md} + scripts/{process_video.py, verify.py} + assets/{avatar-look.js, demo.html}。体检 `validate_skill.py`：0 error 0 warning；description 275 字符，红线 3 条（设计草案 4 条，「自动测试不能代替手感」降级成第 5 步和输出骨架里的说明，违反了收得回来）。

**脚本实测**（用个人博客那条即梦视频）：
- `process_video.py`：自动裁切 828:828:528:0（手工定的是 860:860:525:0）；人脸识别 121/121；绕圈段第 21—120 帧，缺口 38°；自检通过；九宫格 8 方向目视正确
- 反例：只截前 2.5 秒（头转了不到半圈）→ 缺口 159°，退出码 2，提示重新生成
- `verify.py`（Chrome）：8 方向全部在 ±45° 内，画圈每秒跳转 55 次，相邻帧跨度中位 1、最大 3，零报错

**触发评测**（轻档，`claude -p` 每条跑 1 次、只看第一个动作，合计 $2.51）：6 条正例全部调用 avatar-look（含「头像太死板能不能动起来」这条潜在意图、调手感、换形象）；5 条 near-miss 全部没调用（静态 3D 头像、视频转 GIF、光标特效、Three.js 模型、苹果式滚动动画）。每条只跑 1 次，没有算触发率，没做基线对照。

**用 skill 重做博客产出**：`内容/个人博客/99-其他/样张/头像跟随/` 改由 `process_video.py` 生成、组件从 assets 复制，博客里的旧脚本 `生成头像帧.py` 删除，避免两份脚本各改各的。回归时 `verify.py` 在首页 v2 报 4 个方向错：头像在左上角，测试鼠标放到 300px 外已出窗口、不触发事件——是测试脚本的问题。改成每个方向的距离不超过到窗口边缘的距离、画圈半径同样收缩后，v2 8 方向全对（半径 92px，每秒跳转 46 次）。

**没做的**：端到端走一遍新形象（第 1 步 codex 出图 → 用户生视频 → 处理 → 接入）；Safari 验证。
