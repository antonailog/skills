# ai-events-push 设计与测试记录

> 状态：已建成并公开（2026-11-03）；11-04 加小红书渠道（见第 6 节）
> 档位：轻档（SKILL.md + 6 个脚本 + 3 份按需读的说明 + 群海报和小红书两份模板）
> 依据：2026-11-02 一次「本周活动推荐」微信群推送从头跑到定稿的全过程，以及作者在里面的每一次纠正

## 0. 为什么做成 skill

同一套活每周都要做：认出作者挑的活动 → 核实时间票价 → 写文字稿 → 出海报 → 核对链接。其中拉数据、排版截图、扫二维码、查孤字、逐条打开链接都是固定步骤，11-02 那次全靠手工拼了二十多次命令。做成 skill 以后，这些交给脚本，作者定过的写法和版式（不说「我收藏的」、北京在前、网站同款 16:9 门票、标准活动介绍写法）也不用每次重新纠正。

它离不开作者自己的「国内AI活动追踪」网站项目（数据从网站来，加新活动要用网站项目的发布脚本），换人用只能做出海报和文字这一段。

## 2. 设计

### 2.1 要解决的问题

作者挑出几场活动，skill 交回一张能直接发群的海报和一段能直接复制的文字，事实都核过、链接都点过。

### 2.2 定位与边界

**定位**：活动推送编辑。像一个替作者值班的编辑——作者只管挑，它把每场的时间、地点、票价、谁来讲核实清楚，排成群里一眼看懂的图，再配一段能直接转发的文字。

**不处理**：写公众号文章（human-writing）、小红书笔记（xhs-note）、即刻和 X 的宣传帖；网站页面本身的改版（直接改项目代码）；每日简报邮件（脚本/每日简报.sh）；抓取新活动（每日更新.sh）。

### 2.3 触发

该触发：
- 「这几个活动帮我做个推送 / 宣传图」+ 网站截图
- 「把这周收藏的活动发群里」
- 「这个活动不错（附海报），加到本周推荐里」
- 「本周活动推荐出一版」
- 「把上周那张活动海报换成这几场」

很像但不该触发：
- 「给国内AI活动追踪写一篇公众号宣传稿」→ human-writing
- 「活动页的弹窗改一下样式」→ 直接改项目代码
- 「今天的每日简报怎么没发」→ 查 脚本/每日简报.sh
- 「这个活动值不值得去，帮我调研一下」→ deep-survey

### 2.4 输出

一个目录 `宣传/发布/<日期>-微信群/`：`海报.png`（直接发）、`文案.md`（两条横线之间那段直接复制，下面是核实记录）、`活动.json`（海报的数据，改了重出）、`海报.html` 和 `素材/`。

### 失败怎么办

- 网站数据拉不下来：退回本地 页面/app/src/data.json，说明可能不是最新
- 票价、钟点查不到：写「费用未写」「钟点未写」，核实记录里注明查过哪里
- 海报和网页信息冲突：以活动方海报为准，网站上的错另外提出来修
- 报名链接打不开、要登录：照样放，核实记录里注明

## 6. 加小红书渠道（11-04 设计并建成）

依据：2026-11-03—11-04 一期小红书多图推送（11/4–11/10，33 场，13 张图）从选场到发布前定稿的全过程，以及作者在里面的纠正。

### 6.0 为什么扩展本 skill，不另建

选场、拉数据、核实、宣传图、网站纠错这半条流水线和群推送是同一套，数据都来自「国内AI活动追踪」。另建一个小红书活动 skill，两个 skill 会抢「把这周活动发出去」这类请求，核实规则也要维护两份。所以在本 skill 里加一个渠道，名字不改（已发布的 skill 改名会让引用失效）。代价：SKILL.md 变长，渠道细节放进 references，正文只留分流和共用步骤。

### 6.1 要解决的问题

作者给一个日期范围（或几场活动），skill 交回能直接发的一套推送：微信群是一张长图加一段文字；小红书是一组 3:4 图（封面 + 每天的活动页）加标题候选、正文、标签。事实都核过，图和文字里没有网址、二维码和引流字眼。

### 6.2 定位与边界

**定位不变**：替作者值班的活动推送编辑。**小红书这边的立场**：读者是刷到这篇的陌生人，不是群友，所以图要自己能讲清每场（时间、地点、主办方、费用），标题靠真实看点吸引人（首次来华、免费场数、大咖名字），不靠营销词；平台判引流，所以图文里一个网址、一个二维码、一个「扫码」都不能有。

**不处理**（命中交出去）：
- 作者自己的工具分享、听播客感悟这类小红书笔记 → xhs-note
- 公众号文章 → human-writing
- 网站页面改版、每日简报、抓取 → 活动监测项目自己的脚本
- 替作者发笔记、发群、回评论 → 不做，交稿到文件为止

**和 xhs-note 的分界**（要同时改它的 description）：内容是「一段时间里的一批活动」就归本 skill；内容是作者自己的东西（做的工具、读的书、想法）归 xhs-note。11-03 触发测试里「把这周的 AI 活动推荐写成一条小红书笔记」判给了 xhs-note，加渠道后要改判到本 skill。

### 6.3 触发与分流

该触发（新增）：
- 「给我整理一下近期的 AI 活动，用适合小红书的多张图展示，不要放网址」
- 「11/11 到 11/17 的活动做一版小红书」
- 「这周的活动推荐，群里和小红书各出一版」
- 「上次那套小红书图换成下周的活动」
- 「给我小红书的标题和 tag」（在本 skill 出过图的推送目录里）

很像但不该触发：
- 「用 forge 修 bug 好爽，写个小红书」→ xhs-note
- 「帮我看看小红书哪些 AI 账号做得好」→ 调研
- 「活动页做个手机版分享卡片」→ 网站项目
- 「这篇小红书笔记发出去了，链接在这」→ 只记发布索引（本 skill 收尾那一步会做，单独说时不用整套流程）

分流（进来之后走哪条线）：
| 信号 | 走哪 |
|---|---|
| 提到群、微信、IM、长图 | 群推送（现有流程） |
| 提到小红书、红书、xhs、多张图、3:4 | 小红书 |
| 都提了 / 「各出一版」 | 两个都出，共用选场和核实 |
| 都没提 | 问一句发哪 |

选场两种来源：作者给了截图 / 活动名 / 海报 → 就用这几场；只给了日期范围 → 按 `references/小红书.md` 的选场规则从网站全量里挑，先把范围清单给作者过目再做。

| 产物 | 必出 | 对应的检查 |

| 文案.md：标题候选、正文（清单版 / 重点版）、标签、核实记录 | 是 | 标题 ≤20 字、正文+标签 ≤1000 字、没有网址和引流词、正文里的场数统计和数据一致 |

群推送目录和产物不变。

### 6.5 执行流程（小红书）

1. 定范围：拉日期范围内全量，按规则挑，出 范围.md 给作者过目（场数用脚本数，不心算）
2. 拉完整字段：`fetch_events.py --ids … --out 选中.json`
3. 核实：同群推送第 3 步（原文优先；活动行页面按本机时区显示，本机不在东八区就换算回北京；碰到验证码立刻告诉作者）。可疑场次（匿名主办、留个人微信、副业变现口径）提出来让作者定换不换
4. 写 小红书.json：每场 day、form、city、date、time、due、name、venue、org、intro、price、cover；封面挑 1–5 场
5. 出图：`make_xhs.py 小红书.json 出图`。宣传图优先用活动行 800 宽原图；图里印了「扫码」「二维码」或网址的，在 JSON 里写 `cover_blur` 盖掉；没图的场次不当头条
6. 看图：总览先看一遍，再抽看头条大票的宣传图
7. 写文字：标题候选、正文、标签，按 `references/小红书.md`；跑 `check_xhs_text.py` 查字数、引流词和统计数
8. 网站上发现的错：照 `references/新活动上网站.md` 修（先给作者看改动；推服务器时只推改动的文件，不整目录推）
9. 交稿；作者发了以后在发布索引最上面加一行（链接带 xsec_token）

失败：活动行原图下不来 → 用网站存的 640 图；宣传图没有 → 分类默认图，且不当头条；字体 CDN 不通 → 退回系统字体并告诉作者；出图超过 18 张 → 减场次或合并少的日子，问作者。

### 6.8 测试（11-04 真跑）
