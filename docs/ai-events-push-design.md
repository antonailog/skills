# ai-events-push 设计与测试记录

> 状态：已建成并公开（2026-11-03）
> 档位：轻档（SKILL.md + 3 个脚本 + 2 份按需读的说明 + 海报模板）
> 依据：2026-11-02 一次「本周活动推荐」微信群推送从头跑到定稿的全过程，以及作者在里面的每一次纠正

## 0. 为什么做成 skill

同一套活每周都要做：认出作者挑的活动 → 核实时间票价 → 写文字稿 → 出海报 → 核对链接。其中拉数据、排版截图、扫二维码、查孤字、逐条打开链接都是固定步骤，11-02 那次全靠手工拼了二十多次命令。做成 skill 以后，这些交给脚本，作者定过的写法和版式（不说「我收藏的」、北京在前、网站同款 16:9 门票、标准活动介绍写法）也不用每次重新纠正。

它离不开作者自己的「国内AI活动追踪」网站项目（数据从网站来，加新活动要用网站项目的发布脚本），换人用只能做出海报和文字这一段。

## 2. 设计

### 2.1 要解决的问题

作者挑出几场活动，skill 交回一张能直接发群的海报和一段能直接复制的文字，事实都核过、链接都点过。

### 2.2 定位与边界

**定位**：活动推送编辑。像一个替作者值班的编辑——作者只管挑，它把每场的时间、地点、票价、谁来讲核实清楚，排成群里一眼看懂的图，再配一段能直接转发的文字。

**不处理**：写公众号、即刻、X 等平台的宣传文章（renhua-writer-next、xhs-note）；网站页面本身的改版（直接改项目代码）；每日简报邮件（脚本/每日简报.sh）；抓取新活动（每日更新.sh）。

### 2.3 触发

该触发：
- 「这几个活动帮我做个推送 / 宣传图」+ 网站截图
- 「把这周收藏的活动发群里」
- 「这个活动不错（附海报），加到本周推荐里」
- 「本周活动推荐出一版」
- 「把上周那张活动海报换成这几场」

很像但不该触发：
- 「给国内AI活动追踪写一篇公众号宣传稿」→ renhua-writer-next
- 「活动页的弹窗改一下样式」→ 直接改项目代码
- 「今天的每日简报怎么没发」→ 查 脚本/每日简报.sh
- 「这个活动值不值得去，帮我调研一下」→ deep-survey

### 2.4 输出

一个目录 `宣传/发布/<日期>-微信群/`：`海报.png`（直接发）、`文案.md`（两条横线之间那段直接复制，下面是核实记录）、`活动.json`（海报的数据，改了重出）、`海报.html` 和 `素材/`。

### 失败怎么办

- 网站数据拉不下来：退回本地 页面/app/src/data.json，说明可能不是最新
- 票价、钟点查不到：写「费用未写」「钟点未写」，核实记录里注明查过哪里
- 海报和网页信息冲突：以活动方海报为准，网站上的错另外提出来修
- 报名链接打不开、要登录：照样放，核实记录里注明

## 3. 建成情况

- 档位：轻档。红线 3 条；4 个脚本：`fetch_events.py`（拉线上数据和活动原文、列本周、起海报数据草稿）、`read_page.py`（在浏览器里打开报名页、官网，读正文和链接）、`make_poster.py`（填模板、截图、自检孤字和二维码）、`check_links.py`（逐条打开详情链接、查外部链接）；2 份按需读的说明；海报模板、二维码库和拉丁字体（来源和许可见 assets/THIRD-PARTY.md）
- 体检：skill-build 的 validate_skill.py 0 错误 0 警告
- 回放：用 11-02 这周 8 场重出海报，尺寸 2280×6066 和定稿一致；文字和版式逐像素相同，只有宣传图不同（定稿里两张是手裁的，脚本自动截顶上一块）
- 链接核对：对 11-02 的推送文字跑了一遍，17 条链接都对，一条短链是 302 跳转，标成「手机上点开看一眼」
- 项目目录：脚本和说明里不写本机绝对路径，读环境变量 `AI_EVENTS_DIR`，没设就是 `~/claudecode_workspace/工具/活动监测`
