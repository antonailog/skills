# 播客总结skill：需求与基建

## S0 独立 Skill 的理由

这是反复发生的“听完单集 → 保存原文 → 理解主线 → 图文笔记 → 维护飞书”的完整工作。它跨越资料获取、写作、绘图与已有文档保护，不能由只负责导图的 book-to-mindmap 或只负责镜像的 lark-export 单独覆盖。采用完整档；复用现有 CLI 和导图 Skill，不另造下载服务、调度器或渲染平台。

## S1 已确认需求

本会话已经实际演过完整流程。以下来自用户明确修订，不再重新访谈：

- 中文名「播客总结skill」，英文稳定名称 `podcast-summary`。
- 全文和来源先归档；独立写总结与关键要点，Podwise AI 总结只作原始档案。
- 先判断主题和讨论主线，再决定模块、模块内容与表达方式；各期不固定六模块或同一画法。
- 总览图覆盖整期实质知识与关系；总结讲整期推进；要点分模块展开证据、案例、数字、边界，复杂模块可配局部图。
- 维护 Shownotes 的来源文字、链接和内容图片；图片放回对应位置。
- 飞书内使用可编辑画板，SVG 为源文件，XMind 为详细导图的离线附件。
- 保留用户手调标题、顺序、位置、删除记录与个人笔记；不设置回听导航，不代写个人感想。
- 各级标题前为正文、列表或资源时留一个空段；加粗、高亮、下划线各有语义，不铺满整页。
- 学习页去掉制作说明和版本日志。工作区保留计划、证据与检查，结果区保存笔记和导图。
- 图的实际浏览器排版、可编辑能力、重新打开分别验证，不能以 API 成功代替。

用户当前请求是建包；本次不再修改已交付的飞书单集，也不启用自动同步。

## 参考及取舍

| 参考 | 使用 | 不借鉴 |
|---|---|---|
| 本次已验收图文规则和交付 | 主线、三部分分工、数字条件、更新保护、实机检查 | 本期私人 URL、token、固定六分支、具体金融结论 |
| book-to-mindmap | 判断式分支、详细来源、XMind 导出和覆盖检查 | 将核心数字全藏进 notes、默认只出两级、每次重新确认已授权动作 |
| beautiful-feishu-whiteboard | SVG 到原生元素、关系驱动版式、文字与容器分开测量 | 固定米白绿粉模板、截图冒充编辑画板 |
| lark-cli 内嵌技能 | 当前版本的命令与字段、精确更新、原生画板工具 | 长期复制工具全部文档、猜测更新命令有原位修改语义 |

## 工具盘点与字段用途

以下来自当前已安装 CLI 的帮助及本次真实导出形状。运行时仍先读当前版本帮助；不承诺未来版本不变。

| 工具 | 输入 / 有用输出 | 不使用或仅归档 | 失败处理 |
|---|---|---|---|
| `podwise get transcript` | 单集 URL；`--format json` 返回 `start / speaker / content` 段落；文本格式含时间戳 | 不用翻译版替代原文；不默认 refresh | 检查登录与单集状态；保留缺失状态，不把摘要当全文 |
| 官方原始数据或已存在归档 | `segments` 的 `time/start/end/content/speaker/language`；`episode` 元数据及 description HTML | 空字段保留 null；不自行拼内部 API 或提取登录密钥 | 用官方 CLI/MCP 可用接口；缺字段转读发布方页面或向用户要来源 |
| `podwise get summary/chapters/qa/mindmap/highlights/keywords` | 完整原始档案需要时保存 | `summary/takeaways` 不作为独立写作底稿；章节时码不生成回听导航；AI highlights 不当用户划线 | 单项失败记录在清单，其余继续 |
| `podwise clip list` | 单集 URL、当前帮助支持的 JSON 参数；用户 clips | 0 条不补造；音频播放历史不证明听完 | 用户观点仅用实际给出的内容 |
| 发布方页面 / HTML | 标题、参与者、日期、说明、勘误、资料链接、图片 URL、caption/alt | 广告不进入独立三部分；不默认抓完所有外链 | 失败图保留位置和来源，报告缺口 |
| `lark-cli docs +fetch` | 用户指定 doc/wiki；content XML、id、revision_id、resource token | 不把临时 token、内部链接写进可分享 Skill 包 | 无权读则暂停远端更新，完成本地稿 |
| `docs +update / +media-insert` | 本轮精确 block ID、最新 revision、XML 或文件；result/new_blocks/token | 避免全文 overwrite、默认 -1 revision；无关块和权限不修改 | 版本冲突回读重新合并；部分成功先核对再继续 |
| `whiteboard +export / +update` | 画板 token，raw/preview，已验证 payload；原生节点与映射 | raw 写入可能是追加，不当原位更新；不自动使用 overwrite | 先读内嵌 Skill 与语义；新板验收后替换旧块 |
| 本地文件 / 浏览器 | 文本、SVG/PNG/XMind、清单；真实画板显示与编辑 | 不读取凭证文件、不控制用户无关页面 | 可完成的部分继续，未做的检查明确标记 |

一次处理一集，批量明确授权后逐集处理；不自动运行 `process`、`translate`、外部 export 或计费任务，不从 history 自行选择“已听完”集合。

## 成功与失败边界

完成意味着：正文和图形互相一致；源材料完整性有记录；飞书目标内容已回读；用户未授权改动保留；图片和画板实际可见可编辑；结果区与项目记录同步。缺少授权、完整来源或渲染能力时交付可用本地部分，明确缺失项，不声称发布完成。
