# 播客总结skill 设计

档位：完整档。决策依据见 [需求与基建](01-需求与基建.md)。

## 2.1 要解决的问题

把单集播客的原始资料转成读得懂、有细节、可编辑、能持续维护的本地与飞书笔记。

## 2.2 定位与边界

像一个认真读完原文的知识编辑：保留讲话者真正说过的理由和分歧，替读者组织理解顺序。读者需要掌握内容与取舍，所以以主题和关系组织页面，不照抄章节，不填空式凑栏目。

单集为基本单元。支持完整整理、已有笔记重写、图文修复、只出本地稿。讨论/诊断请求只交付判断，不扩大为写入。

不接播客推荐与订阅购买（交给产品检索）、音频剪辑与转写服务开发（媒体/工程能力）、通用书籍导图（book-to-mindmap）、飞书镜像（lark-export）、只问某一政策现状（实时资料核验）、纯原样下载（CLI 直接操作）。

Near-miss 例子：“比较 Podwise 月付套餐和 CLI 功能”“把播客片头剪掉并降噪”“把这本书转 XMind”“只备份飞书播客目录，别改写”。

## 2.3 触发与意图路由

| 可观察信号 | 路径 |
|---|---|
| 给单集或完整转写，要求笔记、总结要点、图和归档 | 完整流程 |
| 已有播客笔记，只要求重写某模块或修图 | 读当前基线，局部处理、精确更新 |
| 明确只要本地、草稿或对比 | 交付本地，停止远端写入 |
| 只讨论怎么整理或比较两种图 | 说明判断及依据，不代为覆盖 |
| 已授权更新目标明确 | 完成可审阅稿和验证后执行，不逐阶段重复问 |

## 2.4 输出框架

外层默认顺序只用于新页；用户已有结构优先。固定的是职责，内容数量和图形动态变化。

| 模块 | 内部职责 | 考点 |
|---|---|---|
| 播客信息 / Shownotes | 元数据、来源文字、图片与勘误 | R1 来源、R6 图文 |
| 关键内容 / 总览、总结、关键要点 | 共用主线，三种阅读粒度；局部图按关系复杂度加入 | R2 主线、R3 总结、R4 要点、R5 图形 |
| 思维导图 / 导图文件 | 详细判断树及可编辑画板，SVG/XMind/真源附件 | R5 图形、R6 资源 |
| 个人思考 | 我的思考、与我的关系、下一步行动；实际用户内容或空位 | R7 保护 |
| 延伸资料 / 原始资料附件 | 支持理解的来源与完整原档 | R1 来源、R8 落地 |

## 2.5 执行流程

| 步 | 工具 / 输入 | 产出 | 失败处理 |
|---|---|---|---|
| 1 识别范围与回读 | 文件、已有飞书文档、目标链接 | 目标与基线 | 缺目标只暂停远端；继续读材料 |
| 2 获取和通读 | Podwise、来源页面、归档 | 原文清单、阅读覆盖、疑点 | 不全则标记范围，不能写成完整总结 |
| 3 决定主线与表达 | 原文、Shownotes | 简短内容方案、模块证据表 | 主线不成立就重组，不套上一集 |
| 4 写文与画图 | 内容方案、书籍导图方法、SVG/native 工具 | 总结、要点、总览、必要详图 | 不以生成摘要或位图替代目标能力 |
| 5 验证和精确更新 | 本地检查、最新 revision、资源上传 | 对应栏目更新 | 冲突重读；先验新资源再换旧块 |
| 6 回读和交付 | API、实际浏览器、本地审核脚本 | 同步笔记与证据 | 只按已完成层次报告 |

## 2.6 辅助资源

- `references/content-and-document.md`：通读、主线、三部分写法、排版和示例。
- `references/visuals.md`：内容关系 → 图形 → 风格，原生可编辑、溢出防护与验证。
- `references/tools-and-storage.md`：实际 CLI 入口、字段用途、不使用字段、失败与归档。
- `references/feishu-update.md`：保留人工修改、精确更新、资源替换与回读。
- `assets/content-plan.md`、`assets/note-template.md`：每期可复制的工作稿与新页默认骨架。
- `scripts/source_manifest.py`：原始资料哈希清单创建与复核。
- `scripts/audit_document.py`：保护块、标题间距和资源变更核对，只读，不代替内容与视觉验收。

不内置账号、目标空间、单集数据、固定分支、强制配色、自动同步或新的外部服务。

## 2.7 输入输出定义

输入优先为单集 URL / 全文文件，已有笔记 URL 或本地目录可从会话和项目推断；新目的地缺失时才问。完整输出包括本地原档、内容方案、笔记、图形源文件、原生回读和远端链接；局部请求只输出对应变化。

真实会话样本经去标识后纳入触发集：

1. “我已经开通 Podwise 会员，下载这期并整理到指定飞书页，包含信息、关键内容、导图和个人思考。”
2. “关键内容别用 Podwise 的总结，要自己读原文重写；标题按我现在维护的来。”
3. “导图只有两级，贷款利率没有具体数值；补细节，飞书里要能编辑。”
4. “在总览里用一张 SVG 说明整个播客，每个模块要有信息和数据。”
5. “Shownotes 图片漏了，文字超出方框；总结、关键要点和图先想主线再生成。”

## 2.8 上下文分层

description 约 300 字；SKILL.md 目标 130 行内；四份参考按步骤读，模板可复制，两个脚本确定性运行。全部引用从入口一层直达。设计、评测、迭代记录放包外，避免每次执行加载建包过程。

## 完备性门禁

| 项 | 结果 / 依据 |
|---|---|
| ≥3 near-miss | 通过，2.2 与触发集 |
| 明确不处理及接手者 | 通过，2.2 |
| 必出模块有考点 | 通过，2.4 的 R1–R8 |
| 工具字段与不用字段 | 通过，01 文档来自当前帮助和真实回读；运行时再核版本 |
| ≥5 真实详细 query | 通过，2.7；另外扩展到 20 条触发样本 |
| 失败路径 | 通过，01 文档、2.5 |

不需补问业务规则；它们已由用户多轮修订和本次“整理成 Skill”授权确定。合成评测样本的判定单独交用户核对，不把未核对写成已确认。
