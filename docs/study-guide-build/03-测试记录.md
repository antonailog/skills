# study-guide 测试记录

评测从简：不打分、不跑触发率，拿真材料按 skill 跑，看产出和执行时卡在哪（用户 11-11 定）。每次只跑到第一次停（提纲 + 样章），这是最值钱、也最容易跑偏的一步。

## 第 1 轮：录屏宣传片 7 份报告（2026-11-11）

做法：全新子 agent，只给 skill 和一份干净副本（7 份报告 + 1-prompt.md + 删掉产出记录的 0-说明.md），不许看线上那篇和原项目文件夹。

产出：13 章提纲（一分钟看懂、前置知识、一到十三章、检查清单、还不确定的），覆盖矩阵列了 6 条不收的要点和理由，还不确定的 7 处；样章是第五章「镜头」，带可切换的缩放演示和双语提示词块，四个宽度自检通过。

**结论不算数**：skill 自带的提纲范例（outline-example.md）用的正是录屏宣传片这个主题，子 agent 照规定读了范例，结构被它锚定。

执行中报的问题和修法：

## 第 2 版：按用户三点意见改（2026-11-11）

用户看完全文：「读起来信息密度不高，有点杂乱」。量下来 734 句里整句照抄 4 句、带 14 字以上原文片段的 153 句，是改写；但内容几乎全收（覆盖矩阵要求每个要点有去处），一节里结论、研究细节、参数表、画廊混在一起。用户随后给了三点方向，外加「证据不足的部分自行联网检索」：

1. 外部引用要收齐实物、按合适的方式展示 → 新增 `collect_refs.py`（截首屏，截到验证页改用 og:image，都拿不到只留链接；YouTube 补嵌入字段，视频缺封面用页面封面）；画廊卡片加 `meta`（关键信息）和 `desc`（为什么值得看）；提纲加「外部对象」一块
2. 基于材料重新思考叙事主线，用专业的叙述，冲突裁决、冗余合并、分散融合 → 第 2 步改成「先拆后建」：论点池 → 合并、裁决、融合 → 自己搭叙事主线（一段话讲清推进）；覆盖矩阵换成「论点池的去向」（每条有交代，不等于都进正文）；语气改成专业综述
3. 规范驱动，不给确定性规则 → writing.md 整份重写成「好的样子 + 自查」；删掉「8–12 条」「章标题写判断句」「一章一个问题」「超过三四个单独成章」、骨架里的「必出」；components.md 只说明组件和写法，不规定用法；infographic.md 改成「用户认可过的样子，供参考」

表格（第 4 条）的过程：

1. 调研常规做法（微软、GOV.UK、Zendesk、Elastic 的写作和表格规范），量了测试页 27 张表：492 格里 125 格换行，其中 54 格最后一行只剩 1–3 个字。给了三种写法（只修孤字 / 一格一短语 / 句子移出表格），用户转向版式：内容全部展示，按行列算阈值，放不下再横滑。
2. 第一版算法以「各行一样高」为目标（列宽按内容比例分，在 0.75–1.33 倍内挑行高最一致的分法，估算后用隐藏副本按真实排版复核），会折行的 12 张表行高一致从 61% 升到 82%。用户：有缓解，但不够好看。
3. 调研已有算法：表格自动排版研究（Gange、Marriott、Stuckey 等 2011–2015）的标准目标是「给定宽度，表格总高度最小」；浏览器按最长内容比例分是它的快速近似；LaTeX tabulary、Typst 同属比例分配；AG Grid、Rich 面向数据表；Pretext 可以不读 DOM 算出文字折几行。都没有现成的文章表格组件。
4. 换成「总高度最小」，1440 宽：所有行的行高合计 202 → 182，换行格 74 → 62，孤字格 30 → 1，单格最多 3 行；768 宽孤字格 41 → 4。用户选了这个。放进模板 `components/Table.tsx`，components.md 写明怎么排、写表格时注意什么。

收尾时补的两处：引用浮窗宽度改成按内容收缩（短标题右边不再留一大块空白，最宽 24rem）；全文用词统一后又跑了一遍四个宽度的自检。

### 独立审查（2026-11-11）

只读审查报了 2 个高、9 个中、12 个低优先级的问题，修了的：

| 问题 | 修法 |
|---|---|
| page_check 把手机上藏起来的宽屏版表格报成「挤成一字一行」，组件计数也算了藏起来的那份 | 只查、只数看得见的元素 |
| 加宽到 3 倍还放不下时表格宽度变成 0 | 加宽只到 1.2、1.4 倍，再放不下改排成行块（句子太多，横着读比竖着读累）；全是短列的宽表直接横滑 |
