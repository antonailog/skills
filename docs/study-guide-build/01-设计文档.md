## 1. 收料

### 1.1 场景

- 谁：你，要入门一个新主题，手上有一堆没读过的材料（Deep Research 报告、PDF、网页、播客或视频转写、别人的文档）
- 现在：11-10 到 11-11 手工走过两遍（录屏宣传片入门、AI 设计协作），一整天来回改
- 理想产出：一篇按主线重新编排、补了前置知识、图文并茂的学习文章，符合博客发布规范，你说「发布」就能上线
- 做对了：你读完能说清这个领域的主线、能判断 AI 给的方案对不对；材料里的要点没漏；可核对的事实都有出处；页面过博客的检查

## 2. 设计

### 2.1 要解决的问题

替你把一堆没读过的材料，变成一篇能学会、能直接发到博客的入门文章：读材料、定主线、补前置知识、核对出处、配图排版、发布。

### 2.2 定位与边界

**定位**：给刚入门的你写的学习文章。像一个先替你把材料全读完的懂行同事——把「这个领域到底在讲什么、先学什么、哪里容易错」讲透：先给一页结论和主线，再按做事的顺序一章章展开，缺的前置知识当场补上，最后拿你自己的项目走一遍。

**核心立场**：你还没读过材料，所以你要的不是材料的缩写，而是一条能跟着走的主线。文章按「你学会这件事要经过的顺序」组织，不按材料的顺序；材料之间矛盾、没讲清的，单独放进「还不确定的」。概念、类比、背景可以 AI 自己写；数字、日期、产品功能、谁说了什么，必须有出处才写。

**范围**：一次一个主题，材料几份到十几份都行。也负责这篇文章以后的维护（新材料进来，补进去重新发布）。

| 不处理 | 交给 |
|---|---|
| 还没有材料，要先出调研题目 | research-with-gpt |
| 要 AI 自己调研、出一份帮你做决定的报告 | deep-survey |
| 已经掌握的知识，总结成飞书文档 | 飞书知识总结 SOP |
| 单期播客的复习笔记 | podcast-summary |
| 把学习文章改成公众号这类正式文章 | human-article |
| 一本书或长文转思维导图 | book-to-mindmap |
| 博客首页、文章页、项目页本身的改版 | 直接改博客项目 |

**很像但不该触发**：
1. 「深度调研一下 Remotion 和 Hyperframes 哪个适合我，出份报告」→ deep-survey
2. 「用 deep research 调研个人博客 SEO，给我几个 prompt」→ research-with-gpt
3. 「这期播客我听完了，帮我整理成笔记」→ podcast-summary
4. 「把录屏宣传片那篇改写成公众号文章」→ human-article
5. 「AI 设计这块我已经很熟了，帮我把要点总结成飞书文档」→ 飞书知识总结 SOP

### 2.3 触发与路由

应触发：「那 7 份报告回来了，整理成一篇我能学的文章」「这几个 PDF 和网页我都没看，帮我梳理成入门指南发博客」「按博客知识页的规范做一篇」「录屏那篇又来了两份报告，补进去重新发」

抢活的隔壁：research-with-gpt（收卷）、deep-survey、podcast-summary、book-to-mindmap。research-with-gpt 收卷「问下一步」第 1 项改成交接给本 skill（改前先快照）。

| 信号 | 走哪条线 |
|---|---|
| 给了材料位置 + 要整理成文章 / 指南 / 知识页 / 发博客 | 全流程（新文章） |
| 已有知识页 + 新材料（「补进去」「更新一下」） | 维护：增量补材料 |
| 有材料但只说「帮我看懂」「理一下」，没说要文章 | 先给一页结论 + 主线提纲，问要不要做成文章 |
| research-with-gpt 收卷后、你读报告时说「太长了」 | 一句话问要不要做成学习文章 |
| 明说「保留原文」「原文全文」 | 原文模式：原文全文 + 补图表（AI 设计协作那种） |

### 2.4 输出框架

**文章固定骨架**（顺序不变，模块按触发条件出）

1. 标题 + 导语：这篇给谁、读完能做什么、整理自几份什么材料
2. 一页结论：一分钟看懂 + 一张骨架图
3. 主线各章：按做事顺序，章标题是判断句
4. 检查清单：能照着做的
5. 还不确定的：材料矛盾、没核到原文、领域内有争议的
6. 来源列表：编号对应正文引用

| 模块 | 类型 | 条件 | 对应考点 |
|---|---|---|---|
| 一页结论 + 骨架图 | 必出 | — | 读完一页能说出主线 |
| 主线各章 | 必出 | — | 覆盖矩阵里每份材料的要点都有去处 |
| 检查清单 | 必出 | — | 每条可以照做、可以判断做没做到 |
| 来源列表 + 引用卡片 | 必出 | — | 可核对的事实都挂了出处、链接能打开 |
| 前置知识 | 触发 | 材料默认读者懂、你不懂的概念（按记忆和以往复盘的盲区判断） | 你不用翻别处就能读下去 |
| 示范 | 触发 | 主题能落到你的某个项目上 | 示范用的是你公开过的项目 |
| 还不确定的 | 触发 | 有矛盾或没核到的 | 正文里没有把没核到的写成定论 |

共 7 个模块。展示组件不算模块，按内容触发，清单在 references/components.md：表格卡片、高保真信息图、截图画廊、流程图 / 泳道图、中轴两栏（人和 AI 分工）、提示词块（中英切换）、视频嵌入、动效演示。

### 2.5 执行流程

两次停下来等你：第 2 步之后、第 6 步之后。

| 步 | 做什么 | 输出 | 失败怎么办 |
|---|---|---|---|
| 1 收料 | 扫整个主题文件夹（含根目录，不只看原件目录），每份转成文字，登记来源、类型、篇幅 | 材料表（写进 0-说明.md） | 转不出来的列出来请你换格式；视频没字幕的请你给转写 |
| 2 定主线 | 读完全部材料；写读者任务、主线提纲、覆盖矩阵（每章用到哪几份、哪些要点没去处）、前置知识清单、展示方案（哪里用什么组件）；按提纲写一章样章，用真组件渲染 | 提纲 + 样章截图 → **停，等你** | 材料互相矛盾 → 提纲里标出，进「还不确定的」 |
| 3 补证据 | 找回原链接、核对关键论断；补充知识里可核对的事实查出处 | links/*.json、核对记录 | 搜索额度用光 → 分批；找不到的不写进正文 |
| 4 写全文 | 按提纲铺开；照 references/writing.md 的口径 | guide.md | — |
| 5 配图排版 | 按展示方案落组件；信息图走 codex，截图走 Playwright，流程图走 mermaid，英文 prompt 加中文版 | 页面源文件、图片 | 生图两次不成 → 不放图；截不到 → 只放链接 |
| 6 构建自检 | 构建本地页面，跑检查脚本（360 / 390 / 768 / 1440 宽：报错、坏图、横向溢出、残留说明文字、字号栏宽） | 本地预览 + 截图 → **停，等你** | 检查不过就修，修不了的写明 |
| 7 发布 | 你说「发布」→ 本机发布脚本：先和服务器比对、只传本页目录、上线后核对 | 线上地址 | 没配置发布脚本 → 停在本地预览 |
| 8 维护 | 新材料进来：更新材料表和覆盖矩阵 → 列出要改的章 → 改、重建、你说「发布」再上线 | 更新后的页面 + 0-说明.md 记一笔 | — |

### 2.7 输入输出

**真实的 query 样本**：

1. 「AI 设计那 7 份报告都在 知识/调研/AI设计协作-2026-11-09/2-报告原件/ 了，帮我整理成一篇能学的文章，发到博客知识组」

3. 「这三期播客的转写稿和一份行业报告是讲 AI 陪伴产品的，按我博客知识页的规范做一篇」

**输出**：主题文件夹下的知识网页目录（guide.md、页面源文件、图片、本地预览）+ 0-说明.md 的材料表和版本记录；你说「发布」后是线上地址。

### 2.8 上下文分层

| 层 | 放什么 | 体量 |

| description | 触发场景、同义说法、交接关系 | ~300 字符 |

**红线**（只放收不回来的）：
1. 可核对的事实（数字、日期、功能、原话）没出处不写；图表里的事实逐条对原文
2. 原始材料只读不改
3. 私人信息不上页面（商业打算、合作者、真人照片、账号）
4. 你说「发布」之前不上线；上线只传本页目录
