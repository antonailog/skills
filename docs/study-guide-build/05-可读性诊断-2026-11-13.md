# 可读性诊断：学习指南为什么读着累

来源：「视觉设计入门」指南的五段节选交给两个模型诊断（诊断材料留在作者本机），本文是两份回答的合并，加上我的取舍。用途：改 references/writing.md 的依据。

## 一句话结论

文章用调研报告的写法去写给新手的入门指南：信息一直维持在最高密度，没有主次起伏；顺序按「定义、分类、文献」排，而不是按新手认识问题的顺序排；句子之间、段落之间缺少因果连接，理解的工作留给了读者。单句语法没有问题，累在组织和密度。

## 诊断（两份共识，按影响排序）

| # | 问题 | 原文例子 | 为什么累 |
|---|---|---|---|
| 1 | 核查级细节占了句子主干，主次不分 | 「UEyes 研究用真实眼动仪记录了 62 名参与者看 1,980 张截图……」；USWDS 和 Carbon 的行高参数并列在一句里 | 读者要带走的只是「没有通用的权重公式」，却先要消化一段实验报告，读完反而忘了前面的结论 |
| 2 | 顺序倒置：先定义、分类、学者年份，后讲用途；结论藏在段尾 | 「设计思维」一节先列 1982、1992、d.school、IDEO，最后一句才说它和排版的关系 | 读者在建立「这和我有什么关系」之前，被迫先记分类 |
| 3 | 段内事实硬拼，缺过渡和落点 | 「三处帮助 → 它管不了视觉 → Lucy Kimbell 的提醒」连跳三次；「几条和字号有关的事实」里混进 HTML 标题层级 | 句与句之间没有因果桥，段尾挂着偏离主线的补充，读者自己搭逻辑 |
| 4 | 结论只说一半，不点出对动手的意义 | 「换了字号或字体，每行实际容纳的字数也会变。」就停了 | 读者要自己补「所以换完字体要重查行长」 |
| 5 | 浓缩的抽象词，要在脑子里翻译成画面 | 「收敛合作方标志」「放成一个局部组」「语义就太宽了」「承担一个判断」 | 对新手是隐形门槛，每处都要停下来还原具体动作 |
| 6 | 回指代词和满载长句 | 「设计师先定前一种……让后一种跟着走」；一句塞五个并列名词短语 | 要回头做变量代换；句子长度和结构单一，没有停顿 |
| 7 | 标题只给话题、不给判断 | 「层级与视觉重量」「卡片的小尺寸取舍」 | 1.9 万字的长文扫读靠标题，名词短语像词典索引 |

两份都指出：第八章的海报诊断（按第一轮到第五轮推进）明显好读，因为它有一条读者能跟着走的行动路线，而且用了「它在传达什么？」这样的看稿提问。

## 写作规范要改的地方

| 现行规范 | 问题 | 改成 |
|---|---|---|
| 删一段时问「读者会少知道什么」，答不上来就删 | 只看知识增量：过渡句、场景铺垫、收束句全被当废话删掉；偏题但带新事实的句子反而被留下 | 问「删掉它，读者理解主线或动手时会不会卡住、走神」。帮助理解的过渡和例子要留；偏离当前主线的事实，即使是新的也删或移走 |
| 实验人数、测量数值写进正文，不算啰嗦 | 方法细节和核心原则挤在同一个句子主干里 | 正文主干只放结论和能直接用的数值；样本量、仪器、各机构参数差异放在括号、表格或注释里，不占主句 |
| 语气是专业综述，像调研报告那样中性陈述 | 参照系选错：报告写给同行，入门指南写给新手 | 资深从业者带新人看稿的讲义：平实、克制、有据可查，叙述视角从「文献说了什么」换成「带你看懂问题、做取舍」 |
| 不喊话、不设问 | 封掉了引导读者观察的最好工具 | 仍不喊话；允许用读者真实的困惑或看稿提问引出话题，一处一问，不连用 |
| 章节标题用名词短语 | 目录只给话题、不给主张 | 见下方「待定」 |
| （新增）| | 先描述读者见过的现象，再给术语 |
| （新增）| | 抽象动作词后面紧跟能看见的画面（大小、深浅、远近、删掉什么） |
| （新增）| | 段首说清这段解决什么、和上一段什么关系；段尾落在一个对读者有用的判断上，不挂补充 |
| （新增）| | 列表里的每一项必须是同一个维度；不同维度的事分段讲 |
| （新增）| | 不用「前一种」「后一种」「两者」回指，直接重复名词 |

保留不变：标准说法、不自造词、避免 AI 腔、一段讲清一件事、论断有出处。

## 写作倾向（给新手的领域入门指南）

整体：眼光是专业的，步伐是陪着走的。像一位资深从业者坐在旁边看稿，指出问题在哪、为什么这样改，也坦白说哪里没有标准答案。

1. **一句只推进一步，长短交错**。稍长的句子交代条件和原因，短句给结论。不把两层因果压进一个没有连接词的短句。
   - 前：一个固定宽度的容器，换了字号或字体，每行实际容纳的字数也会变。
   - 后：容器宽度固定，换了字体或字号，每行能放下的字数还是会变。所以换完字体，要重新看一眼每行是不是太长或太挤。
2. **段首给路标，段尾给落点**。第一句让读者知道这段解决什么；最后一句把事实收成一个能用的判断。
   - 前：一张卡片最好只承担一个判断：「这场活动值不值得点开」……内容分成三层……
   - 后：做信息卡片时，最常见的错误是想把所有卖点都放进去。一张卡片最好只帮看的人做完一个判断，比如「这场活动值不值得点开」。围绕这个判断把内容压成三层，卡片才不会挤。
3. **先现象，后术语**。先写读者见过、踩过的情况，再说「这在设计里叫 X」。
   - 前：英文看小写字母主体的高度（x-height）……换了字体、CSS 数字没动，页面像被放大了，原因就在这里。
   - 后：同样设成 16px，换一款字体后整页字像大了一圈。原因是字号只规定外框，字形在框里占多满由字体决定：英文看小写字母主体的高度，业内叫 x-height；中文看方框里笔画有多饱满。
4. **抽象说法后面紧跟画面**。
   - 前：缩小主视觉、收敛合作方标志。
   - 后：把球体缩小，让出焦点；底部六个合作方标志统一成同一高度的浅灰色，排成整齐的一行。
5. **列表只放同一维度的项，多对象多属性才用表格**。
   - 前：「几条和字号有关的事实」里并列视觉大小、字号下限、行长、HTML 标题层级。
   - 后：前三条是调正文时要一起看的视觉参数，保留成列表；HTML 标题层级单独成段，作为实现时的注意点。
6. **证据降一级**。正文主句写规律，研究细节放括号或句子后半。
   - 前：这些因素没有通用的权重系数：UEyes 研究用真实眼动仪记录了 62 名参与者……
   - 后：这五个因素之间没有通用的权重公式，不同载体的看图习惯差别很大（一项眼动研究记录了 62 人看 1,980 张网页、软件、手机界面和海报截图，四类画面的注视规律各不相同）。

## 两份回答里不采用的部分

- **改写中的口语和行话**：「留给细节控」「拉齐对话框架」「偷懒用同一张主图」「抓眼球」「塞下的字数」。这些和已定的「不用口语压缩、不自造词」冲突；新写法要的是平实，不是口语化。
- **渲染式叙事**：「这股冲动很容易就在找路的过程中断掉了」。场景描写一两句就够，不写成故事。
- **把方法细节放进悬停卡片**：页面的引用卡片只显示来源名、网站和日期，放不了样本量；细节改放括号或表格。
- **用问句当标题**（「它能代替视觉基本功吗？」）：标题仍用陈述，问句只在正文里用。
- 其中一份改写有错字：「学会这套流程并等于掌握」少了「不」。
